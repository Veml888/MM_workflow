- [ ] `docs/02` 每问复杂度适配审计表存在，说明题目困难、模型结构与必要复杂度的对应关系

- [ ] 全文至少一问清楚体现与题目核心困难匹配的建模深度；不要求高复杂度量级
- [ ] 论文正文对模型规模与算法复杂度有交代（状态空间、$O(\cdot)$、结构图/机理图）
- [ ] 题面含动态/随机/博弈/网络结构时，模型显式建模了这些结构（未退化成静态单方程）

## 6. 论文格式（评委偏好 + 获奖惯例）

- [ ] 摘要审计脚本 PASS：默认主标题与摘要标题均为三号；官方模板/用户覆盖已书面登记
- [ ] **摘要写满一整页且未超过一页**：关键词行位于可打印版心纵向 78%--90%，不得只凭“单页”判断；关键方法/结论**加粗**
- [ ] 摘要汉字数 550–1100（优先 750–950）；逐问分块；每问至少 1 个带单位、2–3 位小数的数字
- [ ] 摘要未使用 `\vfill`、弹性空白、`\enlargethispage`、缩小页边距、异常放大标题或空泛句子填页
- [ ] **无目录**
- [ ] 表示顺序的一级标题使用中文数字加顿号（如“一、问题重述”）；参考文献、附录和 AI 工具使用声明等非顺序标题无编号；无自动阿拉伯章节号或混用
- [ ] 正文范围为摘要之后至附录之前，包含参考文献与必设的 AI 工具使用声明，不含摘要和附录；默认 27~30 页并以当届官方规定为准；内容充实、无注水
- [ ] 附录前字号统一：一级标题小三号居中、二级标题四号、三级标题与正文小四号、图题表题小四号、表内文字五号；正文单倍行距，段落额外间隔约四分之一行
- [ ] 所有表格表头、文字和数字水平居中，长文本居中换行，无因五号表格文字造成的溢出
- [ ] 论文结构完整（八段式：重述/**问题分析**/假设/符号/模型与求解/检验/评价/参考文献/附录）
- [ ] 每个子问题解答过程详细（分析→建模→求解→结果表→结果分析流水线）
- [ ] 求解表达可使用连续段落或普通编号，不固定编号形式；只有复杂自研算法才允许流程图；每问有结果表与分析
- [ ] 模型对比、检验、灵敏度和鲁棒性按题目需要出现；凡声称更优、可靠或稳定，均有对应证据
- [ ] 模型评价含"优点 + 缺点（示弱）+ 推广"
- [ ] **图 ≥ 8、表 ≥ 5，每问至少 1 个有信息量的图和 1 个有信息量的表**；图表类型按题目证据选择，不强制每问都制作数据图；图表全文连续编号、无重号跳号；三线表
- [ ] 图文件名与图题（`\caption`）不带"问题X/QN/qN"编号字样；数据图标签与图形元素无重合
- [ ] **摘要/表内/正文数字三处一致**；精度统一（2–3 位小数）
- [ ] **附录紧凑排版**（追求 3~4 页目标）：附录起始处有独立可见、居中的一级标题“附录”，随后含全部完整可运行源码
- [ ] 语言无明显 AI 腔：每段有数字/公式/字段关系/失败结果/选择理由；无路标词与空泛评价；图题表题不写备注
- [ ] 求解步骤编号形式与全文排版协调；不机械强制或禁止圈号数字
- [ ] 故事线：问题→障碍→选择→证据→转折→决策→边界；每节承接上节问题、落下可复算结论；结论最后一句只写应用条件
