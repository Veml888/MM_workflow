# 数学建模：交付验收

本 skill 是数模流程第 7 阶段（最后）。目标：对照清单审计全部产物，找出缺漏与矛盾，输出验收报告。**任何未通过项都应回写对应阶段修正**，而不是在验收阶段自行补写。

## 输入与产出

- 输入：`plan.md`、`project-manifest.json`、`docs/01~05`（含 `docs/05-diagrams-report.md` 与 `docs/05-visual-report.md`）、`code/`、`results/`、`figures/`、`paper/论文.tex`、`paper/论文.pdf`（仅检查本次计划内、非 `n_a` 阶段）。
- 产出：`docs/06-verification-report.md`（必须）、支撑材料 ZIP（按需，见 Step 9）。

验收的核心不是确认“章节和方法都存在”，而是确认阅卷人能否对每个题面要求直接判分。必须逐条审计评分点的最终答案覆盖；缺少可直接判分的答案即使模型、代码和章节齐全，也不得通过。

审计清单见 `references/checklist.md`，先读它再逐项核验。

跨阶段通用规则以 `../mm-orchestrator/references/cumcm-2026-shared-policy.md` 为唯一权威来源；交接字段遵循 `../mm-orchestrator/references/project-manifest-contract.md`。

## 工作流

### Step 1：完整性审计

- 对照 `plan.md` 的阶段清单，逐阶段检查应有产物是否齐全（报告、代码、结果、图表、论文）。
- 检查 `paper/writing-gates.md` 是否存在、G-1~G-5 是否全部 PASS 且证据可查；数字、编译和格式属于终稿验收项，不计入写作前 GATE。若论文阶段为 `n_a`，不要求该文件。
- 检查 `project-manifest.json` 的阶段状态、稳定 ID、文件哈希、版本和回写记录是否完整。
- 运行 `mm-orchestrator/scripts/validate_manifest.py`；Schema 校验失败时验收不得通过。
- 缺失项记录"缺失"，不现场补造。

### Step 1.5：评分点与最终答案覆盖审计（高优先级）

- 从 `docs/00-problem-interpretation.md`、`docs/01-analysis-report.md` 和题面原文提取每个显式任务与可识别评分点，建立稳定的 `SCORE-###`；若使用评委评分细则或用户提供的评分点，记录来源；没有正式评分细则时不得臆造分值，但仍须覆盖题面要求。
- 对每个 `SCORE-###` 建立矩阵，至少包含：评分点/题面位置、所属 `P-##` 或 `REQ-###`、预期答案类型（数值/方案/排序/判定/预测/解释/建议等）、论文最终位置、可直接判分的答案原文或数值、支撑证据位置、复现来源、PASS/FAIL。
- “模型已建立”“算法已运行”“指标已报告”“结果见表”均不是最终答案。必须能从正文或结论中直接读出题目要求的结果，并能判断对象、单位、范围、排序、方案或适用条件；答案分散在多处时，论文应有明确汇总句或汇总表。
- 每个 `P-##` 至少有一个明确的最终回答；每个 `REQ-###` 和 `SCORE-###` 必须映射到最终答案及证据。缺少答案、答案类型不匹配、只有过程没有结论、只有结论没有证据、数字/单位/对象不完整，均判 FAIL 并回写 `mm-paper-writing`；若缺模型或结果则同时回写对应阶段。
- 验收报告必须附完整矩阵，不得只写“各问已回答”或只列章节标题。矩阵中的论文位置应能由阅卷人直接打开定位，答案应尽量引用原文短句、表格行或明确数值，而不是验收者自己的概括。

### Step 2：一致性审计

- 论文中的数值、公式、图表编号是否与 `docs/02`、`docs/03`、`docs/04`、`docs/05-diagrams-report.md`、`docs/05-visual-report.md` 一致。
- 符号表是否与建模报告一致；图/表是否都在正文被引用；求解步骤符号是否与正文一致。
- 核对多等式公式排版：同一个公式表达中用逗号、分号等并列的多个等式，应以左花括号逐行呈现并共享一个式号，不以横向逗号串联；若某行需单独引用或分别推导，才要求拆分。公式组每一行仍能追溯来源、含义和推导链。
- 摘要、正文、结论、CSV 与图表中的关键数字一致（老师验收项 8）。

### Step 3：可复现性审计

- 检查 `results/复现清单.json` 是否存在、字段是否完整。
- 抽查：按 `code-spec` 是否固定了随机种子、输入哈希是否记录。
- 默认从原始数据完整重新运行主程序，退出码必须为 0，关键结果在记录的数值容差内一致。
- 若完整重跑成本过高，记录预计成本、无法完整重跑的原因与抽样方案，改为运行核心程序、独立复核程序并复核关键结果；不得静默跳过。
- 预测、分类、风险排序或审核决策题另运行专项独立复核；其他题型标记 N/A。

### Step 4：数据真实性审计

- 核对论文与结果中的参数能否追溯到题面/附件或建模报告的"待确认项"。
- 排查有无凭空编造数据、为结果好看而改参数的迹象。
- 预测/分类题核对训练/测试隔离：字段选择、标准化、超参、阈值是否只在训练折内完成；身份编码是否进入特征。

### Step 5：图表与图种丰富度审计

- 核对选图是否贴合数据与论证；3D 图仅当数据适合时采用；核对技术路线、框架、机理与适用的复杂自研算法流程图。
- 核对所有图（含流程图/原理图/纯视觉示意图）字体是否可读。
- 核对数据图：PDF+SVG+PNG 三格式，PNG ≥300 DPI（多面板按图表规范）；重要类别不得只靠颜色区分。
- 核对流程/框架图：TikZ `.tex`、矢量 PDF 与 600 DPI PNG 成套存在；重新编译 `.tex`，并检查 PDF 自然尺寸、PNG 物理元数据、文字边界、节点重叠、箭头方向、穿框和无语义线条。仅当 manifest 声明 SVG 分支时检查 SVG 语义结构。
- 核对纯视觉示意图：必须有高分辨率 PNG；矢量或混合路线另有 SVG。色彩与视觉风格不受流程图黑白灰规则限制，但必须事实准确且与论文协调。
- 若本次计划包含完整论文，核对至少一张纯视觉示意图（题目理解或算法理解）为纯视觉模式：画布文字不是主体，只保留去掉后会产生歧义的必要短标签、变量或方向说明，并登记于 `docs/05-visual-report.md`；视觉阶段为 `n_a` 的部分任务不要求该产物。
- 对时间演化、空间演化或迭代子问题，核对是否展示初始、关键中间和终止状态；不要求至少两个子问题。

### Step 6：论文格式审计

- 复跑 `mm-paper-writing/scripts/audit_abstract_page.py`，核对主标题与摘要标题均为三号、汉字数 550--1100、关键词行版心占用率 0.78--0.90，且摘要不过页。官方模板或用户覆盖必须有书面记录；禁止仅凭单页或字数判定“写满”。
- 核对结构完整、结果分析充分、附录源码完整。模型对比、灵敏度、鲁棒性与检验只在适用或支撑论文主张时检查；不设最低数量。
- 求解表达可用连续段落或普通编号，不固定编号形式；只有复杂自研算法才允许流程图。
- 核对故事线：问题→障碍→选择→证据→转折→决策→边界；每节承接上节问题、落下可复算结论；摘要为全文故事缩写；结论最后一句只写应用条件。
- 逐表核对首次正文引用页、表题页和下一小节标题页。数据审计表、符号表和核心结果汇总表必须紧跟首次引出，且不得被同节大型图片挤到下一页或孤立浮动页；异常回写 `mm-paper-writing` 调整锚点或对单张关键表锁位。
- 逐图核对首次正文引用页、图题页和下一小节标题页，确认“文字引出 → 图片 → 实质解读”、问题/小节归属、关键图邻近性和无孤立图页；异常回写 `mm-paper-writing` 调整叙事顺序、锚点或浮动参数。
- 对连续的表—图证据组逐页核查局部版面：表后至图前不得出现由浮动队列或图件画布留白造成的明显无效空白；当前页可容纳时应保持紧凑相邻，必要时回写 `mm-paper-writing` 对该组局部使用 `[H]` 或合并排版。仅“同页/同小节”不视为通过。
- 对每张跨页长表逐页检查：首页表题正常；续页标“续表 N　原表题”并重复完整表头与单位；非末页标“续下页”；仅末页有最终底线；表号、标签和表目录不重复，数据行连续且整张表未跨入下一小节。
- 核对语言是否有明显 AI 腔（参考 `mm-paper-writing` 的去 AI 味规范与 `teacher-storyline-2026.md`）。
- **评卷内容审计**：逐问抽查“题面要求 → 针对性模型或改造 → 可复现结果 → 明确回答”的完整链条。标记并回写：与题目无关的方法罗列、通用算法简单拷贝却未说明本题处理、只报性能而未回答题面、为凑篇幅的重复/空泛段落、无信息图表、无证据的创新或优越性主张，以及任何无法追溯到代码、数据或记录的结果。不得因结构齐全、页数达标或语言流畅而掩盖此类缺陷。
- **最终答案可判分审计**：复核 Step 1.5 矩阵中的每一项，打开论文对应位置，确认答案对题面动词（如预测、优化、比较、安排、解释、判定、提出建议）作出了完整回应。若读者还需自行从多张表、公式或代码推导答案，视为未直接回答；要求回写论文增加简洁的答案汇总句/表，并保留证据引用。此项是高严重度，不得用“章节完整”降级。
- **标题编号审计**：逐页核对可见一级标题。表示正文顺序的标题必须显示中文数字加顿号（如“一、问题重述”）；“参考文献”“附录”“AI 工具使用声明”等非顺序标题不得显示数字。出现自动阿拉伯章节号、把参考文献编号为“九、”或其他混用时，回写 `mm-paper-writing` 修正 LaTeX 标题命令/计数器后重编译。
- **复杂算法深度审计**：若题目或模型使用非平凡算法，核对建模报告、代码、结果报告和论文是否共同说明状态/决策规模、关键更新、终止/收敛、复杂度、参数影响、失败/退化情形和验证证据；缺任一关键环节则回写对应阶段。若题目不需要复杂算法，核对是否有充分理由采用简单方法，防止为复杂而复杂。
- **目标函数合理性审计**：逐个优化/决策子问题核对“题面真实目标 → 决策变量 → 目标函数各项 → 硬约束/软惩罚 → 最终答案”的链条。检查方向、单位/归一化、权重和惩罚来源、代理指标合理性、多目标敏感性、约束可行性及代码实现一致性；发现虚构权重、量纲混用、目标与题面不一致、目标函数遗漏关键代价或把约束错误当目标，判 FAIL 并回写分析/建模/编程阶段。

### Step 7：官方格式规范审计

- 以 `mm-paper-writing/references/official-cumcm-format-2026.md` 为准，核对：页边距 ≥2.5cm、摘要页页码从 1 起（页脚中部）、正文无目录且为 27--30 页（当届官方另有规定时按其执行）、正文范围为摘要之后至附录之前并包含参考文献及必设的 AI 工具使用声明、附录页必须有独立可见的一级标题“附录”并含全部完整可运行源码、全文匿名、参考文献规范、电子版第一页为摘要页且 ≤20MB、AI 使用说明。
- 若机器可用，直接编译核对：`xelatex -interaction=nonstopmode -halt-on-error paper/论文.tex`；再用只读方式检查 PDF 页数、摘要页码与页边距（如 pdfinfo/pypdf，或核对 `.tex` 源码中的 geometry 与分页命令）。
- **老师验收项 3~7**：LaTeX 至少编译两遍且引用稳定；日志无 LaTeX Error、undefined references；Overfull 与严重 Underfull 逐条记录并回写修正（不能直接忽略）；PDF 为 A4、摘要单页；正文范围为摘要之后至附录之前，包含参考文献与必设的 AI 工具使用声明；字体真实嵌入、无缺字方框与替换字符；逐页渲染检查图表大小、标签遮挡、孤行、留白和附录。
- 摘要审计脚本返回非零、版心占用率越界、标题字号不符或发现排版注水宏时，按高严重度 FAIL 回写 `mm-paper-writing`；修复后重新编译、重新测量并更新 manifest 哈希。

- 正文页数按摘要之后至附录之前计算，包含参考文献与必设的 AI 工具使用声明，不含摘要和附录；默认须为 27--30 页，并以当届官方规定为准。为补足必要篇幅，可检查是否缺少服务题目论点的推导、求解细节、验证证据、结果解释或适用图表；适用图表可包括数据图、结构/机制图、复杂算法流程图和题目场景示意图，但必须有正文引出和实质解读。不得以重复文字、无信息图表或排版注水凑页。
- 任何一项 FAIL 都标记为高严重度（可能影响评奖资格）。非关键格式或说明缺陷可标记 `conditional` 并创建返工项；数据真实性、核心结果不可复现、关键数字不一致、编译失败和硬性格式违规不得降级。

### Step 8：写验收报告

逐项记录 PASS / FAIL / 缺失，FAIL 项写清"应回写到哪个阶段、具体问题"。结论分为：通过 / 有条件通过（列明待修正项）/ 不通过。

### Step 9：整理支撑材料

按需生成支撑材料 ZIP，只包含：全部可运行源码、必要中间结果、较大篇幅图表、依赖与中文运行说明、一键运行入口、文件 SHA256 清单和《AI 工具使用详情.pdf》。不得包含论文 PDF/TeX、`docs/` 阶段报告、赛题原始附件、`writing-gates.md`、旧版图、预览图、缓存、个人信息或临时备份文件。

## 边界

- 只审计、不补写；发现的问题回写对应阶段。
- 可按 Step 3 完整重跑或抽查模型，但运行输出必须写入临时目录，不覆盖既有结果。
- 本 skill 只审计、定位并指定回写阶段，不直接修改论文、代码、图表或上游报告；由 `mm-orchestrator` 调用对应 skill 修复后再次验收。
