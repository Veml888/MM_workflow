# 数模论文自然化与技术保真规范

本规范用于 CUMCM 论文的语言层和最终自然化审校。它不替代题目分析、建模、编码、实验、图件或技术验收，也不承诺通过任何所谓 AI 检测器。目标是让论文具有学生团队基于真实工作写成的具体、克制和连贯表达，同时如实保留 AI 使用说明。

## 1. 优先级与执行顺序

发生冲突时依次服从：用户当前明确要求；官方赛题、真实数据和共享规则；已验证的上游报告与结果；本规范。

按以下顺序执行，不得先改文风再补技术内容：

1. 依据题面、模型、代码、结果和图表完成技术上成立的初稿。
2. 逐段检查材料、证据和推导是否足以支撑结论。
3. 结合上下文自然化措辞，合并重复内容并修复断裂段落。
4. 清除正文、图表和附录中的生成过程残留。
5. 重新核对技术事实、结论强度和完整论证链。

## 2. 技术保真硬门槛

自然化不得新增、删除或改变以下内容：

- 题面条件、样本范围、数据字段和数据口径；
- 数字、单位、精度、参数、公式、约束和变量定义；
- 模型选择理由、算法步骤、实验设置与评价标准；
- 相关、因果、显著性、最优性、稳定性和泛化性的结论强度；
- 失败结果、不确定性、适用范围和限制条件；
- 图表含义、文献来源和正文交叉引用。

每个关键结论必须能够沿“结论 → 结果 → 模型 → 数据或题面”反向追溯。无法追溯的结论不得靠润色保留；回到对应上游阶段核实。

不得为了写得更顺而编造案例、机制、实验、参数、文献、人物判断或精确细节。信息不足时写清可观测量、必要假设、待估参数和适用边界，不用语言掩盖真实缺口。

## 3. 以材料推动段落

每段只承担一个主要功能，但不机械限定句数。新段落必须增加至少一种实质内容：事实、定义、公式、推导、数字、比较、选择理由、失败结果、限制或对下一步的作用。同一观点换词重复不算推进。

使用信息增量判据检查铺垫、过渡和收尾：删除某句后，事实、逻辑关系、条件边界和结论均未减少，则该句通常只是表演条理、深刻或文采，应删除。不得用这一判据删去承载因果、转折、定义、范围或推导作用的句子。

复杂分析段检查“论点—依据—推导—结论”是否齐全：

- 当前段要说明什么；
- 依据来自题面、公式、结果还是图表；
- 如何从依据得到判断；
- 该判断为何引出下一步。

避免只有观点没有依据、只有数据没有解释、只有公式没有用途、先给强结论再用模糊语言补理由，以及用“显然”“容易看出”跳过关键推导。

## 3.1 面向人的论证逻辑

论文不是阶段报告的拼接，也不是模型名称和结果数字的清单。读者应能在不查看内部文件的情况下理解每个判断为何出现。正文按以下关系推进：

`题目要求 → 现实障碍 → 数据与假设 → 选择理由 → 模型与求解 → 结果证据 → 决策含义 → 适用边界`

写作时遵守：

- 先说明要解决的具体困难，再引入变量、公式或算法；
- 先解释选择依据，再报告模型结果；
- 结果段同时回答“数值是多少”“说明了什么”“对题目哪一问有用”；
- 小节之间用前一节的结论承接下一节，不用“进入下一阶段”“根据流程安排”等内部流程语言；
- 允许不同问题使用不同的叙事结构，不强行复制同一组小标题、句式和段落长度；
- 删除只负责宣布“本文完成了什么”而没有增加事实、依据或边界的句子。

模型复杂或推导较长时，可以保留必要的定义、过渡和解释；“简洁”不等于省略读者理解所需的因果连接。技术准确性、证据完整性和人的可读性冲突时，保留技术内容并重写连接方式。

## 3.2 题目要求约束

论文只能写题目需要回答的内容。动笔前把题面拆成可核对的子问题和硬性输出，建立内部追踪表：

`题面要求/子问题 → 正文位置 → 模型或计算 → 图表/数值证据 → 结论`

正文不展示这张内部表，也不把 `P-##`、`REQ-###` 等编号写给读者；编号只用于写作和验收追踪。每个核心段落、公式、图表和结论都应能在表中找到服务对象。以下内容不得因为“常见”“有价值”或“能增加篇幅”而加入：

- 题目没有要求、且不会改变任何子问题判断的背景扩展；
- 与当前数据和约束无关的模型介绍、算法比较或理论综述；
- 没有对应题面决策的灵敏度、鲁棒性、推广和评价；
- 不能直接支持结论的装饰性图表和重复解释。

若某项分析对题目不适用，应在内部记录不适用原因，并在正文保持克制；不能为了填充固定模板而强行加入。写完每个问题后，必须用明确结论回答题面动词，例如“预测什么、优化什么、比较什么、安排什么、解释什么或给出什么建议”，不能只报告模型性能。

## 3.3 模型评价与推广的篇幅边界

“模型评价与推广”是收束段，不是第二个结果章。通常写半页至一页，原则上不超过正文的 3%--5%。只回答三件事：哪些优点已经被结果支持，哪一个局限会影响解释或外推，以及在什么数据、假设或资源条件下可以改进或推广。

不得在这一节重复模型公式、完整算法、结果表、灵敏度曲线、鲁棒性过程或逐问结论；这些内容放在对应问题的模型与结果部分。不得使用“模型具有较强适用性”“可广泛推广”等无条件判断，推广必须写清对象、前提和边界。若某项评价没有对应证据，删去或改写为待验证的限制，不得用乐观措辞补足篇幅。

## 4. 结合上下文改写

不得把句子脱离相邻段落孤立改写。修改前至少检查上一段结论、当前句功能、当前段新增信息和下一段进入理由。必要时合并、拆分、前移、后移或删除句子，而不是只换同义词。

改写后重新阅读当前段及相邻段，确认：

- 主语、指代、术语和符号仍然明确一致；
- 因果、条件、转折和递进关系没有丢失；
- 结论没有被无意强化或弱化；
- 没有制造新的重复或逻辑跳跃；
- 图、表、公式仍在正确位置被引出和解释。

局部表达更漂亮却破坏整体论证时，撤销局部改法，从段落功能重新处理。

## 5. 高频模板痕迹与处理

以下项目是风险信号，不是机械禁词。只有在空转、堆叠或重复时才删除或改写：

| 模式 | 问题 | 处理 |
|---|---|---|
| 连续使用“首先、其次、最后” | 提纲替代论证 | 保留真实步骤；其余用材料和因果自然推进 |
| “值得注意的是、综上所述、总而言之” | 常作无信息路标 | 直接写具体发现或删除空句 |
| 每段以“本文/我们”开头 | 主语与节奏单一 | 改用模型、数据、表图或研究对象作主语 |
| “精准、高效、深入、显著提升” | 评价无证据 | 换成误差、耗时、指标、区间或对比结果 |
| “进行建模、开展分析、实现优化” | 动词空泛 | 直接写建立、拟合、求解、检验或最小化什么 |
| 同义词轮换术语 | 看似丰富但定义漂移 | 模型名、变量、类别和指标全文使用唯一名称 |
| “不是 X，而是 Y”式虚假对立 | 先虚构无人主张的 X 再否定 | 若删除 X 后信息不减，直接陈述 Y；真实方案对比可保留 |
| 整齐等长句和排比段 | 节奏机械 | 按信息密度自然调整句长和段长 |
| 人为金句、宏大意义或乐观收尾 | 超出证据 | 以最后一个具体结论或适用条件结束 |
| 多重保留词叠加 | 判断含混 | 保留与不确定性相匹配的一层限定 |
| 无来源的权威表述 | 无法核验 | 给出真实来源，或删除该主张 |
| 熟悉名词反复加引号或重复括注 | 造成不必要强调 | 引号仅用于首次定义、自造概念、引用或特殊语义；数字、单位、缩写、文献和必要术语括注保留 |

冒号、破折号、“不是……而是……”以及“因此、此外、然而”等连接方式不设绝对禁令。它们承担定义、对比、因果或转折功能时可以使用；避免高频重复和装饰性使用。数学箭头保留标准含义，正文叙述中的装饰性箭头改为正常文字。编号按内容选择并保持全文协调，不机械堆叠圈号。

## 6. 数模论文的自然表达

- 量化优先：能用真实数字、区间和效应量说明时，不用空泛形容词。
- 动词具体：说明谁对什么执行了何种计算，得到什么结果。
- 减少空壳名词化：将“进行分析、开展检验、实现求解、产生影响”等优先改为“分析、检验、求解、影响”。专业名词、公式定义，以及用于承接上句的“该估计、这一约束”等名词化结构不得机械拆除。
- 语气克制：区分实测、模型估计、统计关联和机制解释，不写“完美解决”“完全正确”。
- 长短句配合：公式推导和关键判断可用短句，条件较多时允许中长句；不为制造“人味”故意写错、口语化或加入网络梗。
- 术语稳定：首次给出中文全称与缩写，后文统一；符号、单位和小数精度保持一致。
- 自评绑定证据：“精度较高”“模型稳定”“优于基线”等表述必须紧邻相应指标、误差或对照结果。
- 限制写成边界：使用“在当前样本范围内”“在上述假设下”等准确限定，不把局部结果写成普遍规律。

问题重述用自己的话忠实转述任务，不提前写模型和结果。问题分析说明真正障碍、选择理由和各问依赖，不预告章节目录。模型建立交代公式为何出现、变量从哪里来及其服务的子问题。结果分析解释关键差异和决策后果，不逐格朗读表格。结论只回收正文已经验证的发现，最后落在适用条件，不新增论点。

## 7. 保持完整学术叙事

全文应形成连续链条：

题目要求 → 数据与约束 → 必要假设 → 模型选择 → 变量、目标与约束 → 求解 → 结果 → 验证 → 适用边界 → 对题目的回答。

逐章排查以下断裂：问题分析提出的因素后文未使用；变量或公式突然出现；模型与结果使用不同口径；结果只报数字却不回应题目；验证与前文模型无对应；评价与真实实验脱节；结论新增正文没有论证的观点；各小问像独立文本拼接。

公式出现前说明动机、服务对象和变量来源，出现后说明如何进入计算或推断。图表出现前说明查看目的，出现后解释最重要的现象、比较和后果。不得为迁就文风修改真实图表数据或公式。

## 8. 成稿禁用表达与唯一例外

本节是竞赛成稿的硬性语言门禁，适用于作者撰写的标题、摘要、关键词、正文、图题、表题、图表可见文字、附录说明、页眉和页脚。它不适用于完整源代码、程序输出、公式变量名、文献题名或逐字引文；这些内容不得为规避检查而失真，但应避免无关的过程性表述。

以下词语或表达在上述范围内不得出现：

- 生成过程与工具身份：`AI`、人工智能、大语言模型、ChatGPT、Codex、Agent、智能体、提示词、Prompt、skill、工作流、阶段、上游、下游、GATE、manifest、artifact、调用、生成、自动生成、用户、本助手；
- 对话与执行口吻：根据你的要求、下面给出、如果需要可以、接下来、下面由、已完成此阶段、我/我们为你；
- 空泛模板与无证据自评：本文将、值得注意的是、需要指出的是、综上所述、总而言之、形成闭环、完整回答、显著提升、有效赋能、可解释性强、具有重要意义。

这些禁用项不能靠同义替换保留原有空话。应删除无信息句，或改为可核验的题面条件、模型定义、数字、比较结果、推导理由和适用边界。技术上必须使用“生成”等字样时，应以精确的学科术语重述；若无法重述，须在写作前向用户说明冲突。

唯一例外是每篇论文必设且置于参考文献之前的“AI 工具使用声明”。该声明必须如实、简短、使用不编号小节；其前后可用源码注释 `% language-audit: allow-start` 和 `% language-audit: allow-end` 标记，以供审校脚本跳过。豁免标记不得包围其他正文、图表文字或附录说明。

终稿前运行 `python scripts/audit_submission_language.py paper`。命中项必须逐处人工判断：作者撰写文字一律改写；公式、代码、引文或文献元数据保留时，在审校记录中说明原因。脚本通过不替代逐页目检。

## 9. 清除生成过程残留

交付前检查摘要、标题、正文、图题表题、表内文字、图内可见文字、公式说明、页眉页脚、参考文献和附录，清除只服务生成过程的内容，包括：

- “根据你的要求”“下面给出”“如果需要可以”等对话式提示；
- Prompt、TODO、placeholder、待补充、待验证、此处放图和内部备注；
- “由 AI/ChatGPT 生成”、模型建议、审稿备注和工作流说明；
- LaTeX 注释误渲染出的内部信息。

残留若已嵌入图件，回写相应画图阶段重新导出，不直接修改图中真实数据、曲线或技术结论。AI 工具使用情况应在官方要求的位置如实披露，不以删除痕迹代替披露。

## 10. 改写后技术复核

每次大段自然化后，重新检查“题目 → 假设 → 模型 → 推导 → 算法 → 结果 → 验证 → 结论”：

- 没有删除逻辑节点、关键条件、失败结果或限制；
- 没有改变公式解释、变量定义、单位和评价口径；
- 没有把相关写成因果、数值最优写成理论最优、单次稳定写成鲁棒；
- 没有用局部实验支持无边界的普遍结论；
- 摘要、正文、表格、图和结论中的关键数字一致；
- 每个子问题都能从题目要求追踪到模型、结果和最终回答。

自然度与技术严谨发生冲突时，保留技术严谨性并重新寻找更朴素的表达。

## 11. 最终自检

- [ ] 每段都增加了实质信息，没有同义改写灌水。
- [ ] 删除铺垫或收尾句后若信息不减，已删去该表演性句子。
- [ ] 套话和模板句已按语境处理，没有执行机械禁词替换。
- [ ] 没有虚构对立面，弱动词名词化、重复引号和装饰性括注已按语境处理。
- [ ] 结论均有数字、公式、图表或来源支撑。
- [ ] 术语、符号、单位、精度和结论强度前后一致。
- [ ] 生硬句已结合前后文修复，段落之间逻辑连续。
- [ ] 公式、图和表均被正确引出并得到实质解释。
- [ ] 没有新增事实、实验、机制、结果或文献。
- [ ] 没有 Prompt、占位符、内部备注和生成过程提示。
- [ ] AI 使用说明真实、完整，并符合当届要求。
- [ ] 成稿禁用表达已通过脚本和人工复核；唯一豁免仅为 AI 工具使用声明。
- [ ] 每节都能独立回答“解决什么问题、依据是什么、为什么这样判断、如何回应题目”，且不依赖内部报告或工作流语境。
- [ ] 题面每项要求都有模型、证据和结论落点；正文没有与任何子问题无关的扩写、图表或评价。
