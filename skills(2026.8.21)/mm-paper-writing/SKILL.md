# 数学建模：竞赛论文撰写

本 skill 分两遍工作：先根据 `docs/01~03` 形成论文结构草稿与插图需求清单；图件完成后，再把全部报告、图表和结果整合成符合 CUMCM 2026 规范的 LaTeX 论文。

## 输入与产出

- 第一遍输入：`docs/01~03`、`results/`、`plan.md`；产出 `paper/structure-draft.md` 与 `paper/figure-requirements.md`。
- 第二遍输入：结构草稿、全部 `docs/01~05`、`figures/`、`results/`、`project-manifest.json`；产出 `paper/论文.tex` 与 `paper/论文.pdf`（xelatex 编译）。唯一终稿格式为 LaTeX。
- **图片来源（硬性）**：论文插图必须来自 `figures/`，由画图专用 skill 产出——数据图来自 `mm-figures`，流程/架构/机理图来自 `mm-diagrams`，纯视觉示意图（题目理解/算法理解）来自 `mm-visual-concept`。本 skill 不直接画图、不生成图片文件。

跨阶段通用规则以 `../mm-orchestrator/references/cumcm-2026-shared-policy.md` 为唯一权威来源；交接字段遵循 `../mm-orchestrator/references/project-manifest-contract.md`。

写正文前先读规范（必读）：`references/official-cumcm-format-2026.md`（官方硬性要求，优先）、`references/cumcm-paper-structure.md`、`references/abstract-writing.md`、`references/de-ai-writing.md`、`references/teacher-storyline-2026.md`、`references/problem-restatement-writing.md`、`references/problem-analysis-writing.md`；另有 `references/modeling-and-solving-writing.md` 与 `corpus/图表规范-playbook.md` 为 G-1 门禁必读。正文或附录出现跨页长表时，另须完整读取 `references/multipage-table-writing.md`。

**写作惯例语料（按需加载，仅限语料证据）**：`references/corpus/` 下 6 个 playbook 提炼自 28 篇获奖论文，写具体章节时按需加载对应 playbook（不要一次全读）；操作规范已在"写正文前先读规范"与 G-1 中列出，不重复维护于本表：

| 写哪部分 | 加载 playbook |
|---|---|
| 摘要 | `corpus/摘要写作-playbook.md` |
| 章节骨架/假设/符号 | `corpus/章节组织-playbook.md` |
| 模型检验/灵敏度/评价 | `corpus/模型检验与评价-playbook.md` |
| 插图/表、标题、图表数量 | `corpus/图表规范-playbook.md`（语料证据；写结果与插图前必读要求见 G-1） |
| 措辞/过渡词/自评 | `corpus/语言与措辞-playbook.md` |
| 赛前检查易错点 | `corpus/易错点与反模式-playbook.md` |

加载原则：主 playbook 5–15 KB，可整读；`corpus/README.md` 说明语料来源与偏差。

## 硬性要求（官方优先，其次评委偏好）

1. **官方规范优先**：凡与官方《论文格式规范》冲突的偏好，一律以官方为准（页边距 ≥2.5cm、正文 ≤30 页、附录含全部完整源码、摘要不超过一页等），见 `references/official-cumcm-format-2026.md`。**LaTeX 输出必须遵守官方硬性要求，不得放宽。**
2. **摘要**：写满摘要专用页但**严格不超过一页**，关键方法/结论/数值**加粗**；主标题、摘要标题、汉字数和版心占用率按共享 policy 与 `references/abstract-writing.md` 固定执行。编译后必须运行 `scripts/audit_abstract_page.py`，不得用“单页 + 字数合规”替代占用率检查。
3. **不要目录**：论文不设目录，摘要后直接进入正文。
4. **每个问题详细解答**：按"承接分析（1~3 句）→ 模型建立 → 求解步骤（行文编号简要说明）→ 结果表 → 结果分析"的论证链展开，步骤完整（获奖论文惯例，见 `references/modeling-and-solving-writing.md`）。**注意**：这是内容论证链，不是小节标题模板——四问不得共用同一套小节标题；承接分析不设"建模思路"小节（问题分析章已论证时直接承接或省略）；小节标题按题型现场拟定、学术化（如"收率优化模型与代理修正"），不得逐字照搬本 skill 的流水线名称。
5. **求解表达按内容决定**：成熟求解器和常规算法用连续段落或普通编号简要说明，不固定编号形式，也不把步骤做成表格；只有包含实质分支、循环、状态更新或终止机制的复杂自研算法才允许算法流程图。表格只用于结果对比与必要的参数清单。
6. **证据按需写入**：只写 `docs/02/03` 中适用且有真实结果的模型对比、灵敏度、鲁棒性或检验。凡正文声称模型更优、稳定或可靠，必须紧邻给出对应证据；不设每问或全文最低数量。
7. **附录含全部完整可运行源码**：附录必须先输出一个独立、可见、居中的一级标题“附录”，再用 `\appendix` 切换后续附录小节编号；不得只调用 `\appendix` 而省略总标题。附录含支撑材料完整文件列表和全部完整、可运行的源程序；使用 Excel/SPSS 等交互命令时一并附上记录。编译后必须在 PDF 逐页核对该总标题确实出现，且紧凑排版不得以省略必要源码为代价。
8. **数据真实**：论文中所有数字与 `results/` 一致，不编造、不夸大；**摘要/表内/正文数字三处一致**。论文表格（尤其 LOOCV、回归系数、百分位、方差等易错列）的数值必须**逐项来自 `results/` 实际文件**，写完表格后与对应 CSV/JSON 核对，禁止凭印象或推算填表。
9. **匿名**：全文（摘要页/正文/附录）不得出现参赛者身份、学校、赛区信息。
10. **图表数量基线**：正文图 ≥ 8、表 ≥ 5；每问至少 1 个有信息量的图和 1 个有信息量的表，图表类型按题目证据选择，不强制每问都制作数据图；**每张图必须有明确叙事作用（一图一结论）**，禁止为凑图而堆图；图表全文连续编号（见 `corpus/图表规范-playbook.md`）。
11. **图片必须来自画图专用 skill**：正文插图一律取自 `mm-figures`/`mm-diagrams`/`mm-visual-concept` 的产出（`figures/` + `docs/04`/`docs/05-diagrams-report.md`/`docs/05-visual-report.md`）。若图表缺失或尚未生成，先**向上调用** `mm-figures`、`mm-diagrams`、`mm-visual-concept` 补齐，再继续撰写；**写作中临时发现某处特别适合某张图（此前未规划）时，同样先暂停撰写，明确图类型（数据图/流程图/纯视觉示意图），回写对应画图 skill（mm-figures / mm-diagrams / mm-visual-concept）产出并登记对应报告后再继续**；本 skill 禁止用临时脚本、占位图或其他方式自行产出图片。
12. **正文边界与篇幅**：正文指摘要之后、附录之前的全部内容，包含正文顺序章节、必设的 AI 工具使用声明和参考文献；摘要与附录不属于正文。正文篇幅为 27--30 页，若当届官方文件有更严格或不同的明确要求，以官方文件为准。重点放在模型建立、真实结果与解释；为补足必要篇幅，可增加题目相关的推导、求解细节、验证证据、结果解释及适用图表。图表可以是数据图、结构/机制图、复杂算法流程图或题目场景示意图，但每张必须服务明确论点并有正文引出和解读；禁止用重复论述、无信息图表或排版手段注水。
13. **模型复杂度展示**：只在有论证价值时写状态空间、决策变量规模、算法复杂度或约束规模；重点解释这些复杂度为何与题目困难匹配。不得为了显得高级强行制造大状态空间或无贡献模块。
14. **结果描述**：结果不能只报数。每个关键结果说明数值、机理与决策含义；若进行了灵敏度或鲁棒性分析，再解释排序、归因、最坏情形和通过标准。大表给读表指南，每张图给出实质解读，不强制制造反直觉结果。
15. **故事线与冷读检查**：全文按问题→障碍→选择→证据→转折→决策→边界推进，完成初稿后按 `references/teacher-storyline-2026.md` 冷读检查。
16. **纯视觉示意图**：完整论文必须至少一张纯视觉示意图；画布文字保持最小化，只保留去掉后会造成歧义的必要短标签、变量或方向说明，并登记于 `docs/05-visual-report.md`。
17. **图表命名规范**：论文可见的图文件名与图题不得带问题编号前缀，使用描述性内容名称。
18. **问题分析章标题**：每问一节，固定为「问题X的分析」；同一问的多个分析要点合并在该小节，另可设置「各问之间的联系」。
19. **模型章标题**：四问合章时，每个子问题标题末尾加「——问题X」；各问分章时使用「问题X的模型建立与求解」。
20. **AI 工具使用声明**：每篇论文必须在参考文献之前设置该不编号小节。未使用 AI 时如实写“本参赛队在竞赛过程中未使用任何AI 工具。”；使用 AI 时如实写“本参赛队在竞赛过程中使用了AI 工具，主要用于【简要用途】，详细使用情况见支撑材料。”AI 使用详情只放在支撑材料《AI 工具使用详情.pdf》，附录不重复设置说明小节。
21. **支撑材料精简红线**：支撑材料内容严格遵循共享规则，不放论文、阶段报告、原始附件或内部流程文件；压缩包 ≤20MB，论文附录文件列表与其一致。
22. **成稿去过程化与去套话**：论文作者撰写的标题、摘要、正文、图表可见文字、附录说明和页眉页脚必须遵循 `references/de-ai-writing.md` 的第 8 节。该规则禁止暴露生成过程的词语与空泛模板句；仅官方要求的“AI 工具使用声明”可使用其中与 AI 相关的措辞。终稿前必须运行 `scripts/audit_submission_language.py paper`，未通过不得交付。
23. **人的思维逻辑**：论文必须按读者理解问题的自然顺序组织：题目要求/现实障碍 → 可用数据与必要假设 → 模型选择理由 → 变量、目标与约束 → 求解 → 证据 → 对题目的回答与适用边界。每一节开头承接前文留下的具体问题，结尾落到可核验的判断或下一步所需依据；不得把内部流程、报告编号、文件路径、门禁状态或工具操作写成正文叙事。避免机械的“背景—方法—结果”套段、四个问题完全同构的小节和没有证据的总结句。
24. **题目要求优先**：正文的首要目标是逐条回答题面要求，而不是展示模型、算法或写作能力。结构草稿中必须建立“题面要求/子问题 → 正文小节 → 模型变量与约束 → 结果证据 → 最终回答”的追踪表；写作和验收时逐段检查其服务对象。与任何子问题无关、不能改变判断或不能支撑题面交付的内容不得写入正文；不得为了达到页数、图表数量或章节数量而扩写。若某项预设分析对题目不适用，记录原因并跳过，不强行套用。
25. **模型评价与推广从简**：第六节只做收束，不重新介绍模型、重复结果或新增未经验证的结论。仅保留有证据的优点、至少一个真实局限，以及与题目数据和假设相容的改进/推广条件；原则上控制在正文的 3%--5%（通常半页至一页），不单独堆放灵敏度、鲁棒性或模型对比结果。相关证据应写在对应问题的结果分析处，第六节只引用其结论并说明边界。
26. **中文文献为主**：参考文献只收录正文实际引用且可核验的来源。无用户或题目特殊要求时，中文权威文献原则上不少于 60%，并明显多于外文文献；优先使用中文标准、政府/行业资料、权威教材及与题目直接相关的中文期刊论文。原始算法出处、国际标准、关键前沿成果或国内无可靠替代的来源保留外文引用。不得为满足比例改引二手、低质量或与论证无关的中文文献，更不得编造文献。
27. **评卷导向落地**：论文逐问呈现“本题特有困难 → 针对性选择或改造 → 可复算求解 → 真实结果 → 对题面要求的回答”。不得把通用模型、算法定义或方法清单单独堆成主体内容；使用成熟方法时，写清其针对本题的变量、约束、参数、适用条件和取舍。任何“创新”“有效”“更优”主张均须有具体改造和对应证据，不得以复杂术语、固定模板或形式性图表替代实质内容。
28. **复杂算法写深**：题目需要复杂算法时，正文必须解释其必要性、状态/决策变量、目标与约束、关键更新或转移、初始化、终止/收敛条件、复杂度或规模、关键参数影响、退化/失败情形和验证结果；不得用算法名、伪代码或流程图代替分析。复杂算法的篇幅应放在与题面要求直接相关的机制和证据上，不能只增加术语。
29. **最终答案必须可定位**：每个子问题结尾和全文结论必须直接回答题面任务动词，给出完整对象、数值/方案/排序/判定/解释/建议及必要单位或适用条件。不能只写“模型有效”“结果见表”或只报告性能指标；读者不应自行从多张表、公式或代码推导答案。结构草稿和终稿均须保留“题面要求 → 最终答案位置 → 支撑证据”的追踪关系，供 `mm-verification` 逐项验收。
31. **目标函数必须说得通**：论文在目标函数前先说明题面目标、决策变量、硬约束和评价指标的对应关系；公式后解释每个目标项、方向、单位/无量纲化、权重或惩罚来源及其对最终答案的影响。多目标模型必须交代归一化、权重或 ε-约束依据，并报告必要的敏感性；不得只给一个加权公式和最优值。
30. **一级标题序号**：表示章节顺序的一级标题使用中文数字序号并顿号，例如“ 一、问题重述”“二、问题分析”“三、模型假设”。“参考文献”“附录”“AI 工具使用声明”等本身不表示顺序的标题不加序号。二级、三级标题按题目结构使用阿拉伯数字层级编号或无编号短标题，全文保持一致；LaTeX 中不得让自动阿拉伯章节号覆盖可见的中文一级序号。

## 工作流

### Step 0：输出格式（默认 LaTeX）

- **本 skill 默认且唯一输出 LaTeX**：`paper/论文.tex` + xelatex 编译 `paper/论文.pdf`，不再提供 Word/DOCX 排版路径。
- 若用户明确要求 Word/DOCX，明确告知：Word 排版流水线已移除，需另用旧版工具或自行转换，不在本 skill 范围内。
- 写作前先确认本机已装 TeX 发行版（MiKTeX/TeX Live），用其自带的 `xelatex` 引擎编译（当前环境 xelatex 不在 PATH，需定位 MiKTeX 安装目录下的 `xelatex.exe`）；缺失时先安装，安装完成后再动笔。

### Step 0.25：第一遍——结构草稿与插图需求

- 根据 `docs/01~03` 生成 `paper/structure-draft.md`，确定章节、每问核心论证链、结果证据与预计篇幅。
- 生成 `paper/figure-requirements.md`，逐图登记类型、核心用途、来源结果 ID、候选正文锚点、推荐宽度和负责 skill；完整论文必须规划至少一张纯视觉示意图，部分任务可将视觉分支标为 `n_a`。
- 同时创建 `paper/writing-gates.md`，写入 G-1~G-5 的初始 `pending` 状态；结构草稿阶段不要求这些门禁全部通过。
- 第一遍不生成完整论文，不编造尚未完成的图题或图文件。
- 图件完成并在 `project-manifest.json` 登记后，才进入第二遍终稿。

### Step 0.5：第二遍写作前门禁（GATE，防止跳步）

**未通过下列任一 GATE，不得开始撰写正文。** 每项必须在 commentary 输出 `PASS + 证据`，并写入 `paper/writing-gates.md`（表格：检查项 | 证据 | 结果）。GATE 是流程硬门禁：发现 G-1~G-5 任一未满足，立即停下补齐，不允许带着缺口继续。

| GATE | 检查内容 | 通过标准 |
|---|---|---|
| G-1 必读已读 | `references/modeling-and-solving-writing.md`（写模型章时）、`corpus/图表规范-playbook.md`（写结果/插图前）已完整读取 | 引用该规范/playbook 中与本部分直接相关的 1~2 条原文，禁止只写"已读" |
| G-2 图表齐全 | 按 manifest 检查适用的 `figures/`、`docs/04`、`docs/05-diagrams-report.md`、`docs/05-visual-report.md` | 列出实际文件清单；完整论文含至少一张纯视觉示意图，`n_a` 图件分支不视为缺失；缺图或写作中临时新增图，先回写对应 skill |
| G-3 上游数据 | `docs/02` 公式/符号、`docs/03` 结果已核对 | 说明每问公式与结果来自哪个报告小节，禁止凭空写数 |
| G-4 结构拟定 | `paper/structure-draft.md` 与 `paper/figure-requirements.md` 已完成 | 核对每问论证链、插图锚点与 manifest 图件 ID |
| G-5 工具就绪 | xelatex/MiKTeX 可用，`paper/` 存在 | 定位 `xelatex.exe` 路径或确认已安装 |

论文终稿开始前，`paper/writing-gates.md` 和 manifest 的 `paper_gates` 必须全部 PASS 并随论文保留；验收阶段据此反查跳步。

### Step 1：确认结构与排版要求

- 先读 `references/official-cumcm-format-2026.md`，确认当届官方硬性要求（页边距、页数、页码、附录、匿名）。
- 固定按 CUMCM 2026 结构与中文论文规范执行，见 `references/cumcm-paper-structure.md`。
- 若用户提供官方模板/格式要求，以官方为准，覆盖默认结构。
- 确认摘要排版目标：主标题与摘要标题均为三号，整页但不过页、加粗关键方法/结论、无目录、页码从摘要页起；官方模板或用户另有明确字号时记录覆盖原因。

### Step 2：规划各节内容来源

把每个章节映射到上游报告与图表，避免凭空编造：

| 章节 | 内容来源 |
|---|---|
| 摘要 | 综合全部报告，见摘要规范 + `corpus/摘要写作-playbook.md` |
| 问题重述 | `docs/01` 问题重述 |
| 问题分析 | `docs/01` 问题分类/建模方向（逐问分析 + 技术路线图） |
| 模型假设 | `docs/02` 模型假设 |
| 符号说明 | `docs/02` 符号表 |
| 模型建立与求解 | `docs/02` 公式 + 求解步骤 + `docs/03` 结果（每问内嵌结果表与结果分析） |
| 模型对比 | 仅当适用：`docs/02` 对比方案 + `docs/03` 对比结果 |
| 模型检验/灵敏度/鲁棒性 | 仅当适用：`docs/02` 方案 + `docs/03` 结果 |
| 模型评价 | 综合，客观（优点+缺点示弱+推广） |
| 参考文献 | 实际引用且可核验的文献；中文权威文献原则上不少于 60%，原始方法与国际标准等按需保留外文 |
| 附录 | `code/` 全部完整可运行源码 + 支撑材料文件列表 |

### Step 3：撰写正文

- 章节结构遵循 `references/cumcm-paper-structure.md` 八段式骨架（含问题分析章）；语言遵循 `references/de-ai-writing.md` 与 `corpus/语言与措辞-playbook.md`，不堆套话。
- 写"某问建模与求解"前，**必须先完整读** `references/modeling-and-solving-writing.md`（操作规范，已合并 28 篇共性 + 六篇论证思路），不得跳过或只读简介。
- 公式、符号与 `docs/02` 一致；求解表达按 `mm-modeling/references/pseudocode-guide.md` 根据内容采用连续段落或普通编号，复杂自研算法可使用流程图。
- 插图按 `docs/04`、`docs/05-diagrams-report.md`、`docs/05-visual-report.md` 说明插入，图注/表注全文连续编号；结果表用三线表。写结果与插图前**必须先读** `corpus/图表规范-playbook.md`（图必有文、表格克制、图表紧邻文字）。**写正文前先核对 `figures/` 与 `docs/04`/`docs/05-diagrams-report.md`/`docs/05-visual-report.md` 是否齐全**，缺图或写作中临时发现新图需求时，先停止该处撰写、回写对应画图 skill，待图产出并更新报告后再继续；不在本阶段自行生成。
- 流程/框架图优先用 `\includegraphics` 插入 `mm-diagrams` 生成的矢量 PDF；600 DPI PNG 只作兼容与核查备份，不得在 PDF 可用时主动降级为位图。插入后按实际版心复核最终字号与线宽。
- 模型对比、灵敏度、鲁棒性和检验只在适用时写入，可内嵌于对应论证位置，不强制独立小节；动态、空间演化或迭代题写入关键状态结果。
- **表格数字核对**：每张结果表写完后，与 `results/` 对应文件逐项核对（易错列：LOOCV-RMSE、标准化系数、$p$ 值、百分位区间、logdet/方差等）；发现不符立即修正，禁止沿用初稿数值。
- **章节归属检查**：图表插入后确认其位于对应问题章节内（不得出现问题二的表落在问题一、问题三的图跟在问题四后面等跨章节错位），并在提交前通读目录结构核对一遍。
- **关键汇总表位置**：数据审计表、符号表和核心结果汇总表紧跟首次引出文字，并排在同节大型图片之前。默认仍用 `[htbp]`；编译后若因多个浮动体竞争而脱离引出段、落到无关图片之后或形成孤立浮动页，只将该关键表改为 `[H]`，不得把全部表格机械锁位。
- **问题分析与数据预处理分离**：问题分析章只做逐问定性分析与技术路线，不写数据清洗、特征构造、描述统计等预处理细节；数据驱动题的数据预处理在数据重要时独立成章（如"数据预处理与特征构造"，置于问题分析之后、模型假设之前），否则并入各问"模型建立"部分，不得放在问题分析章内。
- **推导链自检**：每问模型建立必须形成闭环推导链——变量定义 → 基础公式（给出机理/统计/数据形态来源）→ 本题化改造 → 目标与约束；纯经验公式必须说明来源，后一条公式须解决前一条公式尚未解决的困难；写完模型节后逐条自检"这条公式从哪来、为什么需要它"，不允许直接抛出公式。
- **求解展示方式**：成熟求解器只写一两句"模型性质→工具→关键参数→结果"；常规算法用连续段落或普通编号，编号形式不固定；只有包含实质分支、循环、状态更新或终止机制的复杂自研算法才允许算法流程图。不得给每问机械设置相同的"求解流程"小节。
- **反模式**：四问小节标题完全一致（如每问都出现"建模思路"）即模板化，会直接暴露生成痕迹；承接段不设标题，小节标题随问拟定。
- **问题重述与分析的自然篇幅**：问题背景和逐问重述按题目数量、对象复杂度及输入输出边界自然展开，不设置最低占页率；`1.1 问题背景`不得只写可替换到任意题目的短套话。问题分析只有在缺少问题要害、选择理由或交付落点时才补写，不得为了填页重复题意。具体执行 `references/problem-restatement-writing.md` 与 `references/problem-analysis-writing.md`。

### Step 4：生成论文（LaTeX）

**LaTeX 路径（默认）**：

- **前置检查**：本机必须已安装 TeX 发行版（MiKTeX/TeX Live），并使用其自带的 `xelatex` 引擎（当前环境 xelatex 不在 PATH，需从 MiKTeX 安装目录调用 `xelatex.exe`）。若未安装，先装 MiKTeX 或 TeX Live；无法安装时暂停并告知用户，不得以未编译的 `.tex` 充当最终交付。
- 生成 `paper/论文.tex`（ctexart / xelatex），结构同 Step 2 规划，公式用 `equation` 环境自动编号、正文 `\eqref` 交叉引用；凡同一个公式表达中原本会用逗号、分号等并列书写多个等式，均用 `equation` 内嵌 `aligned` 与左花括号逐行排版，每行一个等式，整体只保留一个式号，不要求这些等式属于同一模型。需要逐条引用或分别推导的公式才拆分编号；三线表用 `booktabs`（`\toprule/\midrule/\bottomrule`）；插图用 `graphicx` 并 `\graphicspath{{figures/}}`。
- 一级标题按中文序号手工或通过可靠的 LaTeX 编号配置显示（“一、”“二、”“三、”…），非顺序标题使用无编号命令（如 `\section*{参考文献}`、`\section*{附录}`、`\section*{AI 工具使用声明}`）；编译后逐页核对标题显示，禁止出现“1、问题重述”或“九、参考文献”这类混用。
- **LaTeX 必须遵守的官方硬性要求**：
  - `\documentclass[12pt,a4paper]{ctexart}` + `\usepackage[margin=2.54cm]{geometry}`（小四号正文；页边距 ≥2.5cm）；
  - 摘要独占一页（`\newpage`）、页码从摘要页起（`\pagenumbering`/`\thispagestyle` 控制，页脚中部从 1 起）；摘要后的正文各章节连续自然排版，不因章节标题另起一页；附录可在前文结束后另起页。
  - 无官方模板或用户覆盖时，摘要页主标题必须使用 `{\zihao{3}\bfseries ...\par}`，摘要标题使用 `{\zihao{3}\bfseries 摘\quad 要\par}`，两者间距默认 `0.4em`；
  - 附录前一级标题使用小三号黑体并居中，二级标题四号黑体，三级标题与正文小四号，图题表题小四号，表内文字五号；正文单倍行距、两字符首行缩进，相邻正文段落额外间隔约 `0.25\baselineskip`；
  - 不设页眉：`ctexart` 默认可能是 headings 样式（页眉自动出现章节名与页码），必须显式 `\pagestyle{plain}`（页码在页脚中部）或 `\pagestyle{empty}`（无页码，仅用于演示草稿）；
  - 无目录；正文 ≤30 页；附录含全部完整源码（可用 `listings`/`verbatim` 紧凑排版）；
  - 全文匿名，无身份/学校/赛区信息。
  - 单页图表默认使用 `[htbp]`；一级标题边界使用 `placeins`，并在每个 `\subsection` 前执行 `\FloatBarrier`，禁止图表跨入下一小节。只有必须紧跟首次解释的关键图表才使用 `[H]`。顺序保持"文字引出 → 图表 → 解读"。确需跨物理页面的长表改用 `longtable`，按 `references/multipage-table-writing.md` 设置续表，不得嵌套在 `table` 中。
- **排版间距与留白控制**：图表与正文之间不得留下大段空白。先判断空白来自文字篇幅失衡、浮动约束、图表锚点还是图件尺寸，不预设“优先缩图”；默认 `[htbp]`，一级和二级标题边界均使用 `\FloatBarrier` 防止跨节漂移。图片缩放必须保持标签清晰、比例协调，不得把图缩到难以阅读。
- **相邻证据组留白审计**：表格与其直接对应的图（或图与对应表）若在源码中连续出现、共同支撑同一结论，编译后必须作为一个局部证据组检查。若独立浮动导致表后或图前出现明显空白，且当前页剩余空间足以容纳两者，应优先把该组关键表/图局部改为 `[H]` 或合并为同一排版块；不得只凭“仍在同一小节”判定通过。逐页核查相邻表图之间的空白比例，避免浮动间距与图件画布留白叠加。
  - 编译后逐页检查浮动积压、跨节漂移和"仅图题无正文"页面；综合调整文字、插入位置、浮动参数、关联图组合和局部尺寸，只有关键图确需锁位时才改为 `[H]`。
  - **前部改写回归检查**：改动问题背景、问题重述、问题分析或其他位于浮动体之前的文字后，必须双遍编译，并从改动页连续检查到首张后续关键表。至少核对图文顺序、孤立图页、大块无效留白、关键表页码与首次引出位置；不得只检查改动段本身。
  - **局部修复顺序**：先审计相邻文字。缺少问题要害、证据、选择理由或交付边界时，补充对应的实质内容；存在重复题意、可合并句子或应移至其他章节的细节时，删减或压缩。若改变图片大小不适用、会损害可读性或不能解决空白，允许通过上述有依据的增写或减写平衡分页。文字已经完整且紧凑时，再调整图表锚点/叙事顺序、浮动参数、关联图组合和可读范围内的局部尺寸。禁止为排版编造内容、重复注水、删除必要论证，或改变全局字号、行距和页边距。
  - **表格字号与对齐**：表内文字统一五号（`\zihao{5}`，10.5pt）；表头、文字和数字全部水平居中，长文本使用 `>{\centering\arraybackslash}p{}` 或等价定宽列自动换行；使用紧凑列距与行距，禁止为消除溢出擅自缩小字号。
  - **表格浮动与跨页**：单页表格默认 `[htbp]` 并受一级、二级标题边界的 `\FloatBarrier` 约束；只有必须锁定在解释段后的关键表才使用 `[H]`。确实无法单页容纳的表格允许用 `longtable` 跨页，但必须设置：首页正常表题；续页“续表 N　原表题”；续页重复完整表头与单位；非末页标“续下页”；仅末页使用 `\bottomrule`。续页沿用原编号且不重复进入表目录，整张长表必须在同一小节内结束。
  - **表格位置复核**：逐表比对“首次正文引用页 → 表题页 → 下一小节标题页”；关键汇总表不得晚于同节的大型图片，不得单独漂到下一页下半部或浮动专页。发现异常先调整源文件叙事顺序，再按需对单张关键表使用 `[H]`。
  - **图片位置复核**：逐图比对“首次正文引用页 → 图题页 → 下一小节标题页”，确认图片位于对应问题和小节，且顺序为“文字引出 → 图片 → 实质解读”。关键图片不得脱离引出段、形成孤立图页或漂到下一小节；异常先调整叙事顺序和锚点，再在可读范围内调整浮动参数与局部尺寸。
- 编译验证（用 MiKTeX/TeX Live 自带的 `xelatex`）：`xelatex -interaction=nonstopmode -halt-on-error paper/论文.tex` 产出 `paper/论文.pdf`；编译必须通过（无未定义引用、无缺图），若中文缺字检查 ctex/字体配置。
- **语言门禁**：编译前运行 `python scripts/audit_submission_language.py paper`，扫描 `paper/` 下的 TeX 正文源文件。出现禁用表达时，按 `references/de-ai-writing.md` 第 8 节改写并重跑；只有官方规定的 AI 工具使用声明可用 `language-audit: allow-start` 与 `language-audit: allow-end` TeX 注释包围后豁免。不得用豁免标记包围其他正文。
- **人工冷读门禁**：语言脚本通过后，逐节按“本节要解决的具体问题是什么 → 证据来自哪里 → 为什么得到这个判断 → 该判断如何服务题目”冷读。若删去一段后论证、边界或证据没有损失，删除该段；若读者需要跳回上游报告才能理解变量、公式或结论，补足正文中的必要连接。此门禁不能由关键词脚本替代。
- **题面追踪门禁**：提交前逐条核对题面要求追踪表。每个 `P-##` 子问题必须至少对应一个明确的模型、结果和结论落点；每个正文核心段落必须能指出其服务的 `P-##` 或 `REQ-###`。发现“写得正确但没有回答题目”的内容时删除或改写；发现题面要求没有模型、证据或结论承接时，回补对应内容后再交付。
- 生成后校验：PDF 页数、公式编号与引用一致、图片清晰、摘要未溢出、页边距合规、全文匿名。正文页数按摘要之后至附录之前计算，包含参考文献与必设的 AI 工具使用声明，默认须为 27--30 页，若当届官方文件有更严格或不同的明确要求则按其执行。篇幅调整可补充“公式推导与适用条件、实际算法与参数代入、验证证据、结果解释及适用图表”；只要服务于题目论点，数据图、结构/机制图、复杂算法流程图和题目场景示意图均可增加，且须有正文引出和实质解读；禁止重复论述、无信息图表或排版注水。
- 定位 Poppler 的 `pdftotext` 后运行：`python <mm-paper-writing目录>/scripts/audit_abstract_page.py --pdf paper/论文.pdf --abstract-tex paper/sections/00-abstract.tex --pdftotext <pdftotext路径>`。只有 `status=pass` 才可交付；重点记录 `title_size_three`、`han_count` 与 `fill_ratio`。官方模板或用户明确覆盖标题字号时才可追加 `--allow-title-override`，并在验收报告写明依据。没有 `pdftotext` 时必须逐页渲染并用等价坐标工具测量，不能跳过占用率。

**输出要求**：摘要页排版目标、图表数量基线（图≥8、表≥5，每问至少 1 个有信息量的图和 1 个有信息量的表）、正文范围与篇幅、数字三处一致与匿名要求均按共享规则执行；`paper/论文.pdf` 为最终交付物。完成后更新 `project-manifest.json` 的 `paper_final` 状态、图件引用、`paper_gates` 和产物哈希。

## 边界

- 不改动数值结果与图表内容；发现矛盾回写对应阶段。
- 不画图、不生成图片文件；所有插图必须来自 `mm-figures`/`mm-diagrams`/`mm-visual-concept` 的产出，缺失时回写对应 skill 补齐，而不是在本阶段替代。
- 不编造参考文献、不编造数据。
- 生成的论文是"参考稿"，最终以当届官方规则与模板为准。
