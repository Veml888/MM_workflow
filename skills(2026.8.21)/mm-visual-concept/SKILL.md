# 数学建模纯视觉示意图

把论文中的抽象题意或算法机制转化为准确、清晰、有视觉吸引力的图。优先保证信息表达和论文适配，不把“纯视觉”机械理解为零文字。

## 核心原则

- 每篇完整数学建模论文必须至少放置 1 张由本 skill 产出的视觉示意图；不得以数据图或普通流程图替代这一最低数量。
- 在候选章节中选择信息增益最高、与相邻正文结合最自然的位置，禁止为满足数量而随意塞图。
- 所有对象、关系、约束和环境必须能追溯到题面、模型或结果，禁止为美观虚构事实。
- 允许必要的短标签、变量、图例和方向说明。若去掉文字会造成歧义，就保留文字。
- 先建立视觉层级和构图，再决定风格与工具；不要从图标库或固定模板反推内容。
- 不默认黑白、Lucide、左中右流水线或固定布局。根据论文主题和信息结构选择视觉语言。
- 不限制色彩数量或具体视觉风格；以事实准确、视觉效果和论文协调性为准。验收不得套用流程图的黑白灰规则。
- 生成分辨率不能替代构图质量；SVG 可编辑性也不能替代语义清晰度。

## 输入与产出

读取题面，以及存在的 `docs/01-analysis-report.md`、`docs/02-modeling-report.md`、`docs/03-results-report.md`、`paper/structure-draft.md`、`paper/figure-requirements.md` 和 `figures/` 文件清单。先确认论文中是否已有本类示意图，再选择新增或替换；只读取与当前图和放置位置有关的内容。跨阶段通用规则以 `../mm-orchestrator/references/cumcm-2026-shared-policy.md` 为准。

默认产出：

- `figures/<descriptive-name>.png`：论文可直接使用的成品；
- `figures/<descriptive-name>.svg`：仅在采用矢量或混合路线时提供；
- `docs/05-visual-report.md`：记录图的目标、事实依据、路线、提示词或矢量结构、验收结果、候选位置比较、最终章节与精确插入锚点。

## 路线选择

先读取 [references/concept-visual-playbook.md](references/concept-visual-playbook.md)，再按下列规则选择。

### A. 内置 imagegen：默认视觉路线

用于场景理解、空间关系、对象交互、自然或工程环境、具象化算法隐喻、带材质和景深的论文插图。

1. 使用内置 `image_gen` 工具，不要求 API Key，不调用自建图像 API 脚本。
2. 将题面事实整理成紧凑的制作规格：用途、核心信息、对象、关系、视角、构图、视觉层级、风格、配色、必要文字和禁止项。
3. 明确要求“无多余对象、无水印、无装饰性乱码、不得改变题面关系”。
4. 图中若需要精确中文、公式、变量或拓扑，不依赖生成模型直接绘制；改用混合路线添加。
5. 生成后必须视觉回读，逐项核对对象数量、方向、位置、约束和文字。

### B. 原生 SVG：精确表达路线

用于精确拓扑、少量几何对象、严格箭头关系、变量标注、可编辑矢量或黑白印刷要求。不要用它模拟复杂插画。

1. 根据内容自建设计系统，可使用线条、有限色彩、填充、透明度、纹理和自绘符号；保持同图一致即可。
2. 标签应简短且必要，字号按最终论文尺寸检查。
3. 需要 PNG 时运行：

```bash
python scripts/render_svg.py figures/input.svg --png figures/output.png --dpi 600 --width-cm 14.5
```

### C. 混合路线：精确性与表现力并重

用于既需要丰富场景，又需要准确标签、变量、路径或边界的图。

1. 用内置 `imagegen` 生成无文字或少文字的基础场景。
2. 用 SVG 覆盖精确箭头、编号、变量、图例和重点边界；不要让生成模型承担精确排版。
3. 保留基础图和矢量覆盖层，导出最终 PNG，并在报告中说明合成结构。

## 工作流

### 1. 审计最低配图要求并选择位置

确认每篇完整论文至少有 1 张本类视觉示意图。若没有，必须制作；若已有，检查其是否真正解释题意或算法，低质量占位图不计入最低数量。

比较至少两个有意义的候选位置，按信息增益、正文关联、与已有图的非重复性、叙事连续性选择最佳位置。常见候选包括：

- 问题重述之后：放题目场景、对象关系或空间规则图；
- 模型建立的核心机制之后：放变量关系、约束作用或机理隐喻图；
- 算法原理首次完整说明之后：放搜索、迭代、状态变化或决策机制图。

在报告中写明 `最终章节 + 插在何段/何公式之后 + 选择理由`，并提供不可歧义的插入锚点。图件 skill 不修改 `paper/论文.tex`；由 `mm-paper-writing` 统一插入图及图注。

### 2. 定义沟通目标

写一句话：`这张图要让评委在 5 秒内看懂 ________。`

列出：必须出现、必须表达、不得出现、允许简化。若目标仅靠数据图或完整流程图更合适，转交对应 skill。

### 3. 制定视觉方案

确定：

- 信息焦点与次级信息；
- 观察视角和空间结构；
- 构图骨架与视觉动线；
- 风格、色彩、线条和背景；
- 必要标签及其载体；
- A/B/C 路线和选择理由。

避免把所有算法都画成流水线，也避免把所有题目都画成图标网络。

### 4. 制作与迭代

- imagegen 路线：先做完整基础版本，再针对单一问题定向修改；每轮重申事实约束。
- SVG 路线：先完成结构与层级，再处理细节；不要从装饰开始。
- 混合路线：先锁定基础场景，再添加精确覆盖层，避免反复生成导致构图漂移。
- 不设武断的“两轮上限”；通过验收或明确说明工具限制后再停止。

### 5. 双重验收

同时检查科学准确性和视觉质量。使用 playbook 中的评分表；语义准确、5 秒可读性、构图层级、风格一致性、论文适配五项均应达到 4/5，且不存在一票否决问题。画布文字应保持最小化：只保留去掉后会造成歧义的短标签、变量或方向说明，不设死的字符数量上限。

不允许仅凭“看起来正常”写 `passed`。报告中记录具体证据和仍存在的限制。

### 6. 交付

报告稳定 ID、最终文件路径、采用路线、最终提示词或 SVG 结构说明、最终论文章节、精确插入锚点、图注建议、嵌入宽度和版本，并同步更新 `project-manifest.json`。项目使用的最终图必须保存到工作区 `figures/`，不能只留在生成工具默认目录。交付前再次确认每篇论文的最低 1 张示意图要求已经满足。

## 边界

- 折线、柱状、散点、热力、地图统计、曲面等数值图使用 `mm-figures`。
- 技术路线、完整求解步骤、泳道和标准流程图使用 `mm-diagrams`。
- 不重跑模型，不修改论文结论，不把艺术化效果置于事实准确性之上。
- 用户明确要求黑白、纯矢量、零文字或指定风格时，以用户要求为准。
