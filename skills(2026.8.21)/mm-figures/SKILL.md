# 数学建模：数据图表生成

本 skill 是图件制作阶段的数据图分支。目标：把 `results/` 里的数值结果变成可嵌入 LaTeX 论文的出版级数据图。只画"数据图"，非数据图由 `mm-diagrams` 或 `mm-visual-concept` 负责。

## 输入与产出

- 输入：`docs/03-results-report.md`（必须）、`results/`、`paper/figure-requirements.md`（完整流程中必须）。
- 产出：`figures/*.png`（论文嵌入用，另存矢量 `.pdf` 与 `.svg`）、`docs/04-figures-report.md`（必须）。

跨阶段通用规则以 `../mm-orchestrator/references/cumcm-2026-shared-policy.md` 为准；逐图稳定 ID、来源结果 ID、正文锚点、格式、哈希和版本写入 `project-manifest.json`。

画图前先读 `references/chart-selection.md`（选什么图，含创新图与 3D 图）与 `references/figure-style-guide.md`（配色、字体、多面板与三格式导出）。

## 硬性要求（评委偏好，务必满足）

1. **3D 图可选**：仅当数据确实适合三维展示（两个自变量 → 一个因变量、三维解空间、需同时表达三维信息）时，才采用 3D 曲面图 / 3D 散点图 / 3D 柱状图；不适合时**不要为凑数硬画**。
2. **选图以"最能反映数据 + 让评委眼前一亮"为标准**：优先选择与数据特征最匹配、表达力最强的图种（一图一结论），不要局限在柱状图/折线图；在常规图上做精细化与组合创新（子图、双轴、误差带、注释、配色映射、多帧等），但不为炫技牺牲可读性与准确性。
3. **多帧仿真展示**：只有时间演化、空间演化或迭代问题才要求多帧；每个适用子问题展示初始、关键中间与终止状态，二维视角必给，三维仅在数据适合时采用。
4. **字体可读**：所有文字在论文版面中必须清晰可读；字号与字体分工见 `references/figure-style-guide.md`。
5. **样式红线**：白底黑字、高对比配色；重要类别同时用颜色、线型或点形冗余编码；每张终稿图导出 PDF + SVG + PNG，PNG ≥300 DPI，多面板推荐 420 DPI。
6. **文字重叠零容忍**：数据标签、节点编号、图例和关键标注不得压住图形元素或其他文字。导出后运行 `scripts/check_figure_overlap.py`，并按 `references/figure-style-guide.md` 视觉回读，发现重合即返工。
7. **命名规范**：图文件名与图内标题不得带"问题一/二/三、Q1/Q2、q1/q2"等编号前缀，使用描述性内容名称；论文图题同步遵守。

## 工作流

### Step 1：盘点需要画的图

从 `docs/03-results-report.md` 的"供图表阶段使用的数据清单"提取图需求，输出图清单并标注图种与维度：

```text
FIGURE PLAN:
[ ] 成本曲面.png      成本随(位置x,位置y)变化（3D 曲面）
[ ] 多方案对比.png    多方案对比（分组柱状）
[ ] 参数灵敏度.png    参数灵敏度（折线+误差棒）
[ ] 目标函数等高线.png    目标函数等高线（2D 等高线，多维度）
[ ] 演化初始状态.png     仿真第 0 帧情形（2D）
[ ] 演化中间状态3D.png  仿真第 10 帧情形（3D，可选）
```

清单按题面实际增删；仅当某个子问题存在能支持核心结论的数据时，才为该问制作数据图。全局满足"种类丰富、一图一结论"，3D 图仅当数据适合时列入清单。当论文正文目标为 28~30 页、重点在"模型的建立与求解"时，图总量建议做到 **12~20 张**：优先为模型构建与求解章节准备有数据依据的结果图与多帧演化图，其次补充检验/灵敏度/鲁棒性图；每张图必须有明确叙事作用（一图一结论），禁止为凑图而堆图。每个子问题的图/表证据总量由共享规则统一约束，非数据证据由 `mm-diagrams` 或 `mm-visual-concept` 提供。

### Step 2：按样式指南出图

- 严格套用 `references/figure-style-guide.md`：配色、字体分工、字号、2×2 面板、DPI、图例、边框。
- 若采用 3D 图，注意视角（`view_init`）与配色映射（`cmap`），确保高维信息可读、黑白打印可辨识。
- 多帧图统一坐标轴范围与配色，便于跨帧对比；帧序号标注在图内。
- 出图后回读 PNG/PDF 检查标签是否压线/压柱/压点（用 PyMuPDF 检测文字 bbox 与描边图形相交，忽略白底盖层与图例框内文字），重合即返工；**再运行 `scripts/check_figure_overlap.py --dir figures/` 做文字-文字重叠扫描，重叠数必须为 0**；2×2 面板必须标 (a)(b)(c)(d) 且行距足够（底部标题不得与上排刻度/xlabel 相交）；图例不得压标题；热力图、3D 图、堆叠柱小标签按 `references/figure-style-guide.md` 防复发条款执行；节点编号必须带白色底框。
- 每张终稿图导出 PDF + SVG + PNG 三种格式；PNG 分辨率按 `figure-style-guide.md`（≥300 DPI，多面板 ≥420）。

### Step 3：写图表说明

写 `docs/04-figures-report.md`，逐图记录：稳定 ID、文件名、三种格式、图种、维度、展示内容、来源结果 ID、对应正文锚点和版本；同步更新 `project-manifest.json`。

## 边界

- 不画技术路线图/流程图/模型结构图/机理示意图（那是 `mm-diagrams`）。
- 不重新计算数值结果；只可视化 `results/` 里已有的数。
- 不改结果数值；若发现数据异常，回写 `mm-coding` 核实，不在图阶段擅自修改。
