# 数学建模：数据图表生成

本 skill 是图件制作阶段的**数据图**分支。目标：把 `results/` 里的数值结果变成可嵌入 LaTeX 论文的出版级数据图。只画"数据图"；非数据图（逻辑/框架/机理图、场景/空间精确示意图）由 `mm-graphics` 负责。

## 一、定位与边界（本 skill 做什么、不做什么）

- **负责**：把 `results/` 里已有的数值结果 → 出版级数据图。数据图是"展示模型求解结果、或对结果做分析/研究（检验、灵敏度、鲁棒性、多方案对比、多帧演化）"的图。
- **不负责**：
  - 技术路线图 / 流程图 / 模型结构图 / 机理示意图 → `mm-graphics`；
  - 重新计算数值结果 → 只可视化 `results/` 里已有的数，不改结果数值；发现数据异常回写 `mm-coding` 核实，不在图阶段擅自修改；
  - 正文图总量、最终锚点 → `mm-paper-writing` 统筹，本 skill 只对实际需要的数据图负责。

**输入**：`docs/03-results-report.md`（必须）、`results/`、`paper/structure-plan.md`（论证链与锚点）、`paper/figure-requirements.md`（骨架，填入"数据图"区）。
**产出**：`figures/*.png`（嵌入用，另存矢量 `.pdf` 与 `.svg`）、`docs/04-figures-report.md`（必须），并把确定的数据图写入 `paper/figure-requirements.md` 的"数据图"区。

开始前必须确认 `project-manifest.json` 中 `stages.paper_plan.status=complete`，且运行 `python <mm-orchestrator目录>/scripts/validate_paper_plan.py paper/page-budget.json --root .` exit 0。初始化空骨架、未审计初稿或未闭合到 28～29 页的计划不得用于终稿图件制作。

跨阶段不变量遵循 `../mm-orchestrator/references/cumcm-shared-policy.md`；逐图稳定 ID、来源结果 ID、正文锚点、格式、哈希和版本写入 `project-manifest.json`。

## 二、工作流（先决定画哪些，再动手画）

> 本 skill 的主线是**先动脑决定"画什么"（Step 1），再动手"怎么画"（Step 2），最后登记说明（Step 3）**。§三、§四、§五是支撑 Step 2 的规范与选型依据，不是主线。

### Step 1：综合前文，决定要画哪些数据图

读取 `docs/03-results-report.md`（含"供图表阶段使用的候选结果清单"）、`paper/structure-plan.md`（论证链与正文锚点）和 `results/`，综合决定数据图集合——哪些结果值得画、画什么图种与维度、放哪个正文锚点、服务哪条结论。决定后写入 `paper/figure-requirements.md` 的"数据图"区（每图：类型、核心用途、来源结果 ID、候选正文锚点、推荐宽度、负责 skill = `mm-figures`），并输出图清单：

```text
FIGURE PLAN:
[ ] 成本曲面.png      成本随(位置x,位置y)变化（3D 曲面）
[ ] 多方案对比.png    多方案对比（分组柱状）
[ ] 参数灵敏度.png    参数灵敏度（折线+误差棒）
[ ] 目标函数等高线.png    目标函数等高线（2D 等高线，多维度）
[ ] 演化初始状态.png     仿真第 0 帧情形（2D）
[ ] 演化中间状态3D.png  仿真第 10 帧情形（3D，可选）
```

清单按题面实际增删。**本 skill 不设数据图最低数量，也不要求每问都画**；仅当某个子问题存在能支持核心结论的数据时，才为该问制作数据图——每张必须有明确叙事作用（一图一结论），禁止为凑数硬画或重复拆图。需要撑满正文图量（如"数据图不少于 12 张"）属正文锚点级约束，由 `mm-paper-writing` 统筹，本 skill 只确保每张交付的图都有独立结论。

### Step 2：按样式规范出图

严格套用 §四"论文级数据图样式规范"：配色、字体分工、字号、2×2 面板、DPI、图例、边框。3D 图注意视角（`view_init`）与配色映射（`cmap`）；多帧图统一坐标轴范围与配色，帧序号标注在图内。出图后回读 PNG/PDF 检查标签是否压线/压柱/压点，重合即返工；再运行 `python <mm-figures目录>/scripts/check_figure_overlap.py --dir figures/` 做文字-文字重叠扫描，重叠数必须为 0。每张终稿图导出 PDF + SVG + PNG 三种格式，PNG 分辨率见 §四（≥300 DPI，多面板 ≥420）。

### Step 3：写图表说明

写 `docs/04-figures-report.md`，逐图记录：稳定 ID、文件名、三种格式、图种、维度、展示内容、来源结果 ID、对应正文锚点和版本；同步更新 `project-manifest.json`。

## 三、选图标准与图种（Step 1 用这个决定画什么）

### 选图标准

原则：**一图一结论**，图服务于论文论点。选图看三点，优先级从高到低：

1. **数据适配**——最能反映本数据结构与结论的图种（能直观呈现数据特征的优先）。
2. **表达力**——一眼看懂、信息密度高（一图就能定位"结论在哪、依据是什么"）。
3. **眼前一亮**——在常规图上做精细化与组合创新（子图、双轴、误差带、注释、配色映射、多帧），但不为炫技牺牲可读性与准确性。

不要整篇只有柱状图 + 折线图，也不要为凑图种硬上不合适的图。

### 常规图种

| 数据/目的 | 推荐图 | 说明 |
|---|---|---|
| 随时间变化趋势 | 折线图 / 堆叠面积图 | 多系列区分线型/颜色 |
| 分类之间比较 | 柱状图（竖直/水平/分组） | 分组柱状做多系列对比 |
| 占比构成 | 饼图 / 环形图 / 堆叠柱状 | 类别少用饼图，含趋势用堆叠 |
| 两个连续变量关系 | 散点图（+拟合线+置信带） | 标注相关系数 |
| 分布形态 | 直方图 / 箱线图 / 小提琴图 | 箱线图适合多组分布对比 |
| 相关性矩阵 | 热力图 | 标注数值，发散色 |
| 多指标综合比较 | 雷达图 | 指标 5~9 个 |
| 参数影响/鲁棒性 | 灵敏度曲线（折线+误差棒） | 横轴参数、纵轴目标 |
| 预测 vs 实际 | 双线对比 + 误差带 | 强调拟合/预测效果 |
| 收敛过程 | 迭代次数-目标值曲线 | 智能优化/迭代算法必备 |

### 创新/进阶图种（提升丰富度，按需选用）

| 图种 | 适用场景 | 亮点 |
|---|---|---|
| **3D 曲面图**（surface） | 两个自变量→一个因变量 | 多维度展示，直观呈现峰谷 |
| **3D 散点图** | 三维特征/三维解空间 | 展示空间分布与聚类 |
| **3D 柱状图** | 二维分类 × 数值 | 多维度对比 |
| 等高线图（contour） | 二元函数、目标函数地形 | 与 3D 曲面互补，读数精确 |
| 小提琴图 | 多组分布 + 密度 | 比箱线图更丰富 |
| 网络图/关系图 | 节点关系、图论模型 | 展示结构，可用 networkx |
| 桑基图（Sankey） | 流量/资源流向 | 展示分配/迁移过程 |
| 瀑布图（waterfall） | 增量构成 | 展示"由总到分"的增减 |
| 堆叠面积图 | 多成分随时间演进 | 展示结构变化 |
| 平行坐标图 | 高维方案比较 | 多目标优化帕累托解展示 |
| 帕累托前沿图 | 多目标权衡 | 2D/3D 展示非支配解 |

### 3D 立体图规范（可选，数据适合才用）

- **何时用**：结果天然含两个自变量（如空间坐标 x,y → 成本/温度/浓度）、三个维度（参数1、参数2、目标值），或三维解空间。
- **只选能支持结论的 3D 图，不为凑数硬画**——数据不适合二维/三维就退回最匹配的图种。
- **视角**：`ax.view_init(elev=25, azim=45)` 选一个信息不遮挡的角度；可多角度输出同一结果（"多角度展示"）。
- **配色**：曲面用 `cmap="viridis"` 并加 `colorbar`；散点用第三维映射颜色；黑白打印需仍可辨（加网格线）。
- **可读**：坐标轴标签、刻度、colorbar 标签字体与 2D 图同规格，不得过小。
- **数量控制**：宁缺毋滥，每张必须对应一个明确结论。

### 多帧仿真展示规范

仿真/迭代/时间演化类问题，用"不同帧"展示演化过程：

- **帧选取**：选有代表性的时间步（初始、中间转折、收敛/终态等 3~6 帧），不要逐帧全放。
- **2D 为主、3D 按需**：二维俯视帧必给（如位置分布随时间）；三维叠加视角仅当数据适合时采用。
- **统一坐标系**：所有帧共用同一坐标范围与配色，便于跨帧对比；每帧在图内标注时间步/迭代次数。
- **组合排版**：可用子图（`subplots`）把多帧并排，图题写"不同时刻的 XXX 演化"。

### 反模式（避免）

- 一个图塞 5 条以上曲线且无图例。
- 饼图类别 >7 且无标注百分比。
- 若采用 3D 图，视角遮挡数据、无 colorbar。
- 全篇只有柱状图 + 折线图（种类单一）。
- 图无单位、无标题、坐标轴含义不明、字号过小不可读。
- 颜色仅靠红绿区分（色弱/黑白打印失效）。

## 四、论文级数据图样式规范（Step 2 用这个保证"画得专业"）

### 全局配置

```python
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt

plt.rcParams.update({
    "font.family": "SimSun",
    "font.sans-serif": ["SimSun", "Times New Roman"],
    "mathtext.fontset": "stix",
    "axes.unicode_minus": False,
    "text.color": "black",
    "axes.labelcolor": "black",
    "axes.titlecolor": "black",
    "xtick.color": "black",
    "ytick.color": "black",
    "figure.facecolor": "white",
    "axes.facecolor": "white",
    "savefig.facecolor": "white",
    "pdf.fonttype": 42,
    "figure.dpi": 150,
    "savefig.dpi": 300,
    "savefig.bbox": "tight",
})
```

字体分工：中文正文/图内文字宋体（`SimSun`），中文标题黑体（`SimHei`），英文、数字、拉丁字母 Times New Roman，数学字体 STIX。

> **关于硬数字**：下列 `figsize`、字号、DPI、间距是**默认起点**，最终以"插入 A4 页面后回读可读、不重叠"为准——不是机械铁律；若版心宽度不同导致图过大/过小，优先调整 `figsize` 与字号，而非强行保留默认值。

### 配色（高对比、白底、黑字）

| 用途 | 色值 |
|---|---|
| 蓝色 | `#0066CC` |
| 青绿色 | `#008F78` |
| 橙色 | `#E68A00` |
| 红色 | `#D83A58` |
| 深灰色 | `#657487` |
| 网格线 | `#D7E1EA` |

重要类别**同时用颜色、线型和点形区分**；网格只保留有助于读数的方向；禁止深色底、渐变、阴影卡片、灰暗低对比配色和装饰纹理。

**配色语义化**（编码变量，而非美观）：连续变量 → 连续色带（`viridis`/`magma` 或线性/对数映射的单一色带），不把离散类别色硬套连续值；分类变量 → 有限且稳定的类别色（每类一个稳定色、跨图一致，不换色）；风险/阈值/异常 → 强调色（单个高对比低饱和色如红/橙，只在真正需警示处用）。任何颜色都同时用线型/点形/填充冗余编码，保证黑白与色弱仍可辨；颜色必须承载语义，禁止纯装饰性配色。

### 画布与字号

- 核心统计图优先 2×2 多面板，四个子图围绕同一问题；推荐 `figsize=(7.80, 4.39)`（接近 16:9）；子图标记统一 `(a)(b)(c)(d)`。
- 轴名和刻度 7.5~9 pt，图例 6.5~8 pt，子图标记 10~11 pt。
- 最终判断以插入 A4 页面后的可读性为准。

### 图形选择（模型/审核类）

| 数据关系 | 图种 |
|---|---|
| 模型排序 | ROC、AUC 区间或置换结果 |
| 审核效果 | 容量捕获曲线、Lift 曲线 |
| 参数不确定性 | 点区间图 |
| 分组比例 | 带 Wilson 区间的柱形图/点图 |
| 小样本分布 | ECDF |
| 字段闭合 | 点图、哑铃图或误差对比图 |
| 建模流程 | 对齐方框 + 正交箭头（流程图归 `mm-graphics`） |

### 3D 图（可选）

仅当数据适合三维展示时采用：`view_init(elev, azim)` 选不遮挡视角，`cmap` 用色弱友好色带，加 `colorbar`，黑白打印可辨识（详见 §三"3D 立体图规范"）。

### 文字重叠防复发（常见布局陷阱）

数据图交付前必须通过 `python <mm-figures目录>/scripts/check_figure_overlap.py` 的文字-文字重叠扫描（重叠数 = 0），并逐项检查以下**高发场景**：

1. **2×2 多面板行距**：底部面板标题不得与上排面板的刻度、x 轴标签重叠。实现：`fig.subplots_adjust(hspace=0.55, wspace=0.25)`（或更大）；上排 xlabel 与下排标题之间必须肉眼可见空隙。刻度标签很多（如 15 个 y 刻度）或旋转 45°/90° 时，会向下/向外溢出，需缩小刻度字号或加大 hspace，不能用默认行距赌运气。
2. **面板标记**：2×2 面板必须标 `(a)(b)(c)(d)`（`ax.text(-0.10, 1.06, tag, transform=ax.transAxes, ...)`），标记不得与标题/刻度重叠。
3. **图例**：优先放数据稀疏区；放在图顶部时不得压面板标题，否则移到图下方（`fig.legend(..., bbox_to_anchor=(0.5, -0.05))` 并给底部留白 `fig.subplots_adjust(bottom=...)`）。
4. **热力图**：矩阵 ≥10×10 时，数值标注只放内圈单元格（跳过最外圈行/列）或缩小字号并加大画布；colorbar 避免与右缘/底缘标注及旋转刻度相交（必要时改底部横向 `orientation="horizontal"` 并加大 `pad`）；`ax.tick_params(pad=6)` 分隔刻度与图形。
5. **3D 图**：限制刻度数量（如 `set_xticks([0,1,2,3,4])`），轴标签 `labelpad≥10`，扫描确认刻度标签与轴标签不重叠。
6. **堆叠柱小标签**：小计数段（v<2）不标注或加大偏移（`y+v+1.0` 以上），避免相邻数值标签重叠；计数标签字号 6pt 左右。
7. **旋转刻度**：`rotation=45/90` 会显著扩展标签占位，必须为 xlabel、相邻面板、colorbar 预留空间。

上述任一场景存在重叠，必须返工后重扫，禁止带病进入 `docs/04` 与论文。

### 导出

每张终稿图同时导出 PDF、SVG 和 PNG：PDF 用于 LaTeX，SVG 用于编辑，PNG 用于检查与支撑材料。PNG 不低于 300 DPI，多面板图推荐 420 DPI。

## 五、设计原则（出色，不只是合格）

数据图不只是把结果画出来，更要让评委**不靠解释就能沿图的结构读出建模逻辑**。以下四点在本 skill 出图全程适用，与 §三、§四配合执行：

1. **中文无乱码/方框**：所有中文（轴标签、图例、标题、数据标签、注释）必须正常显示，不得出现缺字方框、乱码或替换字符。用 `SimSun`/`SimHei` 或等价中文字体，设置 `axes.unicode_minus=False`，出图后回读确认；字体缺失导致的方框一律返工，**禁止用拼音或英文替身顶替中文标签**。
2. **高级感＝结构可读**：图的视觉结构本身要能读出版（数据→模型→结果）的建模逻辑。做法：用多面板/子图梳理论证链，每个面板承担一个明确环节并用 `(a)(b)(c)(d)` 对齐；统一视觉动线（从上到下/从左到右）；同一指标跨图用同一视口、配色与线型；图内含关键结果标注（数值、单位、结论性注释），一眼能定位"结论在哪、依据是什么"。高级感来自**取舍后的结构与节奏**，不是信息堆得越多越好。
3. **配色语义化**：配色编码变量而非美观（连续→连续色带、分类→稳定类别色、风险/阈值→强调色；任何颜色同时用线型/点形/填充冗余编码），详见 §四"配色语义化"。
4. **场景创新型**：让评委看到模型在解决**真实问题**，而不仅是统计图。医学、交通、能源、生态等题尤其要体现"场景—模型—决策"的关联。数据图可内嵌小的**机制示意/场景标注**（对象、空间时间结构、真实站点/人群/资源），把关键结果落在真实对象上。若一张图的主体是纯机制/场景、而非数据结果，则**转交 `mm-graphics`**；数据图内嵌的机制/场景只作辅助，不能喧宾夺主。

## 六、硬性要求（不可违背的底线）

本节是必须满足的下限，与 §三、§四、§五配合；冲突时以本节为准。

1. **3D 图可选**：仅当数据确实适合三维展示（两个自变量 → 一个因变量、三维解空间、需同时表达三维信息）时才用；不适合时不要为凑数硬画。
2. **选图以"最能反映数据 + 让评委眼前一亮"为标准**：优先与数据特征最匹配、表达力最强的图种（一图一结论）；在常规图上做精细化与组合创新，但不为炫技牺牲可读性与准确性。
3. **多帧仿真展示**：只有时间演化、空间演化或迭代问题才要求多帧；每个适用子问题展示初始、关键中间与终止状态，二维视角必给，三维仅在数据适合时采用。
4. **字体可读**：所有文字在论文版面中必须清晰可读；字号与字体分工见 §四。
5. **样式红线**：白底黑字、高对比配色；重要类别同时用颜色、线型或点形冗余编码；每张终稿图导出 PDF + SVG + PNG，PNG ≥300 DPI，多面板推荐 420 DPI。
6. **文字重叠零容忍**：数据标签、节点编号、图例和关键标注不得压住图形元素或其他文字。导出后运行 `<mm-figures目录>/scripts/check_figure_overlap.py` 并视觉回读，发现重合即返工。
7. **命名规范**：图文件名与图内标题不得带"问题一/二/三、Q1/Q2、q1/q2"等编号前缀，使用描述性内容名称；论文图题同步遵守。
8. **数据图用途**：数据图主要用于**展示模型求解的结果**，或对结果的**分析/研究**（检验、灵敏度、鲁棒性、多方案对比、多帧演化）。不是数据结果或结果分析的不算数据图（归 `mm-graphics`）。每张仍须"一图一结论"，禁止为凑数硬画无信息图。**本 skill 不设数据图最低数量**；需撑满正文图量的锚点级要求由 `mm-paper-writing` 统筹。
