# 模型的建立与求解

> 本模块由原 `mm-paper-writing/SKILL.md` 的 第171–215行 迁移而来。它是终稿写作的强制规范；不得只读摘要或以其它模块代替。**本规范决定模型章的"组织骨架"与"公式粒度"，具体呈现可参考 `demo_full.tex`（本题的重构示例）。**
>
> **硬性纪律：本规范按"必须遵守"与"仅供参考"分层。** 属于**必须遵守**（不可违背）的只有两类——① **模型章骨架**（每问独立成章、章内"模型建立/模型求解"二分层、公式"一量一式"、三级小节"一段=动机+公式+作用"）；② **每问闭合论证链**。其余（题型化路径、故事线、模型修复范式、参数不确定性范式、呈现技巧）均为**参考**，用于打开思路，不影响骨架与论证链的硬性要求。

### 模型章骨架（硬性，必须遵守）
本环节是"论证思路与写作原则库，不是可套用的模板"。判题人看的是"思路对不对、论证顺不顺"，不是"小节齐不齐"。**但框架是硬性的：每个子问题独立成章，章内固定"模型建立 / 模型求解"二分层，公式分解到"一量一式"。**

**外层：每问独立成章。**
- **N = 题面子问题数（任意值，常见 2~4）**，每个子问题单独设一级标题；N 不同骨架不变，只是章数随 N 变，序号连续（前四章"问题重述/问题分析/模型假设/符号说明"固定为一~四，问题章从"五"起，后续章节序号随 N 顺延）。
- **问题章标题命名（硬性格式）**：`（该问核心模型/方法名）的构建与求解——问题X`，破折号后置问题号。核心模型名取该问最具代表性的模型或方法（如"期望净收益递归模型的构建与求解——问题二""多级装配递推模型的构建与求解——问题三"），不得只写"问题一的模型建立与求解"这类无对象死板标题，也不得把次要算法堆进标题。
- **模型评价与推广永远是单独一个一级章节**（序号随 N 顺延），不并入任何一问、不因问数变化而消失。
- 章首（问题一前）可用一段"引言/主线"总述各问的递进关系，点明"前问输出→后问输入"。
- 多问共享同一原始数据时，可在问题一章之前设一个条件性的公共数据处理一级小节；部分共享用"公共处理 + 问题专属处理"，数据彼此独立则分别写入对应问题。

**内层：章内固定"模型建立 / 模型求解"二分层。**
- `模型建立`（二级标题）：只讲"为什么这么建模、公式怎么来"。按模型成分拆成若干三级小节，一个模型成分（一个子模型、一个关键参数）一个三编号小节。
- `模型求解`（二级标题）：只讲"怎么算 + 算什么"。三级小节按"求解算法 → 结果（表/图）→ 解读 / 灵敏度"组织。
- 每个三级小节内部遵循"**一段 = 一个动机 + 一个公式 + 一句作用**"：先给"为什么需要它"，再放公式，最后一句"这个式子的作用 / 怎么检验它"。一事一段，不把一个长段挤进多个模型。
- 不再使用"建模思路—模型建立—模型求解—结果分析—模型检验"这套模板五段；小节数量以本题实际建模成分为准，不要求凑数。

**每问必须闭合的论证链**：题目目标 → 数据与已知条件 → 模型选择依据 → 变量、参数与单位 → 核心数学关系 → 目标与约束（或状态方程）→ 求解算法 → 结果 → 对题目的直接回答 → 证据与适用边界。闭环是硬要求，小节数量和标题名称不是硬要求。

### 公式粒度：一量一式（硬性）
凡一个物理量、一个参数、一个约束，若能被独立推导或独立检验，就**单独编号一个公式**，不要塞进 `cases`/`aligned` 共享式号。**"公式多 = 分解细 = 每个公式都承载一个'从哪来、怎么用'的量"，不是刻意堆砌。**
- 例：`P_g`（合格概率）、`P_b`（不合格概率）不必合并成一个 `cases`；`u_i`（有效成本）、`q_i`（有效次品率）不必合并；`a`（单周期现金流）、`b`（再循环系数）、`Φ`（期望净收益）各成一式。
- 每个式子前给引入理由，后给现实含义与作用，保证"一读即懂这个量是什么、怎么来"。
- 真正需要并列、且必须同时满足的一组判定约束（如情形1/情形2 的功效约束），才用左花括号 `\left\{`/`cases` 共享一个式号（各行左对齐、齐左）。
- 需要分别引用或分别推导的公式才拆分式号；同属一个逻辑、必须并列呈现的少量约束才合并。

### 文字密度：三不写（硬性）
篇幅靠**公式、表、图、小节标题**撑，文字只负责"动机 + 作用"的串联——获奖论文的文字密度约为每页 400～500 字，文字多恰恰是公式/图表不足的遮羞布。
1. **中间推导量不写文字叙述**：凡能用编号公式表达的量（传递关系、中间参数、判定条件），一律用公式，不用文字描述"谁乘谁、怎么算"。
2. **表内数值不在正文复述**：数值结果一律落表/图，正文只写 2～3 句解读（数值→机理→决策含义），不得把表中数字逐个念一遍。
3. **建议/启示类内容不写**：各问正文不得出现"对生产管理的启示""对实际生产的指导""对企业的应用建议"类段落——此类内容全文**只写一处**，统一收口在"模型评价与推广"章（见该章"建议收口"条款）。这类段落与评价章重复，是初稿文字超密的最大来源。
写作自检：任一正文段落，若删去后论证链、数值答案、机理归因均无损失，删。

### 题型化组织参考（只示范逻辑，不是模板）
- **公式六层**：数据处理 / 变量定义 / 主模型 / 目标损失 / 约束 / 检验评价——需要哪些定义哪些；公式必须承担至少一种作用否则不写。
- **分题型论证路径（示例，非唯一）**：优化题（拆问题→定义决策变量→构造指标/参数→目标函数→逐条约束→汇总模型→按性质选算法→求解→结果解释）；数据/统计/分类题（识别数据结构→数据有效性筛选→适配变换→模型适用条件检查→按类型选模型→训练/测试分离与评价→异构交叉验证→敏感性）；物理机理题（过程分阶段→受力/几何分析→基本定律→状态方程+初始条件→小参数近似线性化→求解→发现模型出问题→修假设→策略输出）；概率/序贯决策题（现实随机机制→随机变量/分布→期望成本收益→优化目标→枚举或 DP→参数不确定性→灵敏度）。判断标准：路径是否顺应题目的递进逻辑，而不是"有没有按某个模板写"。
- **模型修复范式**：`模型结论不符合实际/无解 → 检查关键假设（不是急着换模型）→ 放宽/修正假设 → 建立改进模型（最小幅度修改，只动受影响部分）`。
- **参数不确定性范式**：`确定性模型（参数为常数） → 参数视为随机变量（分布来自题面区间/共轭先验） → 情景/后验抽样 → 对目标求期望 → 重新优化 → 与确定性结果对比 → 主观参数灵敏度`。写论文时显式写"在问题一模型基础上，将确定参数升级为随机变量"。

### 模型建立完整性
关键变量与参数说明类型、下标、单位、取值范围和来源；每个公式按"引入理由 → 数学表达 → 各项现实含义 → 在模型中的作用"呈现；每条约束说明对应的资源、容量、预算、时间、守恒、逻辑或边界条件。优化模型求解前集中汇总决策变量、目标函数、全部约束和变量范围，不得让目标与约束分散多页后直接调用算法。

### 写作内在逻辑（通用铁律）
1. **模型链思想**：前一个模型输出 → 后一个模型输入/依据，显式写出传递量、单位、时间/空间尺度和必要转换，并让它真实进入后问的变量、参数、目标、约束、初值或数据输入；只写"基于问题一"而后问仍独立重算，不算模型联动。
2. **公式前必有理由**：先回答"为什么需要它"，再放公式（五种引公式方式：从数据结构/问题特征引、从机理/业务引具体项、从模型适用性引、从业务指标反推数学定义、从优化目标引目标与约束）。
3. **模型与算法分开**：模型回答"什么方案最好"，算法回答"怎样找到"。
4. **求解写法分级**：成熟求解器简洁但完整地说明模型性质、算法或求解器、软件及版本、关键参数、容差/终止条件、求解状态与输出；常规算法用连续段落或普通编号写清输入、核心步骤和输出；智能优化或复杂自研算法必须说明编码、初始化、目标/适应度、更新规则、参数来源、最大迭代、终止条件、随机种子、独立运行与收敛证据，不贴真实代码替代解释。
5. **求解 ≠ 结束**：求解后必须解释结果并提供与模型类型匹配的证据。使用前的量纲、极限、退化、守恒和可行性检查放在模型建立位置；使用后的误差、交叉验证、对比和稳定性证据紧跟对应结果。各问类型不同则分别放置，多个同类模型确需统一比较时才设置共享检验小节。
6. **选择性敏感度**：只扰动重要、不确定或可能改变结论的参数，说明选择原因、基准值、现实范围、步长和关注指标；不得把所有参数机械统一上下浮动固定比例。含人为设定权重、阈值或先验时，必须检查结论是否翻转并报告稳定区间。
7. **不剧透（各问内部，硬性）**：每问结论（最优方案、数值结果、是否稳定/翻转、灵敏度方向）只在该问的**求解小节**出现；该问章首"难点+分层"导语与模型建立节只陈述"要解决什么问题、为什么这么建模"，**不得提前写出结果或模型优势**。
   - **模型选择对比**（为什么选此模型而非其它）收敛到"因此我们采用……"来引出建模，**不说"因此它必定最好/能保证最优/闭式精确"**——模型优劣要等求解与验证结果出来后才有依据；讲"不选的方案有缺陷"（如忽略递归会低估收益）是合理的取舍理由，不算剧透，但不以此断言所选模型必然最优。
   - **引表/图句**：先交代"下表/图用于说明……"再让读者看结论；**不得先写结论再补"见表 X"**（如"情形 2 翻转，见表 4"应改成"表 4 给出各情形在区间下的最优决策，用于判断是否翻转"）。
   - **模型建立节**：只讲"因变量/参数/目标如何引入"，不下"该模型保证了……"的结论式断言，模型效力留给求解与验证小节。&#8203;

### 叙事与故事线（内在逻辑，不是文风）
模型构建不是数学对象清单罗列，而是有前因后果的情节链。按题组织：`开场`（解决什么问题）→ `规矩`（现实规则逐条摆出）→ `主角`（决定什么 → 决策变量）→ `铺垫`（参数从哪来）→ `冲突`（难点/特殊处理 → 本题化改造）→ `成形`（目标+约束汇总）。写作要领：每个数学对象出现都有"前因"；用因果连接词串逻辑；约束按故事顺序讲、不按数学类型罗列；收尾要"成形"（"由此得到如下模型"）。**标题一律学术式**（如"符号与参数确定 / 目标函数的构造 / 约束条件的建立 / 模型汇总 / 模型求解 / 求解结果与分析"），禁止用"主角""规矩""冲突"等口语化标题。**这句话是关键：标题像论文、段落像讲故事。**
> 与"每小节一段一事"并行不悖：故事线是全文的内在因果，`一段=动机+公式+作用`是每小节的微观呈现。两者结合既保证逻辑贯通，又保证每一段清爽、一事一段。

### 呈现规范与求解呈现
- **呈现规范**：目标函数、约束条件按「1) 决策变量 2) 目标函数 3) 约束条件」顺序组织；公式全文连续编号、正文引用"由式(3)可得"。**同一公式表达中若确实需要并列多个等式/约束（如情形1/情形2 的判定、链式 `a=b=c`、`\qquad` 并列的约束组），用左花括号逐行排版、每行一个等式并共享一个式号；但能独立成式、独立检验的物理量（`P_g`、`P_b`、`u_i`、`q_i`、`a`、`b`）一律各成一式，不合并。**
- **求解呈现**：写清算法名称+工具+关键参数（如"模拟退火（初温 100、衰减 0.95、迭代 30000 次）"）；工具写清哪个解决哪步；复杂自研算法在正文编号与算法流程图之间选信息增益更高的表达；涉及随机算法时给出收敛性/稳定性说明。

### 易错点（自查清单）
只建模不求解（公式堆砌无数值）；求解过程黑箱（"用软件求解得…"要写算法与参数）；结果（图/表）无解读段；模型间无衔接、每问从零开始；参数表出现"/"或空缺；模型类型表述摇摆；公式前无理由直接罗列数学对象（叙事断裂、退回清单）；**把本可独立成式的物理量硬塞进 `cases` 共享式号（违背"一量一式"）**；**约束下标不完整**（如"每机至多 3 弹"应写 `∑_k ∑_m a_{jk,m} ≤ 3 ∀j`，不得对单一下标求和造成歧义）；**约束中数值常数来源不明**（如 t_d 上界"−16"、τ 下限"0.5"，须说明是物理/时间窗/防退化/减子域，不得凭空出现）；**扫描子域 ≠ 约束域时不说明**；**同一结果多处口径不一致**（摘要/正文/表/灵敏度基准/鲁棒性基线的同一数值须一致或标注差异）。

### 结果呈现与分析

**结果一致性与口径（硬性，写后逐处核对）**
- **数值一致**：同一物理量、同一模型、同一解在**摘要 / 正文 / 表格 / 灵敏度基准 / 鲁棒性基线**中出现时，数值必须一致。若确需在另一处用不同口径，须**显式说明差异**，不得无声换值。
- **口径显式化**：凡结果有两种以上算法口径，必须在结果呈现处**显式写死口径**，并保证结果文件列含义与正文口径一致。
- **基准对比量化**：凡声称"相比方案 A 提升 X 倍/Δ"或"优于基准"，必须给出对比基准的**具体数值与出处**，最好落一张对比表。

结果不能只报数 + 一句"方向合理"。**结果描述三段式（每问每个关键结果必须）**：`数值 → 机理 → 决策含义`——数值（带单位、精度 2~3 位小数、口径说明）；机理（为什么是这个数，对应哪条机制/策略）；决策含义（翻译回题目/决策者语言）。至少"机理"与"决策含义"缺一不可。
- **灵敏度结果必须解释"为什么敏感/不敏感"**：每个参数扫描给出敏感性排序、机理归因、方向解释、临界/边界观察。
- **大表必须给读表指南**：超过 6 行的结果表，表后解读指明先看哪一行/哪一列、行与行之间差异模式。
- **鲁棒性分析必须展开**：解释波动为什么小、指出最坏情形、通过标准选取依据。
- **结果与机理/策略/图表联动**：灵敏度数字回链策略结构；每个图后 2~4 句解读。

### 骨架一览（硬性，必须遵守）
框架固定，内容按本题实际建模成分定：
```
1  （该问核心模型名）的构建与求解——问题一
   1.1  模型建立
     1.1.1  模型成分A  （动机 → 公式 → 作用）
     1.1.2  模型成分B
     1.1.3  模型成分C
   1.2  模型求解
     1.2.1  求解算法
     1.2.2  求解结果（表/图）
     1.2.3  解读 / 灵敏度
2  （该问核心模型名）的构建与求解——问题二
   （同 1 结构，核心模型名按该问最具代表性的模型/方法定）
```
示例（核心模型名的取法）："期望净收益递归模型的构建与求解——问题二""多级装配递推模型的构建与求解——问题三""二项精确抽样检验模型的构建与求解——问题一"。
子模型小节的数量与命名按本题实际建模成分决定，不要求凑数；每问章首一段"本节难点 + 分层说明"，点明该问要解决什么、按哪些子模型推进。**注意：这里"不凑数"指的是小节内部的具体成分数量按题定，不是骨架本身可放松——"每问成章 + 模型建立/模型求解二分层 + 公式一量一式 + 三级小节一段一事"这四点是硬性的，必须遵守。**
