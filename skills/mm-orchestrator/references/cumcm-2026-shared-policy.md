# CUMCM 2026 共享执行规则

本文件是整套 `mm-*` 数学建模 skills 的跨阶段唯一权威规则源。各阶段只保留本阶段的操作细节；发生重复或冲突时，以本文件为准。

## 固定适用范围

- 整套流水线只服务全国大学生数学建模竞赛（CUMCM）。
- 格式规范固定采用内置 CUMCM 2026 规范，不自动切换年份，也不宣称兼容 MCM/ICM、华为杯、MathorCup 等其他竞赛。
- 默认交付 LaTeX 源文件与 XeLaTeX 编译 PDF。
- 赛题分析必须先完成来源核验：未经可靠文本层、视觉复核或双向追溯确认的 OCR、自动转录和模型推测，不得作为后续分析、建模、编码、绘图或论文写作的事实依据。
- 赛题分析还必须完成逐子问题语义核对：动作、对象、输入、输出、范围、限制、排除项和依赖关系均须回到题面位置；存在未解决的语义分歧时，不得进入模型候选筛选。

## 内容与数量基线

- 本工作流中，正文指摘要之后、附录之前的全部内容，包含正文顺序章节、必设的 AI 工具使用声明和参考文献；摘要与附录不属于正文。完整论文的正文篇幅为 27--30 页，若当届官方文件有更严格或不同的明确要求，以官方文件为准，并在项目 manifest 的覆盖记录中说明。达到篇幅下限时，可补充题目相关的推导、求解细节、验证证据、结果解释及适用图表；图表可以是数据图、结构/机制图、复杂算法流程图或题目场景示意图，但每张都必须服务明确论点并有正文引出和解读。不得以重复文字、无信息图表或排版注水凑页。正文各章节连续自然排版，不因某一章节另起一页；仅摘要独占一页，附录可在前文结束后另起页。
- 全文至少 8 张图、5 张表。每个子问题至少提供 1 个有信息量的图和 1 个有信息量的表；图可以是数据图、模型结构图、机制图或场景图，表可以是参数表、约束表、结果表或方案对比表。没有数据依据时，不强制制作数据图。
- 每篇完整论文必须至少有 1 张由 `mm-visual-concept` 产出的纯视觉示意图。
- 数量门槛不得通过重复图、无信息拆图、空表、重复论述或排版注水满足。需要补充论证时，优先补充公式推导、适用条件、实际求解细节、验证证据和结果解释；算法说明必须绑定真实变量、公式、参数代入和结果产出，不得写空泛步骤。

## 论文固定版式

- 未提供官方模板且用户未另行指定时，主标题固定为三号黑体（`\zihao{3}\bfseries`），摘要标题固定为三号黑体（`\zihao{3}\bfseries`）；不得自行放大标题填充页面。
- 附录前统一采用：一级标题小三号黑体、居中；二级标题四号黑体；三级标题与正文小四号；图题、表题小四号；表内文字五号。正文使用单倍行距、两字符首行缩进，相邻正文段落额外间隔约四分之一行。
- 表格的表头、文字与数字默认水平居中；长文本使用居中的定宽列自动换行。每个二级标题前清空本小节待排浮动体，图表不得跨入下一小节。单页表格使用浮动环境；确实无法单页容纳的长表允许跨物理页面，但必须在同一小节内完整结束。
- 跨页长表使用 `longtable`：首页正常表题；每个续页顶部标“续表 N　原表题”并重复完整表头与单位；非末页底部标“续下页”；只在末页使用最终底线。续页沿用原表编号，不新增标签、不重复进入表目录，也不得出现漏行、重行或下一小节标题插入表内。
- 数据审计表、符号表和核心结果汇总表必须紧跟首次引出文字，并优先排在同节大型图片之前；若多个浮动体竞争导致关键表脱离引出段或形成孤立浮动页，仅对该关键表使用 `[H]` 锁位。
- 改动位于图表之前的正文后，必须双遍编译并连续复查至首张后续关键表，防止文字增减引发孤立图页、大块无效留白、图文倒序或关键表漂移。若图片尺寸不宜改变，允许补充缺失的实质内容或删减重复、错位内容来平衡分页；不得为排版编造内容、重复注水、删除必要论证，或全局缩小字号、行距和页边距。
- 摘要正文采用小四号与两字符首行缩进；字数允许 550--1100 个汉字，优先写到 750--950 个汉字，以实质方法、数字、转折与边界补足篇幅。
- “写满一页”必须同时满足：摘要不跨页，关键词行位于可打印版心纵向 78%--90% 区间。不得用 `\vfill`、弹性空白、缩小页边距或无信息句子制造占用率。
- `mm-paper-writing` 编译后必须运行摘要页审计脚本；`mm-verification` 必须复跑并记录字号、汉字数和版心占用率。任一硬门槛失败都回写论文阶段，不得仅凭“单页”或“字数合规”判定通过。

## 模型与验证原则

- **评卷导向**：围绕每个具体子问题的对象、任务动词、数据、约束和交付形式开展分析、建模、求解与写作。每个核心方法、公式、图表和结论都必须能说明其解决的具体困难及其服务的 `P-##`/`REQ-###`；不能说明的内容不得因“常见”“高级”或“增加篇幅”而加入。
- **针对性创新**：鼓励从题目机制、数据形态、约束冲突或决策要求出发，提出必要的变量构造、约束设计、模型改造、方法组合或验证设计。创新不等于采用生僻算法、堆叠模块或增加复杂度；成熟方法在本题中经充分论证、恰当改造并得到真实有效结果，同样符合要求。若采用通用方法，必须写明其在本题中的适用条件、针对性处理和相对备选方案的取舍。
- **反堆砌与真实性**：不罗列与题目无关的方法、通用模型或算法，不把简单拷贝包装成创新；不编造数据、参数、文献、实验、结果、比较或适用范围。计算结果必须可由代码、输入与记录复现；不确定性、失败结果和适用边界如实保留。
- **反套路化**：不得用固定章节、相同小标题、无信息图表、空泛流程、重复结论或形式性验证代替实质论证。各问的组织和证据应随题目需要变化；没有对应问题、证据或结论落点的内容删除，不为页数、图表数或形式完整性填充。
- **复杂算法深度**：当题目确实需要组合优化、动态/随机过程、网络、博弈、多目标、迭代仿真或其他非平凡算法时，必须保留并深入解释其必要机制。至少说明状态/决策变量、目标与约束、关键更新或转移、初始化、终止/收敛条件、复杂度或规模随输入增长的关系、关键参数影响、退化/失败情形和验证证据；不能只报算法名称、贴伪代码或给出一张流程图。复杂算法的深入分析应服务题面要求，不能成为脱离题目的独立展示。
- **可直接阅卷的最终答案**：每个题面要求和可识别评分点都必须有明确的最终答案落点。最终答案可以是数值、排序、方案、配置、判定、预测、解释或有条件的建议，但必须在论文正文/结论中可直接定位，并由结果、图表、公式或代码复现证据支撑。只有模型、算法、过程、性能指标或“得到结果”而没有回答题面任务动词的，不算覆盖该评分点。验收必须建立“评分点 → 预期答案类型 → 论文位置 → 最终答案原文/数值 → 支撑证据”的矩阵；不能以章节存在、方法存在或页数达标替代答案覆盖。
- **目标函数合理性**：目标函数必须由题面任务动词、现实决策目标或可核验的物理/统计量推出，并与决策变量、约束和最终答案一致。每一项须说明含义、方向（最大化/最小化）、单位或无量纲化方式、权重/惩罚系数来源及适用边界；多目标组合必须先处理量纲并给出权重或 ε 的依据与敏感性。不得虚构权重、用容易优化的代理目标替代题面目标、把硬约束错误塞进目标函数，或以单一性能指标掩盖真实成本、风险、公平性、资源和可行性要求。
- 模型复杂度必须与题目难点匹配。每问填写复杂度审计，但不设统一的 3/4 达标线，也不强制大状态空间、组合、随机或博弈模型。
- 灵敏度、鲁棒性、模型对比和统计检验均按题目需要决定，不设每问或全文最低数量；凡声称稳定、优越、可靠，必须给出对应证据。
- 预测、分类、风险排序和审核决策的专项规则仅在对应题型触发，其他题型标记为 N/A。
- 只有涉及时间演化、空间演化或迭代过程的子问题才要求真实仿真；适用时至少保存初始、关键中间和终止状态。

## 流程图与视觉图边界

- `mm-diagrams` 默认只画技术路线、总体框架、数据处理、模型结构、指标体系、变量关系和验证闭环。
- 成熟求解器、常规算法和一般求解步骤不画流程图，使用正文说明。
- 只有包含实质分支、循环、状态更新或终止机制的复杂自研算法，才允许绘制算法流程图。
- 纯视觉示意图不限制色彩与具体视觉风格，以事实准确、视觉效果和论文协调性为准；不得套用流程图的黑白灰限制。

## 图件交付格式

- 数据图：PDF + SVG + PNG；PNG 不低于 300 DPI，多面板图按图表规范执行。
- 流程与框架图：默认 TikZ `.tex` + 矢量 PDF + 带物理尺寸元数据的 600 DPI PNG；明确需要网页兼容或 SVG 时再附 SVG。
- 纯视觉示意图：高分辨率 PNG；采用矢量或混合路线时另交 SVG。
- 论文可见的图文件名与图题不得以“问题一”“Q1”“q1”等问题编号命名；内部代码与结果文件允许 `problem1.py`、`q1_result.csv` 等追踪编号。

图件分支按适用性执行：`mm-figures` 在存在能支持结论的数据图时执行；`mm-diagrams` 在存在技术路线、模型结构、指标关系或复杂反馈时执行，否则将阶段标记为 `n_a`；完整论文至少执行一次 `mm-visual-concept`，非完整任务可标记为 `n_a`。三个图件分支在论文结构草稿完成后彼此独立，可并行运行。

图件 skill 只生成图件及其报告，不修改 `paper/论文.tex`。图件报告必须提供精确正文锚点，由 `mm-paper-writing` 统一插入和编译。

## 两遍式论文与图件流程

1. 论文阶段先生成结构草稿和插图需求清单，不撰写终稿。
2. 数据图、流程图和纯视觉示意图按清单制作并登记。
3. 论文阶段读取最终图件，完成正文与排版终稿。
4. 终稿写作中若发现新增图件需求，回写对应画图 skill，记录原因与版本后再继续。

## 验收与修复

- 写作前门禁固定为 G-1--G-5；数字一致性、编译和格式属于终稿验收，不扩充为写作前门禁。
- 验收默认从原始数据完整重跑主程序；计算成本过高时，可记录原因并抽查核心程序、独立复核程序与关键结果。
- `mm-verification` 只审计、定位并指定回写阶段，不直接修改上游产物；由 `mm-orchestrator` 调用对应 skill 修复后再次验收。
- 阶段状态使用 `pending`、`in_progress`、`complete`、`failed`、`n_a`；只有 `verification` 允许额外使用 `conditional`。`conditional` 仅适用于非关键缺陷，数据真实性、核心结果不可复现、关键数字不一致、编译失败和硬性格式违规必须为 `failed`。
- 验收发现的问题必须写入 manifest 的返工队列。阻断性返工关闭前不能通过验收；修复后按影响范围重验目标阶段及其下游阶段，并更新产物哈希。稳定 ID 不复用，旧记录标记为 `rejected`、`superseded` 或 `invalidated`。
- 部分任务也执行范围化验收：只检查本次计划内的阶段，`n_a` 阶段不要求产物；不得据此声称完整论文流程完成。
- 每个阶段完成前必须通过 `project-manifest.schema.json` 校验；校验失败时不得标记为 `complete` 或 `conditional`。
- LaTeX 单页图表默认使用 `[htbp]`，一级和二级标题边界均用 `\FloatBarrier`；只有必须紧跟解释的关键图表才用 `[H]`。跨页长表是非浮动 `longtable`，按续表规则处理，不使用 `[H]` 或外层 `table`。

## 支撑材料

支撑材料只包含：全部可运行源码、必要中间结果、较大篇幅图表、依赖与中文运行说明、一键运行入口、SHA256 清单和《AI 工具使用详情.pdf》。不得包含论文 PDF/TeX、`docs/` 阶段报告、赛题原始附件、内部流程文件或临时备份文件。
