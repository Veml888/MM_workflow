# 数学建模：交付验收

本 skill 是数模流程第 7 阶段（最后）。目标：对照验收清单审计全部产物，找出缺漏与矛盾，输出验收报告。**任何未通过项都回写对应阶段修正，不在验收阶段自行补写。**

**职责与权威边界**：跨阶段不变量遵循 `../mm-orchestrator/references/cumcm-shared-policy.md`；交接字段遵循 `../mm-orchestrator/references/project-manifest-contract.md`。各类产物的**合格标准以对应 owner skill 为唯一权威**——本文件不重述排版/格式细则，只规定"复跑哪个脚本、核对哪类证据"；两处冲突时以 owner 文件为准。

**验收的核心不是确认"章节和方法都存在"，而是确认阅卷人能否对每个题面要求直接判分。** 必须逐条审计评分点的最终答案覆盖；缺少可直接判分的答案，即使模型、代码和章节齐全，也不得通过。

## 输入与产出

- 输入：`plan.md`、`project-manifest.json`、`docs/01~05`、`code/`、`results/`、`figures/`、论文策划与预算（`paper/structure-plan.md`、`page-budget.json`、`draft-audit.md`、`draft-metrics.json`）、`paper/论文.tex|pdf`、`page-audit.json`、`content-gap-report.md`（仅检查本次计划内、非 `n_a` 阶段）。
- 产出：`docs/06-verification-report.md`（必须）、支撑材料 ZIP/RAR（本 skill 是其 owner，见清单 8）。

## 机检复跑（硬性纪律）

**本阶段不得信任前序阶段的手写 PASS。** 凡可机检项必须在此阶段重新运行对应脚本，以其 exit 0 为准，不得沿用或转述前序声明：

| 审计对象 | 脚本（路径相对对应 skill 目录） |
|---|---|
| 可复现性 | `mm-coding`/`scripts/check_reproducibility.py` |
| 图件重叠 | `mm-figures`/`scripts/check_figure_overlap.py` |
| 表格/表题/符号说明/模型章/检验章结构 | `mm-paper-writing`/`scripts/audit_paper_tables.py` |
| 摘要页 | `mm-paper-writing`/`scripts/audit_abstract_page.py` |
| 语言门禁 | `mm-paper-writing`/`scripts/audit_submission_language.py` |
| 正文页数 | `mm-paper-writing`/`scripts/check_paper_length.py`（输出 `paper/page-audit-verification.json`） |
| 图表引用/编号/文献 | `mm-paper-writing`/`scripts/check_paper_refs.py`、`check_paper_cites.py` |
| 版面/留白/孤立图 | `mm-paper-writing`/`scripts/check_layout.py`、`check_line_spacing.py`、`check_noindent.py`、`check_quotes.py`、`check_abstract_symbols.py` |
| 论文编译 | `xelatex -interaction=nonstopmode -halt-on-error paper/论文.tex`（≥2 遍） |
| manifest | `mm-orchestrator`/`scripts/validate_manifest.py`；`validate_paper_plan.py paper/page-budget.json --root .` |

脚本 FAIL 的处置：按高严重度回写 `mm-paper-writing` 或对应阶段；修复后重新编译、重跑并更新 manifest 哈希。**数据真实性、核心结果不可复现、关键数字不一致、编译失败和硬性格式违规不得降级**；非关键说明缺陷可标 `conditional` 并创建返工项。正文页数不足若未在 paper 阶段拦截，同时记录为"paper 完成门禁失效"，不能只写普通篇幅返工。

## 验收流程

1. **完整读取本清单**，按下列 8+2 类逐项核对，每项标 PASS / FAIL / N/A；缺失项记录"缺失"，不现场补造。
2. **先做第 1.5 类（评分点与最终答案覆盖矩阵）**——最高优先级，其余审计都以它为基础。
3. **复跑机检**（上表全部适用脚本）。
4. **写验收报告**（格式见末尾模板）：逐项记录 PASS/FAIL/缺失，FAIL 项写清"回写到哪个阶段、具体问题"；结论分为通过 / 有条件通过（列明待修正项）/ 不通过。
5. **整理支撑材料**（清单 8；文件集合变更走回写闭环）。

- [ ] 故事线：问题→障碍→选择→证据→转折→决策→边界；每节承接上节问题、落下可复算结论；结论最后一句只写应用条件

### 6.5 评卷内容与模型质量审计（高价值，逐问抽查）

- [ ] **评卷内容**：逐问抽查"题面要求 → 针对性模型或改造 → 可复现结果 → 明确回答"链条。回写：与题目无关的方法罗列、通用算法简单拷贝却未说明本题处理、只报性能而未回答题面、凑篇幅的重复/空泛段落、无信息图表、无证据的创新或优越性主张、任何无法追溯到代码/数据/记录的结果。**不得因结构齐全、页数达标或语言流畅掩盖此类缺陷**
- [ ] **模型完整性**：逐问核对模型选择依据、备选取舍、变量/参数类型、单位、范围和来源、公式引入理由、约束现实含义及优化模型集中汇总；删除题目背景后仍可原样套用的通用选型段判为针对性不足
- [ ] **求解可复现**：成熟求解器至少说明模型性质、工具/版本、关键参数、容差/终止、状态和输出；常规算法说明输入、核心步骤和输出；智能优化/复杂算法另核对编码、初始化、目标/适应度、更新、随机种子、独立运行与收敛证据；论文描述与 `docs/03` 和复现清单一致
- [ ] **证据位置**：使用前的量纲、极限、退化、守恒和可行性检查位于模型建立附近；使用后的误差、交叉验证、对比和稳定性证据紧邻对应结果；各问模型不同可分别放置，同类模型可共享检验小节，不强制独立成章
- [ ] **最终答案可判分**：复核 1.5 矩阵每一项，打开论文对应位置，确认答案对题面动词（预测、优化、比较、安排、解释、判定、提出建议）完整回应；读者还需自行从多张表/公式/代码推导答案视为未直接回答，回写增加简洁答案汇总句/表并保留证据引用（高严重度，不得用"章节完整"降级）
- [ ] **复杂算法深度**：使用非平凡算法时，建模报告、代码、结果报告和论文共同说明状态/决策规模、关键更新、终止/收敛、复杂度、参数影响、失败/退化情形和验证证据；题目不需要复杂算法时核对有充分理由，防止为复杂而复杂
- [ ] **求解路线与推导勾稽**：逐问核对 docs/02 求解路线设计表 → 论文求解段——判"无解析解"的问，路线表列有 ≥2 项已排除技术及原因；判"可行"的问，论文呈现逐步推导且与 docs/02 一致；数值结果有可解析特例的标定对照或 N/A 理由；解析—数值双轨题两法结果同表对照
- [ ] **目标函数合理性**：逐个优化/决策子问题核对"题面真实目标→决策变量→目标函数各项→硬约束/软惩罚→最终答案"链条；发现虚构权重、量纲混用、目标与题面不一致、遗漏关键代价或把约束错误当目标，判 FAIL 并回写分析/建模/编程阶段
- [ ] **机理推导链与推断纪律**：机理-经验类模型推导链三层（定律/近似/本题化）在正文可见、每条近似有半定量论据；机理题方程前源项清单与正方向声明在正文可见，带适用域的近似已量化为判据并在结果分析处回核；交付置信区间的已做覆盖率校准或声明名义区间；多重检验已校正或边缘效应已降级；排序结果已做前k名逐对验证。

### 7. 论文格式与交付规则

- [ ] 页边距上下左右 ≥2.5cm（不得为写满摘要而缩小）；PDF 为 A4
- [ ] 摘要页内容不超过一页；**页码从摘要页开始**，页脚中部，阿拉伯数字从 1 起；无页眉（显式 `\pagestyle{plain}`；页眉/正文/附录无身份、学校、赛区信息，全文匿名）
- [ ] 第一页为摘要页（无承诺书/编号页）；电子版文件 ≤20MB
- [ ] LaTeX 编译 ≥2 遍且引用稳定；日志无 LaTeX Error、undefined references；**Overfull 与严重 Underfull 逐条记录并回写修正（不能直接忽略）**；逐页渲染检查图表大小、标签遮挡、孤行、留白和附录
- [ ] 参考文献按 GB/T 7714 规范列出、正文标注引用；中文权威文献占比 ≥60%（按向上取整计，未以无关/低质量/重复资料凑比例）；每个 `\cite` 有对应条目、每条目均被引用、编号按首次引用顺序连续；网页/数据库条目指向具体内容页并含访问日期；条目可核验无编造；AI 工具未列入参考文献
- [ ] 必设的 AI 工具使用声明置于参考文献之前、不编号小节；文案如实说明未使用，或简述实际用途并指向支撑材料《AI 工具使用详情.pdf》
- [ ] `paper_final.status=complete` 时已登记 `draft_mode`、基线 SHA256/页数（无初稿为 null）、`planned_body_pages`、`final_body_pages`、`length_audit`、`content_gap_report`、`compile_passes>=2`；`read_receipt`、`writing_audit`、`review_findings`、`review_audit` 路径齐备

### 8. 支撑材料（本 skill 是 owner）

以论文附录 A"支撑材料文件列表"为锁定清单整理**一个** RAR/ZIP（≤20MB，相对路径）；不得静默改变文件集合——确需增删改名时先创建回写项，由 `mm-paper-writing` 更新附录 A、双遍重编译并更新哈希后再打包。

- [ ] **必须包含**：全部完整可运行源码；必要中间结果；正文未完整展开但用于复核的较大篇幅图表；自主查阅并实际使用的数据资料（注明来源；赛题原始附件除外）；精确依赖锁定；中文运行说明；一键运行入口；全部文件 SHA256 清单；《AI 工具使用详情.pdf》（内容与格式规范见 `references/ai-details-spec.md`：六段结构、A-XX 编号连续、人工核验为可复核动作、匿名、无【待补充】）
- [ ] **不得包含**：论文 PDF/TeX；`docs/` 阶段报告；赛题原始附件；`writing-gates.md`、页面预算、初稿审计等内部流程文件；旧版图、预览图、缓存、临时/备份文件；承诺书、编号页、身份和联系方式；账号、密码或 API 密钥
- [ ] **一致性**：压缩包文件集合与附录 A 逐项一致；附录 B 展示的主要程序与压缩包对应源文件内容一致；《AI 工具使用详情.pdf》与论文声明用途一致且符合 ai-details-spec；SHA256 清单覆盖压缩包内全部普通文件且复算一致
- [ ] **复现性**：按中文运行说明从解压目录执行一键入口，全部必要源码、库、输入和输出关系可查；至少复现论文主要结果，无法全量运行时按高成本抽查规则记录原因和复核范围
- [ ] **变更闭环**：任何文件集合、程序版本、运行说明或 AI 详情变化都更新附录 A、SHA256、manifest artifacts 和 change_log；论文重编译与支撑材料重验完成前不得交付
