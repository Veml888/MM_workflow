# 数学建模：交付验收

本 skill 是数模流程第 7 阶段（最后）。目标：对照清单审计全部产物，找出缺漏与矛盾，输出验收报告。**任何未通过项都应回写对应阶段修正**，而不是在验收阶段自行补写。

## 输入与产出

- 输入：`plan.md`、`project-manifest.json`、`docs/01~05`、`code/`、`results/`、`figures/`、正式论文策划与预算（`paper/structure-plan.md`、`page-budget.json`、`draft-audit.md`、`draft-metrics.json`）、`paper/论文.tex`、`paper/论文.pdf`、`page-audit.json` 与 `content-gap-report.md`（仅检查本次计划内、非 `n_a` 阶段）。
- 产出：`docs/06-verification-report.md`（必须）、支撑材料 ZIP（按需，见 Step 9）。

验收的核心不是确认“章节和方法都存在”，而是确认阅卷人能否对每个题面要求直接判分。必须逐条审计评分点的最终答案覆盖；缺少可直接判分的答案即使模型、代码和章节齐全，也不得通过。

**机检纪律：本阶段不得信任前序阶段的手写 PASS。** 凡可机检项——复现清单（`check_reproducibility.py`）、图件引用与编号（`check_paper_refs.py`）、图件重叠（`check_figure_overlap.py`）、**版面检测/页内空白与孤立图**（`check_layout.py`）、论文编译（`xelatex`）、**表格/表题/符号说明/模型章结构专项**（`audit_paper_tables.py`，覆盖表题去冒号、表格居中、符号说明单 `longtable`、续表头、五号、三线表、无重复 `\end{document}`、仅收录跨章节符号、模型章允许条件性公共数据处理且问题小节按题面顺序、标题层级不超过三级、公式多等式左花括号）、摘要/语言门禁（`audit_abstract_page.py`、`audit_submission_language.py`）、manifest（`validate_manifest.py`）——必须**在此阶段重新运行对应脚本，以其 exit 0 为准**，不得沿用或转述前序声明。

审计清单见本文最后的"验收审计清单"，先按它的各分类逐项核对。

跨阶段不变量遵循 `../mm-orchestrator/references/cumcm-shared-policy.md`；各类产物的具体合格标准以对应 owner skill 为准，本 SKILL 负责复跑机检、核对证据并创建返工。交接字段遵循 `../mm-orchestrator/references/project-manifest-contract.md`。

## 工作流

### Step 1：完整性审计

> 对应下方审计清单 **1. 完整性**（含各产物是否齐全）。以下补充说明关键判据与处置：

- 对照 `plan.md` 的阶段清单，逐阶段检查应有产物是否齐全（报告、代码、结果、图表、论文）。
- 检查 `paper/writing-gates.md` 是否存在、G-1~G-5 是否全部 PASS 且证据可查；数字、编译和格式属于终稿验收项，不计入写作前 GATE。若论文阶段为 `n_a`，不要求该文件。
- 检查 G-1 是否逐类覆盖摘要、问题重述/分析、模型/求解、结果/检验/评价、字体/图表/LaTeX、AI声明/文献/附录/支撑材料并记录 SKILL SHA256；只引用1～2条规则不能视为完整阅读。
- 运行 `<mm-orchestrator目录>/scripts/validate_paper_plan.py paper/page-budget.json --root .`，检查正式预算目标为28～29页、各章预算闭合、初稿审计存在且 `paper_plan.status=complete`；失败说明论文阶段不应启动。
- 检查 `project-manifest.json` 的阶段状态、稳定 ID、文件哈希、版本和回写记录是否完整。
- 运行 `<mm-orchestrator目录>/scripts/validate_manifest.py`；Schema 校验失败时验收不得通过。
- 缺失项记录"缺失"，不现场补造。

### Step 1.5：评分点与最终答案覆盖审计（高优先级）

> 对应下方审计清单 **1.5 评分点与最终答案覆盖**。这是最高优先级的审计（评分点可判分），其余审计都以它为基础。

- 从 `docs/00-problem-interpretation.md`、`docs/01-analysis-report.md` 和题面原文提取每个显式任务与可识别评分点，建立稳定的 `SCORE-###`；若使用评委评分细则或用户提供的评分点，记录来源；没有正式评分细则时不得臆造分值，但仍须覆盖题面要求。
- 对每个 `SCORE-###` 建立矩阵，至少包含：评分点/题面位置、所属 `P-##` 或 `REQ-###`、预期答案类型（数值/方案/排序/判定/预测/解释/建议等）、论文最终位置、可直接判分的答案原文或数值、支撑证据位置、复现来源、PASS/FAIL。
- “模型已建立”“算法已运行”“指标已报告”“结果见表”均不是最终答案。必须能从正文或结论中直接读出题目要求的结果，并能判断对象、单位、范围、排序、方案或适用条件；答案分散在多处时，论文应有明确汇总句或汇总表。
- 每个 `P-##` 至少有一个明确的最终回答；每个 `REQ-###` 和 `SCORE-###` 必须映射到最终答案及证据。缺少答案、答案类型不匹配、只有过程没有结论、只有结论没有证据、数字/单位/对象不完整，均判 FAIL 并回写 `mm-paper-writing`；若缺模型或结果则同时回写对应阶段。
- 验收报告必须附完整矩阵，不得只写“各问已回答”或只列章节标题。矩阵中的论文位置应能由阅卷人直接打开定位，答案应尽量引用原文短句、表格行或明确数值，而不是验收者自己的概括。

### Step 2：一致性审计

> 对应下方审计清单 **2. 一致性**（数字、公式、图表编号与各报告一致）。

- 论文中的数值、公式、图表编号是否与 `docs/02`、`docs/03`、`docs/04`、`docs/05-diagrams-report.md` 一致。
- 符号表是否与建模报告一致；图/表是否都在正文被引用；求解步骤符号是否与正文一致。
- 核对多等式公式排版：同一个公式表达中用逗号、分号等并列的多个等式，应以左花括号逐行呈现并共享一个式号，不以横向逗号串联；若某行需单独引用或分别推导，才要求拆分。公式组每一行仍能追溯来源、含义和推导链。
- 摘要、正文、结论、CSV 与图表中的关键数字一致（老师验收项 8）。

### Step 3：可复现性审计

> 对应下方审计清单 **3. 可复现性**（复现清单字段、随机种子、重跑结果一致）。

- 检查 `results/复现清单.json` 是否存在、字段是否完整。
- 抽查：按 `code-spec` 是否固定了随机种子、输入哈希是否记录。
- 默认从原始数据完整重新运行主程序，退出码必须为 0，关键结果在记录的数值容差内一致。
- 若完整重跑成本过高，记录预计成本、无法完整重跑的原因与抽样方案，改为运行核心程序、独立复核程序并复核关键结果；不得静默跳过。
- 预测、分类、风险排序或审核决策题另运行专项独立复核；其他题型标记 N/A。

### Step 4：数据真实性审计

> 对应下方审计清单 **4. 数据真实性**（参数可追溯、无编造）。

- 核对论文与结果中的参数能否追溯到题面/附件或建模报告的"待确认项"。
- 排查有无凭空编造数据、为结果好看而改参数的迹象。
- 预测/分类题核对训练/测试隔离：字段选择、标准化、超参、阈值是否只在训练折内完成；身份编码是否进入特征。

### Step 4.5：模型复杂度审计（评委关注项）

> 对应下方审计清单 **4.5 模型复杂度**。重点核对：`docs/02` 每问复杂度适配审计表是否存在并说明题目困难与必要复杂度的对应；全文至少一问体现与核心困难匹配的建模深度；题面含动态/随机/博弈/网络结构时模型显式建模（未退化成静态单方程）；每个优化/决策模型完成"题面真实目标→决策变量→目标函数→约束→最终答案"追踪，目标方向、单位/归一化、权重/惩罚来源与适用边界明确；多目标有归一化/权重或 ε-约束依据与敏感性；代码/结果/论文的目标值与约束可行性一致，无虚构权重、量纲混用、静默换目标、把不可行解当最优解；模型检验与模型类型匹配并给量化指标与对照；灵敏度/稳健性只覆盖重要或不确定参数且有现实依据。

### Step 4.6：证据与决策红线审计（仅预测/分类/风险排序/审核题）

> 对应下方审计清单 **4.6 证据与决策红线**；其他题型全部 N/A，直接跳过。重点核对：小样本用重复分层交叉验证且标准化/变量筛选在训练折内、报告均值±波动；类别不平衡在固定管线比较并报告 AUC/G-mean 与容量指标（Recall@B/Precision@B/Lift@B）；风险因素有折内入选频率、标准化系数、OR/倍率、Bootstrap 区间、方向一致率；数学机制能映射真实字段、聚合方式有敏感性比较；决策模型不虚构逐客户损失、用标准化成本比在捕获曲线上选容量。

### Step 5：图表与图种丰富度审计

> 对应下方审计清单 **5. 图表与图种丰富度**（评委偏好项）。

- 核对选图是否贴合数据与论证；3D 图仅当数据适合时采用；核对技术路线、框架、机理与适用的复杂自研算法流程图。
- 核对所有图（含流程图/原理图与场景/空间示意图）字体是否可读。
- 核对数据图：PDF+SVG+PNG 三格式，PNG ≥300 DPI（多面板按图表规范）；重要类别不得只靠颜色区分。
- 核对流程/框架图：TikZ `.tex`、矢量 PDF 与 600 DPI PNG 成套存在；重新编译 `.tex`，并检查 PDF 自然尺寸、PNG 物理元数据、文字边界、节点重叠、箭头方向、穿框和无语义线条。仅当 manifest 声明 SVG 分支时检查 SVG 语义结构。
- 对时间演化、空间演化或迭代子问题，核对是否展示初始、关键中间和终止状态；不要求至少两个子问题。

### Step 6：论文格式审计

> 本节对应下方审计清单 **6. 论文格式**，逐项核对。格式是硬性项，任何 FAIL 标记为高严重度；数据真实性、核心结果不可复现、关键数字不一致、编译失败和硬性格式违规不得降级。以下按审计主题分组列出核对要点，便于逐类扫查：

**6.1 摘要页与字体**
- 复跑 `<mm-paper-writing目录>/scripts/audit_abstract_page.py`，核对主标题与摘要标题均为三号黑体加粗，摘要正文为小四号宋体，“关键词：”标签为小四号黑体且内容为小四号宋体，汉字数 800～1000、关键词行版心占用率 0.78～0.90，且摘要不过页。用户覆盖必须有书面记录；禁止仅凭单页或字数判定“写满”。
- 复跑 `<mm-paper-writing目录>/scripts/audit_paper_tables.py`，核对表题/图题为 "表1 标题"（去冒号、空格分隔）、表格列全部居中、符号说明为单个 `longtable`（符号|含义|单位）且无章内 `\FloatBarrier`、无两栏并排分组、具备续表头、表内五号、三线表、无重复 `\end{document}`；并核对其“仅收录跨章节符号”判定（表中符号须在正文被复用≥2 次），防止"只出现在个别处的推导中间量/一次性常量"混入符号表。

**6.2 图/表锚点与版面**
- 逐表核对首次正文引用页、表题页和下一小节标题页。数据审计表、符号表和核心结果汇总表必须紧跟首次引出，且不得被同节大型图片挤到下一页或孤立浮动页；异常回写 `mm-paper-writing` 调整锚点或对单张关键表锁位。
- 逐图核对首次正文引用页、图题页和下一小节标题页，确认“文字引出 → 图片 → 实质解读”、问题/小节归属、关键图邻近性和无孤立图页；异常回写 `mm-paper-writing` 调整叙事顺序、锚点或浮动参数。
- 对连续的表—图证据组逐页核查局部版面：表后至图前不得出现由浮动队列或图件画布留白造成的明显无效空白；当前页可容纳时应保持紧凑相邻，必要时回写 `mm-paper-writing` 对该组局部使用 `[H]` 或合并排版。仅“同页/同小节”不视为通过。
- 对每张跨页长表逐页检查：首页表题正常；续页标“续表 N　原表题”并重复完整表头与单位；非末页标“续下页”；仅末页有最终底线；表号、标签和表目录不重复，数据行连续且整张表未跨入下一小节。

**6.3 结构、故事线与语言**
- 核对结构完整、结果分析充分、附录源码完整。模型对比、灵敏度、鲁棒性与检验只在适用或支撑论文主张时检查；不设最低数量。
- 求解表达可用连续段落或普通编号，不固定编号形式；只有复杂自研算法才允许流程图。
- 核对故事线：问题→障碍→选择→证据→转折→决策→边界；每节承接上节问题、落下可复算结论；摘要为全文故事缩写；结论最后一句只写应用条件。
- 核对语言是否有明显 AI 腔（参考 `mm-paper-writing` 的「语言自然化与去 AI 味」与「故事线」两节）。

**6.4 评卷内容审计（高价值，逐问抽查）**
- **评卷内容审计**：逐问抽查“题面要求 → 针对性模型或改造 → 可复现结果 → 明确回答”的完整链条。标记并回写：与题目无关的方法罗列、通用算法简单拷贝却未说明本题处理、只报性能而未回答题面、为凑篇幅的重复/空泛段落、无信息图表、无证据的创新或优越性主张，以及任何无法追溯到代码、数据或记录的结果。不得因结构齐全、页数达标或语言流畅而掩盖此类缺陷。
- **模型章骨架审计**：模型章外层按题面问题顺序；问题一前至多有一个公共数据处理二级标题；每问内部标题按真实机理、数据、目标、约束、算法或结果组织且不超过三级，不要求各问复制同一模板。共享、专属和混合数据处理的位置与真实数据关系一致。
- **模型完整性审计**：逐问核对模型选择依据、备选取舍、变量/参数类型、单位、范围和来源、公式引入理由、约束现实含义及优化模型集中汇总；删除题目背景后仍可原样套用的通用选型段判为针对性不足。
- **求解可复现审计**：成熟求解器至少说明模型性质、工具/版本、关键参数、容差/终止、状态和输出；常规算法说明输入、核心步骤和输出；智能优化/复杂算法另核对编码、初始化、目标/适应度、更新、随机种子、独立运行与收敛证据。论文描述必须与 `docs/03` 和复现清单一致。
- **模型联动审计**：前问输出若声称进入后问，必须核对传递对象、符号、单位、尺度、变换及其在后问变量、参数、目标、约束、初值或数据输入中的真实落点，并检查误差传播；只有“基于前问”文字而无实际输入映射时判 FAIL。
- **证据位置审计**：使用前的量纲、极限、退化、守恒和可行性检查位于模型建立附近；使用后的误差、交叉验证、对比和稳定性证据紧邻对应结果。各问模型不同可分别放置，同类模型可共享检验小节，不强制独立成章。
- **最终答案可判分审计**：复核 Step 1.5 矩阵中的每一项，打开论文对应位置，确认答案对题面动词（如预测、优化、比较、安排、解释、判定、提出建议）作出了完整回应。若读者还需自行从多张表、公式或代码推导答案，视为未直接回答；要求回写论文增加简洁的答案汇总句/表，并保留证据引用。此项是高严重度，不得用“章节完整”降级。
- **复杂算法深度审计**：若题目或模型使用非平凡算法，核对建模报告、代码、结果报告和论文是否共同说明状态/决策规模、关键更新、终止/收敛、复杂度、参数影响、失败/退化情形和验证证据；缺任一关键环节则回写对应阶段。若题目不需要复杂算法，核对是否有充分理由采用简单方法，防止为复杂而复杂。
- **目标函数合理性审计**：逐个优化/决策子问题核对“题面真实目标 → 决策变量 → 目标函数各项 → 硬约束/软惩罚 → 最终答案”的链条。检查方向、单位/归一化、权重和惩罚来源、代理指标合理性、多目标敏感性、约束可行性及代码实现一致性；发现虚构权重、量纲混用、目标与题面不一致、目标函数遗漏关键代价或把约束错误当目标，判 FAIL 并回写分析/建模/编程阶段。

**6.5 标题编号与格式硬性**
- **标题编号审计**：逐页核对可见一级标题。表示正文顺序的标题必须显示中文数字加顿号（如“一、问题重述”）；“参考文献”“附录”“AI 工具使用声明”等非顺序标题不得显示数字。出现自动阿拉伯章节号、把参考文献编号为“九、”或其他混用时，回写 `mm-paper-writing` 修正 LaTeX 标题命令/计数器后重编译。
- **字体实现审计**：源码显式设置 SimSun 与 SimHei；一级标题小三号黑体居中、二级四号黑体左对齐、三级小四号黑体左对齐、正文小四号宋体、图题表题小四号宋体、表内五号宋体；AI 声明、参考文献和附录标题/正文按同级规则执行，附录源码五号等宽字体。用 `pdffonts` 或等价工具确认字体真实嵌入。

### Step 7：论文格式与交付审计

> 对应下方审计清单 **7. 论文格式与交付规则**（页边距、页码、页眉、编译、字体嵌入、交付）。这是高严重度项。

- 以 `mm-paper-writing/SKILL.md` 为论文格式与交付的具体标准，并同时核对共享文件中的真实性与追踪不变量：正文范围包含参考文献及必设的 AI 工具使用声明，参考文献中文条目占比不得低于 60%，附录必须独立另起一页、控制在 9～11 页、固定包含 A、支撑材料文件列表和 B、主要的源程序；论文附录只展示主要源码，其余完整可运行源码由支撑材料提供。

### Step 9：整理支撑材料

> 对应下方审计清单 **8. 支撑材料**（本 skill 是支撑材料压缩包的 owner）。

本 skill 是最终支撑材料压缩包的 owner。以论文附录 A“支撑材料文件列表”为锁定清单整理一个 RAR 或 ZIP 文件，不得静默改变文件集合；确需增加、删除或改名时，先创建回写项，由 `mm-paper-writing` 更新附录 A、双遍重编译论文并更新哈希，再继续打包。

- **必须包含**：建模所用全部完整可运行源码；必要中间结果；正文未完整展开但用于复核的较大篇幅图表；自主查阅并实际使用的数据资料（赛题原始附件除外）；精确依赖锁定；中文运行说明；一键运行入口；全部文件 SHA256 清单；与论文 AI 声明一致的《AI 工具使用详情.pdf》（**内容与格式规范见 `references/ai-details-spec.md`：六段结构、A-XX 编号连续、人工核验为可复核动作、匿名、无【待补充】**）。
- **不得包含**：论文 PDF/TeX；`docs/` 阶段报告；赛题原始附件；`writing-gates.md`、页面预算、初稿审计等内部流程文件；旧版图、预览图、缓存、临时/备份文件；承诺书、编号页、身份和联系方式；账号、密码或API密钥。
- **打包要求**：只生成一个压缩包，后缀为 RAR 或 ZIP，大小不超过20MB；文件路径使用相对目录，压缩包解压后不得依赖作者电脑绝对路径。
- **一致性**：压缩包文件集合与附录 A 逐项一致；附录 B 展示的主要程序与压缩包中的对应源文件内容一致；《AI 工具使用详情.pdf》与论文声明用途一致（**且符合 `references/ai-details-spec.md` 的内容规范**）；SHA256 清单覆盖压缩包内全部普通文件且复算一致。
- **复现性**：按中文运行说明从解压目录执行一键入口，全部必要源码、库、输入和输出关系可查；至少复现论文主要结果，无法全量运行时按既定高成本抽查规则记录原因和复核范围。
- **变更闭环**：任何文件集合、程序版本、运行说明或AI详情变化都要更新附录 A、SHA256、manifest artifacts和change_log；论文重编译与支撑材料重验完成前不得交付。

### 6. 论文格式

- [ ] 摘要审计脚本 PASS：主标题与摘要标题均为三号；用户覆盖已书面登记
- [ ] 摘要页论文题目和“摘　要”为三号黑体加粗居中；摘要正文为小四号宋体；“关键词：”标签为小四号黑体、关键词内容为小四号宋体
- [ ] **摘要写满一整页且未超过一页**：关键词行位于可打印版心纵向 78%～90%，不得只凭"单页"判断；关键信息仅按需少量加粗
- [ ] 摘要汉字数为 800～1000；结构为一个两句引言段、每问各一段和一个真实收尾段；未用固定段数上限把多个问题合并
- [ ] 每问摘要段均包含实际任务、模型名称及数学类型、求解算法、可直接回答题目的数值/排序/预测/方案/判定，以及适用的检验证据；非数值型问题未为凑数字虚构结果
- [ ] 问题间承接关系与正文真实输入输出一致；未因题号顺序强行写成递进模型
- [ ] 题目突出全文主模型与研究对象；关键词为 4～6 个，覆盖问题/对象、主要模型、核心算法或真实创新，无宽泛词、软件名凑数或同义重复
- [ ] 摘要使用第三人称，无图、表、公式、参考文献编号和未经解释的非常用缩写；创新、精度、稳定性、鲁棒性、推广和局限均有正文依据
- [ ] 摘要未使用 `\vfill`、弹性空白、`\enlargethispage`、缩小页边距、异常放大标题或空泛句子填页
- [ ] `check_paper_length.py` 在paper阶段与verification阶段均 exit 0，正文为27～30页，manifest最终页数与两份审计一致
- [ ] **无目录**
- [ ] 表示顺序的一级标题使用中文数字加顿号（如"一、问题重述"）；参考文献、附录和 AI 工具使用声明等非顺序标题无编号；无自动阿拉伯章节号或混用
- [ ] 正文范围为摘要之后至附录之前，包含参考文献与必设的 AI 工具使用声明，不含摘要和附录；默认 27~30 页并以当届官方规定为准；内容充实、无注水
- [ ] 字体层级统一：一级标题小三号黑体居中、二级标题四号黑体左对齐、三级标题小四号黑体左对齐、正文小四号宋体、图题表题小四号宋体、表内文字五号宋体；正文单倍行距，段落额外间隔约四分之一行
- [ ] AI 工具使用声明、参考文献和附录的无编号一级标题为小三号黑体居中，正文/文献条目为小四号宋体；附录 A/B 标题为四号黑体左对齐，源码为五号等宽字体
- [ ] 所有表格表头、文字和数字使用五号宋体并水平居中，长文本居中换行，表后恢复小四号宋体正文，无字号或字体族泄漏
- [ ] 论文结构完整（八段式：重述/**问题分析**/假设/符号/模型与求解/检验/评价/参考文献/附录）
- [ ] 每个子问题解答过程详细（分析→建模→求解→结果表→结果分析流水线）
- [ ] 求解表达可使用连续段落或普通编号，不固定编号形式；只有复杂自研算法才允许流程图；每问有结果表与分析
- [ ] 模型对比、检验、灵敏度和鲁棒性按题目需要出现；凡声称更优、可靠或稳定，均有对应证据
- [ ] 模型评价含"优点 + 缺点（示弱）+ 推广"
- [ ] **正文图 ≥ 12**；**表按需使用，仅内容适合三线表时再做，无"每问至少 1 表"与最低表数**（"符号说明"章仅一个三线表、无需正文引用）；图表类型按题目证据选择，不强制每问都制作数据图；图表全文连续编号、无重号跳号；凡表格须为三线表
- [ ] 图文件名与图题（`\caption`）不带"问题X/QN/qN"编号字样；数据图标签与图形元素无重合
- [ ] **摘要/表内/正文数字三处一致**；精度统一（2–3 位小数）
- [ ] **附录单独另起一页且总篇幅为 9～11 页**：起始处有独立可见、居中的一级标题"附录"，固定包含 A、支撑材料文件列表和 B、主要的源程序；论文附录展示主要源码，其余完整可运行源码在支撑材料中提供；少于 9 页时未用重复内容或空白注水，超过 11 页时已精简非核心代码；代码字号不小于五号、无超出版心或核心逻辑删减
- [ ] 语言无明显 AI 腔：每段有数字/公式/字段关系/失败结果/选择理由；无路标词与空泛评价；图题表题不写备注
- [ ] 求解步骤编号形式与全文排版协调；不机械强制或禁止圈号数字
- [ ] 故事线：问题→障碍→选择→证据→转折→决策→边界；每节承接上节问题、落下可复算结论；结论最后一句只写应用条件

- [ ] 逐页渲染检查：图表大小、标签遮挡、孤行、留白、附录
