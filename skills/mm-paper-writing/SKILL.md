# 数学建模：竞赛论文撰写

本 skill 在完整工作流中必须由 `mm-orchestrator` **连续、独立调用两次**。每次调用都必须从头完整读取本文件和本次适用的直接引用规范，读取已定稿的结构规划、页面预算、初稿审计、图件清单、全部报告和结果，并在本次调用内完成多轮终稿、双遍编译、正文页数与全部专项审计；不合格时生成内容缺口报告并继续有依据地补充或压缩，直到本轮全部门禁通过。它不是“打开初稿快速润色后结束”的工具。

### 双调用协议（进入验收前的硬门禁）

1. **两次调用相互独立**：第一次与第二次调用开始时，都必须按文件顶部 `READ-PREAMBLE` 重新量出总行数、列出全部 `##/###` 标题、按明确行号范围分块读取到文件末尾，并确认没有任何分块出现 `truncated`。不得以第一次调用的上下文、摘要、缓存或“已读过”为由跳过第二次完整读取。直接引用且本轮适用的规范也须重新完整读取。
2. **第一次调用（成稿轮）**：从上游材料新建或重构 `paper/论文.tex`，落实本文件全部适用要求，完成至少双遍编译和全部专项门禁。生成 `paper/pass-1-audit.md`，按本文件全部二/三级标题记录“已执行/不适用（含理由）/阻断”，并在 manifest 写入 `paper_final.full_skill_passes=1`、登记审计文件哈希；此时 `paper_final.status` 只能保持 `in_progress`，不得置为 `complete`。
3. **第二次调用（独立终审轮）**：以第一次产出的 `paper/论文.tex|pdf` 为当前终稿，而不是 `draft-baseline`。重新读取全部上游输入、当前终稿和本文件全部规则，逐项检查第一次可能遗漏的内容；发现问题必须直接修正，并再次完成至少双遍编译、页数审计、引用/布局/摘要/语言/字体表格等全部适用机检与人工冷读。第二次调用不是只读抽查或快速润色，未改动的要求也必须重新核实并记录证据。
4. **第二轮审计产物**：生成 `paper/pass-2-audit.md`，至少逐项覆盖本文件全部二/三级标题、公共硬性要求、G-1～G-5、全部机检命令与 exit code、人工检查项、修改摘要和最终文件哈希。只有第二轮无阻断项，才能写入 `paper_final.full_skill_passes=2`、`paper_final.second_pass_audit="paper/pass-2-audit.md"` 并把 `paper_final.status` 置为 `complete`。
5. **禁止提前验收**：`full_skill_passes<2`、第二轮审计缺失/哈希未登记、任一适用要求未核实或任一脚本非零时，均不得调用 `mm-verification`。若第一轮或第二轮发现上游矛盾，先按 owner skill 回写，受影响的论文轮次必须重新执行。

## 输入与产出
- 输入：编排器正式定稿的 `paper/structure-plan.md`、`paper/page-budget.json`、`paper/draft-audit.md`、`paper/draft-metrics.json` 与 `paper/writing-gates.md`；`paper/figure-requirements.md`（由图件 skills 填入）；可选只读初稿 `paper/draft-baseline.tex|pdf`；全部 `docs/01~05`、`figures/`、`results/`、`plan.md`、`project-manifest.json`。
- 产出：`paper/论文.tex`、`paper/论文.pdf`、`paper/page-audit.json` 与 `paper/content-gap-report.md`。唯一终稿格式为 LaTeX；初稿基线不得被覆盖或作为终稿提交。
- 跨阶段不变量遵循 `../mm-orchestrator/references/cumcm-2026-shared-policy.md`；论文结构、写作、字体、排版、引用、附录和终稿交付细则以本 SKILL 及其直接引用的 references 为准。交接字段遵循 `../mm-orchestrator/references/project-manifest-contract.md`。

## 写作要求（硬性，不能违背）

官方要求与评委偏好冲突时以官方为准（官方优先），但二者都必须满足。凡"原则上/建议/按需"表述也应在适用时尽力落实，不得以"只是偏好"为由跳过；验收逐条核对，缺项即回写。

### 公共要求（所有章节通用，必须遵守）

1. **本工作流固定版式**：论文排版、匿名、页码、篇幅、字体、摘要、引用和附录规则以本 SKILL 为准；用户明确提供的新要求可以覆盖，并记录覆盖原因。LaTeX 输出不得静默放宽或改写这些规则。
2. **数据真实**：所有数字与 `results/` 一致，不编造不夸大；摘要/表内/正文数字三处一致；表格数值逐项来自 `results/`，禁止凭印象/推算填表。
3. **匿名**：全文（摘要页/正文/附录/支撑材料）不得出现身份、学校、赛区信息。
4. **不要目录**：论文不设目录，摘要后直接进入正文。
5. **正文边界与篇幅**：正文=摘要之后、附录之前（含顺序章节、AI 声明、参考文献）；正文 27–30 页；禁止重复论述/无信息图表/排版注水；可用展开更细致的推导链、求解细节、验证证据、结果解释、补图补足篇幅。
6. **题目要求优先**：正文首要目标是逐条回答题面要求；结构规划须建"题面要求/子问题→正文小节→变量与约束→结果证据→最终回答"追踪；与题目无关、不改变判断、不支撑交付的内容不写；不为页数/图表数/章数扩写；不适用项记录原因并跳过。
7. **评卷导向落地**：逐问呈现"本题特有困难→针对性选择或改造→可复算求解→真实结果→对题面要求的回答"；不得把通用模型/算法/方法清单堆成主体；"创新/有效/更优"须有具体改造与证据。
8. **最终答案必须可定位**：每个子问题结尾与全文结论直接回答题面任务动词，给出完整对象/数值/方案/判定/解释/建议及必要单位或适用条件；不得只写"模型有效/结果见表"；保留"题面要求→答案位置→支撑证据"追踪。
9. **人的思维逻辑**（详见 `references/去AI味与故事线-必须遵守.md`）：按"问题/障碍→可用数据与必要假设→模型选择理由→变量目标约束→求解→证据→回答与边界"组织；每节开头承接前文、结尾落可核验判断；不写内部流程/报告编号/门禁状态/工具操作；避免四问完全同构小节的模板化。
10. **模型/算法深度与适配**：只在有论证价值时写状态空间/决策变量/复杂度/约束规模，并解释与题目困难匹配；复杂算法须写必要性、状态与决策、目标约束、关键更新/终止、复杂度、参数影响、退化/失败与验证，不得以算法名/伪代码/流程图代替分析；简单方法已够则说明为何不需要更复杂算法。
11. **证据按需写入**：只写 `docs/02/03` 中适用且有真实结果的对比/灵敏度/鲁棒性/检验；凡声称更优/稳定/可靠，须紧邻给出证据；不设每问或全文最低数量。
12. **一级标题序号**：顺序一级标题用中文数字+顿号（"一、问题重述"）；"参考文献""附录""AI 工具使用声明"等不加序号；二/三级用阿拉伯层级或无编号；不得让自动阿拉伯章号覆盖中文序号。
13. **图表（边界/数量/命名/来源/必引用/位置）**：正文图≥12；表仅在适合三线表时用、不设每问最少；每图有明确叙事作用、一图一结论；图表全文连续编号；可见图文件名/图题不得带问题编号前缀；正文插图一律来自 `mm-figures`/`mm-graphics`（缺失先回写补齐，禁止临时脚本/占位图）；纯视觉示意图按需（登记 `docs/05-visual-report.md`）。**硬性**：**每张图、每张表都必须有正文 `\ref`/`\eqref` 引用**（不得出现"只 `\label` 不 `\ref`"的孤儿图/表），且**不得形成孤立图页/表页**（一页内几乎只有图或表、无正文文字）；插图/表格必须**紧跟其所属或被讨论的段落**，**不得被浮动推到该讨论之后、其它无关段落的后面**（若图与前后段落主题不符，视为锚点错误，应移到对应讨论段旁）；凡出现即视为 FAIL，须就地锁定（`[H]`/`[htbp]` 配合）或调整锚点，使"文字引出→图/表→解读"。机检：`check_paper_refs.py` 已校验每个 `\label{fig:...}`/`\label{tab:...}` 都有且仅有正文引用；`check_layout.py` 校验孤立图/表页与留白；"图落在不相关段落后"靠作者自查（图应与其紧挨段落同主题）。
14. **成稿去过程化与去套话**（详见 `references/去AI味与故事线-必须遵守.md`）：标题/摘要/正文/图表可见文字/附录说明/页眉页脚遵循"语言自然化与去 AI 味"；禁止暴露生成过程的词与空泛模板句；仅官方 AI 声明可用相关措辞；终稿前运行 `audit_submission_language.py`。
15. **故事线与冷读**（详见 `references/去AI味与故事线-必须遵守.md`）：全文按问题→障碍→选择→证据→转折→决策→边界推进；初稿后按"故事线"冷读检查，删除无新增信息的段落。
16. **表格与首次引用相邻（所有章节通用，硬性）**：只要某章节用到表格，该表就必须排在其第一次被正文引用（`\ref`/文字引出）的段落之后、与之紧邻；若表格较长、单页放不下，**允许跨页**（用 `longtable` + 续表格式），但不得因浮动被推走而滞后到后续页或落到无关图表之后，从而在引用段与表格之间、或在页面内留下**大段空白**，也不得出现孤立表页。作者须逐表自查"首次引用段 → 表所在位置"，发现漂移即就地处理（关键表用 `[H]`、长表改 `longtable`、必要时微调同节图件与文字紧凑度），**不得**以"float 到就近页""下一小节标题自动带过"为由接受留白。若同一引用句**同时引出多张表**（如"…见表 N、表 M"），可把这些表**紧排在该句之后**：其中靠后的表之前出现前一张表（同句引入的组合）属正常，**不算"其他内容隔开"**；判据只针对**与这些表无关**的文字、公式、图或其它表插入其间，才视为漂移。该条对全文所有出现表格的章节通用，不因章节不同而放宽，且同样适用于 图表与格式 的相关规定。
17. **无溢出/Overfull（所有内容通用，硬性）**：正文、附录不得出现 `Overfull \hbox`（文字/公式/表格超出版心宽度）。长公式用 `equation` 内 `\begin{split}` 或 `aligned`+`\left\{` 断行、共享一个式号；过宽表格用 `\setlength{\tabcolsep}{1pt}`（或更短的表头/标签）收紧；含长 `\texttt{文件路径}` 的列表或段落加 `\sloppy`（列表可 `\raggedright`）允许折行。编译后检查日志无 `Overfull`，有则逐处修正；禁止为消溢出把字号缩到小于五号，也不得注水/删必要内容。
18. **正文段落缩进（所有章节通用，硬性）**：可用黑体（`\paragraph{}` 小标题、子题、关键词、图题表题等）。但每个**新段落**的首行必须**首行缩进两字符**；不得用 `\noindent` 消除新段落的首行缩进（`\noindent` 仅允许用于"摘要之关键词行"这类本就不该缩进的行）；`\paragraph{}` 若用作小标题，其后正文仍须是一段**缩进的正文**（若 LaTeX 的 run-in `\paragraph{}` 不缩进正文，则应改用"标题 + 缩进正文段落"，或让正文段落自身缩进）。终稿抽查：每个正文段落首行应有两字缩进；出现 `\noindent` 处应为特殊行（如关键词），否则 FAIL。
19. **中文引号与标点（所有章节通用，硬性）**：中文引号必须成对使用弯引号——开启用“”（U+201C）、闭合用”（U+201D），禁止使用两端同向的直引号`"`（U+0022）或两端同向的单引号。全文可见文字（摘要、正文、标题、图题、表题、图表内文字、关键词、附录说明、页眉页脚）使用全角中文标点，不得用半角标点充当中文标点；成对引号不得跨句、嵌套或左右错位。终稿需全文核对引号配对与方向，避免“两端同向”。


20. **禁用 Markdown 加粗/强调语法（论文 LaTeX 源码，硬性）**：论文 `.tex` 源码中不得使用 Markdown 的 `**...**`、`__...__`、`*...*`、`_..._` 表示加粗/强调——它们在 LaTeX 中不会加粗，会原样显示为 `**` 或下划线。强调一律用 LaTeX 命令：加粗中文用**带作用域的黑体**：`{\heiti 文本}`（先定义 `\newcommand{\cjkbold}[1]{{\heiti #1}}` 后用 `\cjkbold{文本}`）——黑体只作用于该段文字、不泄漏到其后整段；`\textbf{...}` 亦可，但主字体须配 `\setCJKmainfont{SimSun}[BoldFont=SimHei]` 才真正可见；或用 `\textbf{...}` 且主字体须配 "
    "`[BoldFont=SimHei]`（如 `\setCJKmainfont{SimSun}[BoldFont=SimHei]`）才可见；"
    "斜体 `\textit{...}`、等宽 `\texttt{...}`。并须使加粗真正可见：正文主字体需为 `\textbf` 配置可加粗的字形（如 `\setCJKmainfont{SimSun}[BoldFont=SimHei]`），否则 `\textbf` 对中文可能不显示加粗。终稿应全文检查，凡正文/摘要/标题/图题/表题/附录说明出现 `**`、`__`、`*`、`_`（作为强调标记）即视为违规，改写为对应 LaTeX 命令。

#### 图表与格式

- **数量基线**：正文图 ≥ 12；**表按需使用，仅在内容适合用三线表时才做**（无"每问至少 1 表"、无最低表数）；每张图必须服务明确论点、禁止为凑图堆图；表（结果/对比/参数）应被正文引用并解读，"符号说明"表除外（只需一个三线表，不要求正文引用）。
- **图题**「图 N 描述」（图下方）、**表题**「表 N 描述」（表上方），统一使用小四号宋体；全文连续编号、无重号跳号；正文必须引用每张图/表。
- **题注短命名（硬性，所有章节通用）**：图题/表题只写对象名（短名词短语，如「各月光学效率分量」「鲁棒性扰动检验」「分区异质布局」），不得在题注里写说明性长句、冒号解释、结论或机理；图/表的关键现象、机理与结论一律在正文首次引用处用 2～4 句说明。题注通常不超过16字；同节多图/多表以内容词区分，禁止用“问题一/二/三”或Q1/Q2作题注区分词。
  - **表与首次引用相邻（同公共要求第16条）**：每张结果表、参数表和汇总表必须紧跟第一次正文引用段，不得被无关文字、公式、图或其它表隔开；发生漂移时对该关键表局部使用 `[H]` 或改用 `longtable`，不得机械全局锁位。
  - **交叉引用颜色**：正文 `\ref`、`\eqref`、`\cite` 显示为普通黑色正文，不得使用彩色、下划线或彩色边框；使用 `\usepackage[hidelinks]{hyperref}` 或明确将全部链接颜色设为黑色。
- **三线表**：凡使用表格，一律采用 `booktabs` 的 `\toprule/\midrule/\bottomrule`，无竖线；符号说明只放一个三线表且无需正文引用。
- 图内文字必须在最终物理尺寸下可读；位图不低于300 DPI，子图使用(a)(b)标注。
- **浮动与边界**：单页图表默认 `[htbp]`；一级和二级标题边界使用 `\FloatBarrier`，图表不得跨入下一小节；只有必须紧跟解释的关键图表使用 `[H]`。
- **表格字体与对齐**：表内文字统一五号宋体，表头、文字和数字水平居中，长文本使用居中的定宽列换行；表格结束后恢复小四号宋体正文，避免字体和字号泄漏。
- **关键表顺序**：数据审计表、符号表和核心结果汇总表紧跟首次引出，并优先于同节大型图片。
- **数字一致性**：摘要、表内和正文数字完全一致，精度统一为2～3位小数或按题面口径执行。
- **求解步骤呈现**：是否单设求解小节取决于信息量；成熟求解器通常并入模型末尾但仍须完整交代工具、版本、参数、终止、状态和输出，常规算法可用连续段落或普通编号，复杂自研算法按需使用内容化小节与流程图。

##### 跨页续表排版

- 单页能够容纳的表格继续用 `table` + `tabular/tabularx`；只有保持五号宋体、可读列宽和合理行距后仍无法单页容纳时，才使用 `longtable`。
- `longtable` 不得包在 `table` 环境中，也不使用 `[H]`；跨页只发生在数据行之间，不拆同一逻辑行，整张表必须在同一小节内结束。
- 首页使用正常表号和完整表题，只设置一个 `\label`；续页顶部标“续表 N　原表题”，重复完整表头和单位，沿用原表号且不重复进入表目录。
- 非末页底部右侧标“续下页”；中间页不使用最终底线，只在末页使用 `\bottomrule`。
- 至少双遍编译，逐页检查续表号、表题、重复表头、单位、续下页、末页底线、数据连续性，以及是否出现漏行、重行、空白续页或下一小节标题插入表内。

#### 去 AI 味与讲好故事（所有章节必须遵守）

本要求适用于标题、摘要、关键词、正文、图题、表题、图表可见文字、附录说明和页眉页脚。完整规则见 `references/去AI味与故事线-必须遵守.md`；公共要求第9、14、15条与本节共同构成硬性语言规则。终稿前必须运行 `audit_submission_language.py` 并进行人工冷读，删除无新增信息的段落，确保全文按“问题→障碍→选择→证据→转折→决策→边界”推进；仅AI工具使用声明允许出现规定的AI措辞。

### 章节级要求（已并入对应写作小节）

摘要、问题分析（每问一节）、模型假设、符号说明、模型的建立与求解（外层按问题顺序、内层按内容生成）、结果呈现与分析、模型评价与推广、AI 工具使用声明、参考文献、附录 A/B，以及“附录与支撑材料接口”。支撑材料详细内容和打包规则由 `mm-verification` 负责。**详见各章节级小节，此处不再重复**。

## 章节结构与写作规范

### 整体论文骨架（固定，获奖惯例 + 官方要求）

**固定部分**（顺序固定，不得增删挪动）：

```text
摘要
一、问题重述（1.1 问题背景 / 1.2 问题提出；固定两子节）
二、问题分析（逐问一小节，不另设“各问之间的联系”等汇总小节）
三、模型假设（2–8 条；编号列表，每条单独成段）
四、符号说明（一个三线表：符号 | 含义 | 单位）
五、模型的建立与求解（按问题顺序设置二级标题；可在最前设置条件性的公共数据处理；每问内部标题按模型内容生成）
六、模型评价与推广（优点 + 至少一个真实局限（示弱）+ 改进/推广）
AI 工具使用声明（无顺序序号；置于参考文献之前）
参考文献（无顺序序号；按引用顺序编号、正文标引）
附录（无顺序序号；A 支撑材料文件列表 / B 主要的源程序；总篇幅 9～11 页）
```

**写作执行顺序**（注意与论文排版顺序不同）：**先写正文各章，最后写摘要**——问题重述 → 问题分析 → 模型假设 → 符号说明 → 模型的建立与求解（含结果呈现与分析）→ 模型评价与推广 → AI 工具使用声明 → 参考文献 → 附录 → **最后写摘要**（→ 图表与格式）。摘要必须等全文写完、信息齐全后，从正文中提炼缩写，不能最先写；**成稿排版顺序仍是摘要在前**（见上方"整体论文骨架"）。

**要点**：
- 固定为"摘要、问题重述、问题分析、模型假设、符号说明、模型的建立与求解、模型评价与推广"；模型章外层固定按问题顺序，内层按模型真实结构组织，不用一套三级标题机械复制。模型对比、检验、灵敏度、鲁棒性和误差分析按适用性放入对应问题，只有多个同类模型确需统一比较时才设置共享小节。
- 固定收尾顺序：**模型评价与推广 → AI 工具使用声明（无编号）→ 参考文献（无编号）→ 附录（无编号）**；AI 声明放参考文献之前，附录固定为 A 支撑材料文件列表和 B 主要的源程序，其余完整源码放支撑材料。
- 各章要点（要求 + 机检）：① 问题重述——两子节、改写（防查重）、半页到一页（`audit_submission_language` 查禁用词：人工核对结构）；② 问题分析——逐问一小节，按叙事需要融入任务、数学类型、跨问依赖、数据条件、方法依据、验证与交付，不另设汇总小节（人工）；③ 模型假设——2–8 条、单条成段、给理由（人工）；④ 符号说明——单个 `longtable`（符号|含义|单位）、仅收录跨章节符号、不分组、章内无 `\FloatBarrier`（`audit_paper_tables` T-1~T-3/T-7）；⑤ 模型的建立与求解——外层按问题顺序，允许条件性公共数据处理，内层标题按题型与模型内容生成；每问形成建模、求解、结果、回答与证据闭环（T-8/T-9）；⑥ 模型评价与推广——优点+真实局限+推广，约 3%–5%（人工）。
- 是否合规以机检 exit 0 为准；机检覆盖不到项（是否改写、是否示弱、是否同数据同指标）须人工核对，不以"已实现"自评。

### 问题重述写作

- **章节结构（固定）**：只允许 `\subsection{问题背景}` 与 `\subsection{问题提出}` 两个子节标题（`\section{问题重述}` 下再多一级，**不要**另设"研究现状/问题分析"等子节）。
- **核心要求：改写！** 问题重述要用**自己的话**总结题面，**关键是改写**，不得照抄原题；该部分虽非论文重点，但**是查重最容易出问题的地方**，必须重述而非摘抄。说明情景的来龙去脉，列出必要数据，提出要解决的问题，并给出研究对象的关键信息，让读者对要解决的问题形成印象。
- **1.1 问题背景**：说明情景与来龙去脉——研究对象、现实/学术意义、核心矛盾；通常 3~5 句；并给出研究对象的关键信息（场地/设备/关键参数/约束/任务范围）与必要数据；不得用可替换到任意题目的套话。
- **1.2 问题提出**：逐问重述，条目数与题面一一对应；每问以加粗的"问题X"开头，**不加序号、不加项目符号**；用改写后的词句表达题目任务与本问输入/输出。
- **写法要点**：只重述不展开（建模思路属问题分析章）；不抄原题；语言去 AI 味（不用"首先…其次…最后""值得注意的是""综上所述"）；**篇幅约半页到一页**，不插图、不列表、不放公式、不填版；问题条目用分段段落、空行分隔，不用 `enumerate`/`itemize`；导言区必须 `\pagestyle{plain}`；如模板要求"一、问题重述"式中文编号，另配 `\renewcommand{\thesection}{\chinese{section}}` 类设置。
- **自检**：背景与本题复杂度相称、写清研究对象/意义/核心矛盾并列出关键数据；问题提出逐问覆盖且为改写；未引入题面外要求；无原句搬运；无 AI 腔连接词；问题条目不加序号/项目符号、仅"问题X"加粗；篇幅约半页到一页；仅两个子节标题。

### 问题分析写作

- **固定骨架**：开头不写总结，直接进入逐问分析；每问一小节，标题固定为「问题X的分析」。每个子问题必须在自己的小节内独立成段，不得把多个子问题的分析合并进同一个大段；内容简单时写一个完整自然段，内容复杂时可拆成若干逻辑连贯的自然段，但不机械增设三级标题。不设置「各问之间的联系」、总体分析、数据分析、方法选择等额外汇总小节，也不把下列内容机械拆成六个三级标题。跨问关系写入实际发生依赖的相关问题小节。
- **内容覆盖**：各问按叙事需要自然融入以下内容；某项确实不适用时不强行补写，但整章必须完整反映题目的任务链与建模路线：
  1. 研究对象、任务动词、已知条件、限制和预期输出；
  2. 各任务的数学类型和主要困难；
  3. 各问之间共享的数据及指标、参数或结果传递关系；
  4. 数据来源、可用性、质量风险和必要处理方向；
  5. 模型或方法的选择依据、备选方案和基本求解路线；
  6. 计划采用的验证方式及最终交付形式。
- **叙事方式**：围绕「任务与困难 → 数据和依赖 → 方法取舍 → 求解、验证与交付」组织自然段。每问至少有一个独立自然段，各问之间不得共用一个大段；复杂问题可按上述逻辑拆成多个自然段。标题保持逐问式，但各问内部不复制同一套句式、段数或固定小标题；后问使用前问产生的指标、参数或结果时，在后问小节明确说明传递对象及用途。
- **内容边界**：可以说明模型类型、关键变量、方法思想、选择理由、验证计划和输出形式；不得写具体结果、权重、预测值、误差值、排序、最优方案或最终结论；不得展示大段公式、符号定义、完整推导和程序运行过程。问题分析可以概括数据质量问题和预处理计划，但具体统计值、处理参数和处理结果应放入数据预处理或模型建立章节。
- **图件边界**：问题分析章不强制设置总体技术路线图。若现有图件清单中有确能澄清某问任务、数据流或跨问传递关系的框架图，将其放入最相关的「问题X的分析」小节并按通用图表规则引出和解读，不为容纳图件新增「各问之间的联系」小节，也不逐节点复述图中文字。
- **体量与版面联动**：篇幅随每问复杂度自然展开，不设置固定段数、句数或最低占页率。缺少任务边界、主要困难、数据条件、方法依据、跨问依赖、验证方式或交付形式时补足；存在重复题意、无依据的方法罗列或已由其他章节承担的细节时删减。改动问题重述或问题分析后，重新编译并检查从改动页到首张后续关键表之间的所有页面，确认无孤立图页、大块无效留白、图文倒序或关键表脱离首次引出。

### 模型假设章节

- **格式**：编号列表（**1.**、**2.**、**3.**…），**每个假设单独成段**（一段只写一个假设），不要用逗号、分号把它们挤成一个大段，也不要用表格或图。
- **写法**：每条一句话，简洁；按"合理、必要、可解释"列出，并说明理由或违反后的影响。
- **数量**：通常 2–8 条；不堆砌无关假设，不为显得严谨而乱加。
- **口径说明**：确需说明的输入口径、来源或假设值，可在对应假设段末尾补一句，或并入参数表说明，不单写章节。

### 符号说明章节

  只写**一个三线表**（允许跨页，用 `longtable` 按"跨页续表"规则），不配说明段落。列设计为**符号 | 含义 | 单位**；**若大部分符号没有单位，则去掉"单位"列**，只留"符号 | 含义"。**硬性：禁止把符号表做成"两栏并排 / 双列分组"的紧凑布局**；符号表用 `longtable` **就地排版**、不包进 `table`/`figure` 浮动环境，章内**不加 `\FloatBarrier`**。表内必须显式使用 `\songti\zihao{5}`，结束后立即恢复 `\songti\zihao{-4}`，避免表格字体或字号泄漏到后续正文。

**应放进表里的符号**：
1. 跨章节反复出现的核心变量；
2. 目标函数、约束中的关键参数；
3. 向量、矩阵、集合及其下标；
4. 具有特定业务含义或单位的量。

**不应放进表里的符号**：
1. 只出现在个别处的符号变量；
2. 求和号、最大值等常识性算子（如 $\sum$、$\max$、$\min$）；
3. 正文没有使用的预留符号；
4. 为显得复杂而罗列的所有字母。

**判断标准**：删除该符号后，评委是否需要回到正文才能继续理解？需要则保留；不影响理解则不放。
**高频错误（避免）**：同一个符号表示多个含义；符号表与正文不一致；收录过多、临时变量全部写进去；自己造怪符号（非标准、无定义）；隔十页再次出现某符号时不做任何说明。
**表中未列出的符号**：均须在正文**首次出现时**就地说明（定义、单位），不得无提示直接使用。


### 模型建立与求解写作
本环节是"论证思路与写作原则库，不是可套用的模板"。判题人看的是"思路对不对、论证顺不顺"，不是"小节齐不齐"。
**外层固定、内层自适应**：统一使用一级标题`五、模型的建立与求解`。其下按题面顺序设置`问题一：任务内容`、`问题二：任务内容`等二级标题；多问共享同一数据时可在问题一之前设置一个条件性的公共数据处理二级标题，部分共享时采用“公共处理 + 问题专属处理”，数据彼此独立时分别写入对应问题。每问内部只选择真正需要的内容模块，标题按机理、数据、目标、约束、算法或结果的实际内容命名，最多使用三级标题；一两句话能够说清的内容直接并入段落，不为形式完整机械复制“建模思路—模型建立—模型求解—结果分析—模型检验”。

**每问必须闭合的论证链**：题目目标 → 数据与已知条件 → 模型选择依据 → 变量、参数与单位 → 核心数学关系 → 目标与约束（或状态方程）→ 求解算法 → 结果 → 对题目的直接回答 → 证据与适用边界。闭环是硬要求，小节数量和标题名称不是硬要求。

**题型化组织示例（只示范逻辑，不是模板）**：机理题可按“作用机制—状态方程—参数标定—数值解—误差”展开；预测题可按“特征与窗口—预测关系—滚动求解—预测与不确定性”展开；优化题可按“决策与成本—目标—现实约束—模型汇总—求解与可行性”展开；评价题可按“指标处理—赋权与综合—排序与稳定性”展开。标题必须能反映本题对象，删除题目背景后仍可原封不动套到任意题目的标题或段落应改写。

**数据处理位置**：共享数据统一处理时，正文写明来源、样本量、字段、时间/空间范围、缺失异常判据、处理数量与影响，后续各问直接引用；专属数据处理写在对应问题；混合情形只集中写公共操作，专属变换分别写。问题分析章只写处理计划，本章才写实际方法、参数和处理结果。

**模型建立完整性**：关键变量与参数说明类型、下标、单位、取值范围和来源；每个公式按“引入理由 → 数学表达 → 各项现实含义 → 在模型中的作用”呈现；每条约束说明对应的资源、容量、预算、时间、守恒、逻辑或边界条件。优化模型求解前集中汇总决策变量、目标函数、全部约束和变量范围，不得让目标与约束分散多页后直接调用算法。

**写作内在逻辑（通用铁律）**
1. **模型链思想**：前一个模型输出 → 后一个模型输入/依据，显式写出传递量、单位、时间/空间尺度和必要转换，并让它真实进入后问的变量、参数、目标、约束、初值或数据输入；只写“基于问题一”而后问仍独立重算，不算模型联动。
2. **公式前必有理由**：先回答"为什么需要它"，再放公式（五种引公式方式：从数据结构/问题特征引、从机理/业务引具体项、从模型适用性引、从业务指标反推数学定义、从优化目标引目标与约束）。
3. **模型与算法分开**：模型回答"什么方案最好"，算法回答"怎样找到"。
4. **求解写法分级**：成熟求解器简洁但完整地说明模型性质、算法或求解器、软件及版本、关键参数、容差/终止条件、求解状态与输出；常规算法用连续段落或普通编号写清输入、核心步骤和输出；智能优化或复杂自研算法必须说明编码、初始化、目标/适应度、更新规则、参数来源、最大迭代、终止条件、随机种子、独立运行与收敛证据，不贴真实代码替代解释。
5. **求解 ≠ 结束**：求解后必须解释结果并提供与模型类型匹配的证据。使用前的量纲、极限、退化、守恒和可行性检查放在模型建立位置；使用后的误差、交叉验证、对比和稳定性证据紧跟对应结果。各问类型不同则分别放置，多个同类模型确需统一比较时才设置共享检验小节。
6. **选择性敏感度**：只扰动重要、不确定或可能改变结论的参数，说明选择原因、基准值、现实范围、步长和关注指标；不得把所有参数机械统一上下浮动固定比例。含人为设定权重、阈值或先验时，必须检查结论是否翻转并报告稳定区间。

**叙事与故事线（讲故事原则）**
模型构建不是数学对象清单罗列，而是有前因后果的情节链。按题组织：`开场`（解决什么问题，1–3 句）→ `规矩`（现实规则逐条摆出，即约束由来）→ `主角`（决定什么 → 决策变量）→ `铺垫`（参数从哪来）→ `冲突`（难点/特殊处理 → 本题化改造）→ `成形`（目标+约束汇总）。写作要领：每个数学对象出现都有"前因"；用因果连接词串逻辑；约束按故事顺序讲、不按数学类型罗列；冲突是叙事核心；收尾要"成形"（"由此得到如下 0-1 整数规划/随机规划模型"）；删除任一环节读者还能顺下去才说明叙事成立、否则退回清单；创新点/关键设计给足篇幅、宁可长不可略，篇幅紧时砍常规环节、不砍创新点。**叙事是内在逻辑，不是文风**：标题一律学术式（如"符号与参数确定 / 目标函数的构造 / 约束条件的建立 / 模型汇总 / 模型求解 / 求解结果与分析"），禁止用"主角""规矩""冲突"等口语化标题；一句话判定：**标题像论文、段落像讲故事**。

**论证与选型参考（模板/范式，按题取舍）**
- **公式六层**：数据处理 / 变量定义 / 主模型 / 目标损失 / 约束 / 检验评价——需要哪些定义哪些；公式必须承担至少一种作用否则不写。
- **分题型论证路径（示例，非唯一）**：优化题（拆问题→定义决策变量→构造指标/参数→目标函数→逐条约束→汇总模型→按性质选算法→求解→结果解释）；数据/统计/分类题（识别数据结构→数据有效性筛选→适配变换→模型适用条件检查→按类型选模型→训练/测试分离与评价→异构交叉验证→敏感性）；物理机理题（过程分阶段→受力/几何分析→基本定律→状态方程+初始条件→小参数近似线性化→求解→发现模型出问题→修假设→策略输出）；概率/序贯决策题（现实随机机制→随机变量/分布→期望成本收益→优化目标→枚举或 DP→参数不确定性→灵敏度）。判断标准：路径是否顺应题目的递进逻辑，而不是"有没有按某个模板写"。
- **模型修复范式**：`模型结论不符合实际/无解 → 检查关键假设（不是急着换模型）→ 放宽/修正假设 → 建立改进模型（最小幅度修改，只动受影响部分）`。
- **参数不确定性范式**：`确定性模型（参数为常数） → 参数视为随机变量（分布来自题面区间/共轭先验） → 情景/后验抽样 → 对目标求期望 → 重新优化 → 与确定性结果对比 → 主观参数灵敏度`。写论文时显式写"在问题一模型基础上，将确定参数升级为随机变量"。

**呈现规范与求解呈现**
- **呈现规范**：目标函数、约束条件按「1) 决策变量 2) 目标函数 3) 约束条件」顺序组织；公式全文连续编号、正文引用"由式(3)可得"；同一公式表达中并列多个等式/约束（含链式 `a=b=c`、逗号/`\qquad` 并列、以及仅用 `\quad`/`\qquad` 并列的若干约束或表达式组）用左花括号逐行排版、每行一个等式并共享一个式号（各等式要**左对齐**、齐左，用 ligned 每行以 & 开头实现齐左；不要用 \left\{...\right. 时把 & 放在等号/关系符前导致左边缘参差、整体居中）（不要求同一模型），需单独引用或分别推导才拆为独立公式；每个模型先说适用条件/假设再说数学表达；若多个候选模型，可显式对比后选其一（这种"模型比较"写法加分）。
- **求解呈现**：写清算法名称+工具+关键参数（如"模拟退火（初温 100、衰减 0.95、迭代 30000 次）"）；工具写清哪个解决哪步；复杂自研算法在正文编号与算法流程图之间选信息增益更高的表达；涉及随机算法时给出收敛性/稳定性说明（如 MCMC 收敛、模拟退火误差对比、遗传算法进化曲线收敛）；自研算法只在存在实质拓扑时用流程图。
**- 易错点（自查清单）**
只建模不求解（公式堆砌无数值）；求解过程黑箱（"用软件求解得…"要写算法与参数）；结果（图/表）无解读段；模型间无衔接、每问从零开始；参数表出现"/"或空缺；模型类型表述摇摆；公式前无理由直接罗列数学对象（叙事断裂、退回清单）。
### 结果呈现与分析

结果不能只报数 + 一句"方向合理"。**结果描述三段式（每问每个关键结果必须）**：`数值 → 机理 → 决策含义`——数值（带单位、精度 2~3 位小数、口径说明）；机理（为什么是这个数，对应哪条机制/策略）；决策含义（翻译回题目/决策者语言）。至少"机理"与"决策含义"缺一不可。
- **灵敏度结果必须解释"为什么敏感/不敏感"**：每个参数扫描给出敏感性排序、机理归因（为什么这个参数敏感/不敏感，与策略结构挂钩）、方向解释（为什么正/负）、临界/边界观察（是否存在策略切换点）。反例（禁止）："变化 ±19%，方向合理"——没有归因、没有结构挂钩。
- **大表必须给读表指南**：超过 6 行的结果表，表后解读指明先看哪一行/哪一列、行与行之间差异模式、表内数字与前面策略特征的联系。禁止整表只有一句"见表 X"。
- **鲁棒性分析必须展开**：不只报"变化区间+通过标准"，还要解释波动为什么小（模型结构：冗余购买、约束主导、最优解平坦区）、指出最坏情形、通过标准选取依据（为什么 ≤5%/≤1% 合理）、若不稳健如实讨论原因（示弱也是加分项）。
- **异常与反直觉结果**：存在异常、边界或反直觉结果时，如实指出现象、可能机制和验证证据；没有真实异常时不为形式完整虚构“反直觉结果清单”。
- **结果与机理/策略/图表联动**：灵敏度数字回链策略结构；每个图后 2~4 句解读（看图指南：看哪条曲线、哪个拐点、对应哪段策略）；结果章节引用前面公式/表格时说明"为什么这个机制导致这个结果"。
- **验收自检**：每问每个关键结果有数值/方案、机理和决策含义；灵敏度对实际选择的参数给出排序、归因、方向与稳定区间；大表有读表指南；鲁棒性有波动解释、最坏情形与标准依据；真实异常得到解释；每张图有 2~4 句解读；全文无"方向合理"式空话结尾。


### 模型评价与推广

是收束段，不是第二个结果章。通常半页至一页，原则上不超过正文的 3%--5%。结构固定为该章内**依次三节**（编号随本章实际章节号变化，不写死为 7）：

- **X.1 模型的优点**（优点说充分）：用编号列出被结果支持的优点，常见落脚点——① 模型/思路简洁实用、效率高；② 针对性强、有创新性（指出改造点）；③ 计算结果准确、精度高；④ 考虑系统全面、实用性强；⑤ 经各类检验、稳定性高；⑥ 模型本身优点（无量纲、有界、目标透明等）。
- **X.2 模型的缺点**（缺点不回避）：编号列出至少一个真实局限，常见落脚点——① 受某因素限制、未考虑某情况而影响精度；② 考虑因素较理想、降低普适性与推广能力；③ 因考虑因素多导致模型较复杂、计算时间长、效率低；④ 模型本身固有缺点；⑤ 目标或边界上的局限。
- **X.3 模型的改进**：针对 X.2 的缺点逐条给出改进思路（不必求解），如算法升级、引入更多实际因素、做多目标/连续优化、并行/代理模型降耗时等；可附一句可迁移的推广方向。

> 注：X 为"模型评价与推广"所在章节号。在本工作流固定骨架中，模型的建立与求解为第五章，模型评价与推广通常为第六章，对应 6.1/6.2/6.3；若用户明确增加其它必要一级章节，X 随实际章节号顺延，不得在源文件中硬编码错误章号。

**原则**：优点说充分、缺点不回避；评价必须落在被结果或题面条件支持的证据上——不得重复模型公式、完整算法、结果表、灵敏度/鲁棒性过程或逐问结论；不得用"模型具有较强适用性""可广泛推广"等无条件判断；某优点无证据则删除，某局限不确定则改写为"待验证的限制"。


### AI 工具使用声明写作

每篇论文须在正文之后、参考文献之前设置该不编号小节（`\section*{AI 工具使用声明}`，不编入顺序序号）。**只能按以下模板，不得改动句式、不得改写成其它表述**：
> **AI 使用声明：**本参赛队在竞赛过程中使用了 AI 工具，主要用于【简要用途，如语言润色、代码调试等】，详细使用情况见支撑材料。
- **唯一模板**：句式固定为"本参赛队在竞赛过程中使用了 AI 工具，主要用于____，详细使用情况见支撑材料。"；方括号【简要用途…】仅替换为实际用途（如"模型推导、数值求解与文字编辑"），**不得增删句子**、不得改成"未使用 AI 工具"等其它说法、不得在声明中堆字数、加结论或评价。
- **位置**：置于参考文献之前（正文之后、参考文献之前）；AI 使用详情只放支撑材料《AI 工具使用详情.pdf》，附录不重复设置说明小节。
- **匿名**：声明中不得出现参赛者身份、学校、赛区信息。
- **机检**：`audit_submission_language` 对该节用 `% language-audit: allow-start` / `% language-audit: allow-end` 包裹（唯一豁免），其余正文的禁用表达不因涉及 AI 而豁免。

### 参考文献写作

参考文献是论文的组成部分，原则是"**只收录实际引用且可核验的来源**"，不作为凑篇幅或展示的工具。要点：

- **收录范围**：只收录正文**实际引用且可核验**的文献来源；与论证无关、或未被正文引用的文献不列入。
- **编号与标引**：**按引用顺序编号**（`\bibitem` + 正文 `\cite`），并在正文首次引出处标注；参考文献本身**不加顺序序号**（用 `\section*{参考文献}`）。
- **引用显示为右上角上标（硬性）**：正文的 `\cite` 引用要显示为**右上角上标**（如 `[3]`、`[1,2]`，含方括号），不是正文同行的下划线/普通行内文字。实现可 `\renewcommand{\cite}[1]{\textsuperscript{[#1]}}`（适用于 `\bibitem{编号}` 的键即为序号的情形），或 `\usepackage[super]{natbib}` 并确认输出带方括号的上标；`\cite{1,2}` 应合并为上标 `[1,2]`。终稿逐处核对：凡正文出现 `\cite` 处，引用都须是上标且带方括号。
- **中文文献比例（硬性）**：无用户或题目特殊要求时，中文权威文献占全部有效参考文献的比例**不得低于 60%**，并明显多于外文；所需中文条目数按 `ceil(0.60 × 有效条目总数)` 向上取整。比例按文末有效条目数计算，不按正文引用次数计算；不得通过加入与正文无关、低质量或重复的中文资料满足比例。优先使用中文标准、政府/行业资料、权威教材及与题目直接相关的中文期刊论文。
- **外文保留**：原始算法出处、国际标准、关键前沿成果，或国内无可靠替代的来源，保留外文引用。
- **真实性核验（硬性）**：每条文献至少核对作者或发布机构、题名、来源和年份；期刊论文按实际来源补齐卷、期、页码及 DOI（存在时）；网页与数据库必须指向具体内容页并写明访问日期，不得只列搜索引擎首页、数据库首页或“网络收集”。AI 推荐的文献必须回到真实原文核验，最终只引用真实来源，不引用 AI 工具；无法确认真实性的条目不得进入终稿。
- **著录格式统一**：同一论文统一使用顺序编码格式；按来源类型标注专著 `[M]`、期刊 `[J]`、会议论文 `[C]`、学位论文 `[D]`、报纸 `[N]`、报告 `[R]`、标准 `[S]`、专利 `[P]`、网页 `[EB/OL]`、数据库 `[DB/OL]`、法规政策 `[Z]`。作者、题名、来源、年份、卷期页码、网址和访问日期按相应类型完整著录，不混用多套标点与日期格式。
- **禁止**：为满足比例改引二手、低质量或与论证无关的中文文献；**编造参考文献**；把 ChatGPT、DeepSeek、Claude、GitHub Copilot 等 AI 工具列为参考文献；把参考文献条目当作排版注水。
- **位置与顺序**：参考文献置于"AI 工具使用声明"之后、"附录"之前，使用无编号标题。

**自检/机检**：每篇被引文献都在正文有 `\cite` 对应，且正文每个 `\cite` 都有对应条目；编号按首次引用顺序连续；无"参考文献"条目未在正文引用、也无正文引用而无条目；网络来源有具体网址和访问日期；无 AI 工具条目、无编造文献；中文权威文献占比按向上取整规则达到 60%。

### 附录写作

附录是完整论文的必要组成部分，必须用 `\clearpage` **单独另起一页**，总篇幅控制在 **9～11 页**，紧凑但不注水。结构固定为：先输出独立、可见、居中的一级标题"附录"，再 `\appendix`，随后按 **A、B** 两块展开（只有附录的二级标题采用 A、B，并且左对齐），不得增设 C、D、E 等其它附录分区。
- **A、支撑材料文件列表**（二级标题）：用表格列出实际提交的文件名称、格式、主要内容和对应问题或论文位置，并登记全部源程序文件名；文件列表须与支撑材料压缩包逐项一致（压缩包放全部完整可运行源码），不得列入不存在、已删除或未提交的文件。实现：`\clearpage` 后输出无编号一级标题"附录"，再执行 `\appendix`、`\renewcommand{\thesection}{\Alph{section}}`、`\ctexset{section/number={\Alph{section}、}}` 与 `\ctexset{section/format={\raggedright\heiti\zihao{4}\bfseries}}`，随后 `\section{支撑材料文件列表}`（显示为 "A、支撑材料文件列表"）。
- **B、主要的源程序**（二级标题）：只展示承担核心计算、能够产生论文主要结果的主要求解程序，不要求在论文附录展开全部辅助源文件；其余完整可运行源码在 A 的文件列表中登记并放入支撑材料压缩包。每份主要程序前简要写明程序名称、对应问题、主要作用、输入文件、输出文件和运行环境，并优先用 `\lstinputlisting` 引入支撑材料中的真实源文件，避免手工复制产生版本不一致。用 `\section{主要的源程序}` 显示 "B、主要的源程序"，保持四号黑体左对齐；`listings` 必须设置 `basicstyle=\ttfamily\zihao{5}`，中文注释字体须能正常回退显示。
- **环境与运行**：注明运行环境（Python 版本、依赖锁定文件）与一键复现命令；使用 Excel/SPSS 等交互命令时一并附上记录。
- **篇幅控制**：附录总篇幅必须控制在 9～11 页。少于 9 页时检查主要程序是否展示不足，不得用重复代码、无信息说明或空白注水；超过 11 页时优先精简非核心代码、无意义空行和调试注释，次要辅助模块只在 A 中登记并放入支撑材料。允许采用协调的紧凑代码行距控制篇幅，但不得使用小于五号的代码字号、删除核心逻辑或产生超出版心内容。
- **匿名**：附录任何位置不得出现参赛者身份、学校、赛区信息。
- **核对**：编译后逐页确认"附录"总标题确实出现，且两块标题为 A、B + 顿号；`audit_submission_language` 扫描 `.tex` 时，"禁用表达"**不适用于完整源代码、程序输出、公式变量名、文献题名或逐字引文**，若脚本误扫到 `\lstinputlisting` 引入的源码（如注释里的"生成"），应只查作者文字而非源码。

**注意**：附录"支撑材料文件列表"须与支撑材料压缩包内容一致（**支撑材料要求见「支撑材料写作」节**）；未使用 Excel/SPSS 时注明全部计算所用环境。

### 摘要写作
摘要必须在模型、代码、结果、检验和正文全部完成后最后撰写，是一篇能够脱离正文独立阅读的短文。首页固定包含论文题目、摘要和关键词三部分；摘要重点呈现全部问题、主模型与算法、可直接核验的结果、真实创新和适用边界。内容控制在 **800～1000 个汉字**并写满一页但不超过一页（一定不能超过一页）；关键词行底边须位于可打印版心纵向 78%～90%。

- **论文题目**：先确定全文主模型与研究对象，再拟题。优先采用`基于[主要模型/方法/理论]的[研究对象或核心问题]研究`，只突出最能代表全文的方法，不把次要算法全部堆进题目，不为追求新颖使用晦涩词；题目必须与正文实际模型和研究对象一致。
- **引言段（固定两句）**：第一句简要交代背景或现实意义，第二句自然引出需要解决的核心问题。通常控制在两句、约 3～4 行；不在引言段罗列数据预处理、模型体系、所有子问题目标、算法清单或完整技术细节。
- **逐问主体（硬性一问一段）**：按题面问题顺序，每个子问题独立一个自然段，不倒叙、不混写。每段按正文真实内容选择并组织：本问任务与必要的数据处理/假设 → 模型名称及数学类型 → 针对性建模思想 → 求解算法（软件只作工具说明，不能替代算法）→ 能直接回答题目的关键数值、排序、预测、方案或决策 → 适用的检验结论。上述内容是覆盖维度，不要求每问复制相同句式；问题间是否承接必须依据正文真实输入输出关系，不能因题号顺序虚构递进模型。
- **结果要求**：优先写能直接回答题面的量化结果，数值带对象、单位、统计口径和必要精度；输出本身为类别、排序、方案、判定或建议时，直接写相应答案，不得为了“每问有数字”虚构数值。摘要中的模型、算法、数据、结果和检验必须全部来自正文，并与正文、表格和结果文件一致。
- **收尾段**：总结正文有证据支持的针对性创新、模型优势、精度/稳定性/鲁棒性、适用范围、局限和改进方向，并说明必要的推广价值。正文未做相应检验时不得在摘要声称稳定或鲁棒；没有独立创新时可概括本题化变量、约束、模型组合或验证设计，不虚构“创新模型”。
- **关键词**：设置 4～6 个，优先覆盖三个方向：研究问题或对象、主要模型、核心算法/真实创新；按检索价值补充评价方法或应用领域。不得使用“研究”“分析”“方法”等过宽词，不把软件名称当核心关键词，不为凑数重复同义概念；分隔符全文统一。
- **语言与边界**：使用第三人称，以“本文”“该模型”等为主语，不用“我”“我们”；摘要中不放图、表、公式、参考文献编号和未经解释的非常用缩写，不写大段背景、代码步骤或参数清单，不使用“结果良好”“效果显著”“模型合理”等无量化依据的评价。关键信息可以少量加粗，但不得通篇加粗制造视觉噪声。
- **需要加粗的术语（少量、用于强调）**：摘要中提倡加粗的是“有信息量的术语/数值/结论”，通常包括——① 主模型或方法名称（如“纯方位无源定位模型”“基准四边形锚定”）；② 关键算法与求解方法（如“圆周角定理两圆相交”“Levenberg–Marquardt”“可辨识性分析”“固定点迭代”）；③ 能直接回答题面的核心结论（如“至少还需 2 架”“2 轮收敛”）；④ 带对象与单位的关键量化结果或指标（如“定位 RMSE≈1.35 m”“残差<10⁻¹³ m”）；⑤ 影响结论的关键假设或前提（如“发射机位置无偏差”“编号已知”）；⑥ 核心评价指标名（如“GDOP”“收敛轮次”）。不加粗整句、连接词、状语，也不加粗图/表/公式/文献编号；每问加粗 1–3 处即可，避免满屏加粗形成视觉噪声。
- **数值口径**：与常见口径不可直接比较时（如“成功优先、失败记 0”与确定性期望、含回收与不含回收），用简短括号注明口径；摘要、正文和表格的精度及单位保持一致。
- **段落与排版**：摘要段落数随子问题数量变化，固定为“一个两句引言段 + 每问各一段 + 一个收尾段”，不得用 3～5 段上限压缩多个问题到同一段。主标题与摘要标题均使用三号黑体、加粗、居中（`\heiti\zihao{3}\bfseries`），间距默认 `0.4em`；摘要正文使用小四号宋体（`\songti\zihao{-4}`），各段首行缩进两字符；关键词标签使用小四号黑体，关键词内容使用小四号宋体，关键词行允许 `\noindent`。禁止使用 `\vfill`、弹性空白、`\enlargethispage`、缩小页边距、异常放大标题、无信息句或手工换行注水；占用率不足时补充正文已有的关键结果、选模依据、检验证据和适用边界，不得补造内容。
- **交付前自检**：确认题目突出主模型与对象；引言恰为两句且未写成技术目录；全部子问题均一问一段；每段包含真实任务、模型/算法、可核验答案和适用证据；承接关系与正文一致；收尾没有无证据创新或稳定性主张；摘要无图表公式引用；汉字数为 800～1000；关键词为 4～6 个且覆盖问题、模型、算法/创新；`audit_abstract_page.py` 输出 `status=pass`，占用率为 0.78～0.90；所有数字、单位、模型名称和结论与正文一致。

### 附录与支撑材料接口

- 本 skill 不决定最终支撑材料范围、不生成压缩包，只负责撰写附录 A“支撑材料文件列表”和附录 B“主要的源程序”；最终内容、排除项、大小、SHA256、运行说明、AI 使用详情和压缩包由 `mm-verification` 统一负责。
- 附录 A 只能列项目中实际存在且准备提交的文件，至少写明文件名、格式、主要内容和对应论文位置；不得列入占位文件、临时文件或计划以后生成的文件。
- 附录 A 是最终压缩包的锁定清单。`mm-verification` 必须按该清单整理，不得静默增加、删除或改名；若验收发现文件集合必须变化，创建回写项，由 `mm-paper-writing` 更新附录 A、重新双遍编译论文并更新哈希后再打包。
- 附录 B 只展示主要程序，但其版本必须与最终支撑材料中的对应源文件一致；其余完整可运行源码只在附录 A 登记并由 `mm-verification` 放入压缩包。

## 工作流

### Step 0：输出格式（默认 LaTeX）

- **本 skill 默认且唯一输出 LaTeX**：`paper/论文.tex` + xelatex 编译 `paper/论文.pdf`，不再提供 Word/DOCX 排版路径。若用户明确要求 Word/DOCX，明确告知：Word 排版流水线已移除，需另用旧版工具或自行转换，不在本 skill 范围内。
- 写作前先确认本机已装 TeX 发行版（MiKTeX/TeX Live），用其自带的 `xelatex` 引擎编译（当前环境 xelatex 不在 PATH，需定位 MiKTeX 安装目录下的 `xelatex.exe`）；缺失时先安装，安装完成后再动笔。

> 结构规划（`paper/structure-plan.md`）由编排器建；图件清单（`paper/figure-requirements.md`）由编排器建骨架、`mm-figures`/`mm-graphics` 填内容；写作门禁初始状态（`paper/writing-gates.md`）由编排器初始化。本 skill 只负责终稿写作，并在写作前核对写作门禁。

### Step 0.25：初稿接管确认

- 若存在 `paper/draft-baseline.tex|pdf`，只读核对其 SHA256、可编译状态和 `draft-audit.md`；初稿只作为最低权威的语言与排版素材，题面、`docs/02`、`docs/03`、`results/`、图件报告和 manifest 依次优先。
- 不得直接把 `draft-baseline.tex` 复制成终稿后只做局部润色。必须新建 `paper/论文.tex`，仅吸收 `draft-audit.md` 标记为“保留”的内容；“改写/删除/补充”逐项落实。
- 若初稿整体失效，保留基线并按 `invalidated` 处理，从上游报告重建；若无初稿，按 `none` 走全新写作，但仍执行页面预算和多轮审计。
- 第二次调用时，第一次调用生成的 `paper/论文.tex|pdf` 是待独立终审的当前终稿，不得改名为 `draft-baseline`，也不得重新执行初稿接管改名逻辑；原始 `draft-baseline.*` 仍保持只读。

### Step 0.5：写作前门禁（GATE，防止跳步）

**未通过下列任一 GATE，不得开始撰写正文。** 每项必须在 commentary 输出 `PASS + 证据`，并写入 `paper/writing-gates.md`（表格：检查项 | 证据 | 结果）。GATE 是流程硬门禁：发现 G-1~G-5 任一未满足，立即停下补齐，不允许带着缺口继续。

| GATE | 检查内容 | 通过标准 |
|---|---|---|
| G-1 必读已读 | 完整读取本 SKILL 的六类规则：①摘要；②问题重述与问题分析；③模型建立与求解；④结果、检验与评价；⑤字体、图表与LaTeX；⑥AI声明、文献、附录和支撑材料 | `writing-gates.md`逐类记录核心结构、内容边界、数量/页数、字体格式、对应机检及本 SKILL SHA256；任一类缺失不得 PASS，禁止只引1～2条代替完整阅读 |
| G-2 图表齐全 | 按 manifest 检查适用的 `figures/`、`docs/04`、`docs/05-diagrams-report.md`、`docs/05-visual-report.md` | 列出实际文件清单；按 `paper/figure-requirements.md` 核对适用的非数据图（视觉示意图仅在非 `n_a` 时要求）；缺图或写作中临时新增图，先回写对应 skill |
| G-3 上游数据 | `docs/02` 公式/符号、`docs/03` 结果已核对 | 说明每问公式与结果来自哪个报告小节，禁止凭空写数 |
| G-4 结构拟定 | 正式策划和初稿审计已完成 | `draft-audit.md`/`draft-metrics.json`存在，`page-budget.json`目标为28～29且各章预算闭合，`validate_paper_plan.py` exit 0；每问论证链、真实来源、证据ID、最终回答与图件锚点齐全，无占位符 |
| G-5 工具就绪 | xelatex/MiKTeX 可用，`paper/` 存在 | 定位 `xelatex.exe` 路径或确认已安装 |

论文终稿开始前，`paper/writing-gates.md` 和 manifest 的 `paper_gates` 必须全部 PASS 并随论文保留；验收阶段据此反查跳步。

### Step 1：确认结构与排版要求

- 写作前完整读取本 SKILL 的公共要求、章节规范、图表格式和跨阶段不变量，确认页边距、页数、页码、附录和匿名要求。
- 运行 `python <mm-orchestrator目录>/scripts/validate_paper_plan.py paper/page-budget.json --root .`，确认 `paper_plan.status=complete`；失败时停止写作并返回论文策划阶段，不得在终稿阶段临时猜测页面分配。
- 固定按 CUMCM 2026 结构与中文论文规范执行，见本文"整体八段式骨架"，并以编排器产出的 `paper/structure-plan.md` 为章节骨架与逐问论证链。若用户提供官方模板/格式要求，以官方为准并记录覆盖原因。
- 确认摘要排版目标：主标题与摘要标题均为三号，整页但不过页、加粗关键方法/结论、无目录、页码从摘要页起；官方模板或用户另有明确字号时记录覆盖原因。

### Step 2：规划各节内容来源

按 `paper/structure-plan.md` 的章节骨架，把每个章节映射到上游报告与图表，避免凭空编造：

| 章节 | 内容来源 |
|---|---|
| 摘要 | 综合全部报告，见本文"摘要写作" |
| 问题重述 | `docs/01` 问题重述 |
| 问题分析 | `docs/01` 问题分类/建模方向（逐问分析 + 技术路线图） |
| 模型假设 | `docs/02` 模型假设 |
| 符号说明 | `docs/02` 符号表 |
| 模型建立与求解 | `docs/02` 公式 + 求解步骤 + `docs/03` 结果（每问内嵌结果表与结果分析） |
| 模型对比 | 仅当适用：`docs/02` 对比方案 + `docs/03` 对比结果 |
| 模型检验/灵敏度/鲁棒性 | 仅当适用：`docs/02` 方案 + `docs/03` 结果 |

### Step 3：撰写正文

- 从新建的 `paper/论文.tex` 开始，按 `draft-audit.md` 吸收有效初稿内容；不得直接覆盖或改名初稿基线充当终稿。
- 章节结构遵循本文"整体论文骨架"；语言遵循"去 AI 味与讲好故事"硬性要求，详见 `references/去AI味与故事线-必须遵守.md`。
- 写"某问建模与求解"前，必须先完整读本文"模型建立与求解写作"节，不得跳过或只读简介。
- 公式、符号与 `docs/02` 一致；求解表达根据内容采用连续段落或普通编号，复杂自研算法可使用流程图。
- 插图按 `docs/04`、`docs/05-diagrams-report.md`、`docs/05-visual-report.md` 说明插入，图注/表注全文连续编号；结果表用三线表。写结果与插图前必须先读本文"图表与格式"。**写正文前先核对 `figures/` 与 `docs/04`/`docs/05` 是否齐全**，缺图或写作中临时发现新图需求时，先停止该处撰写、回写对应画图 skill，待图产出并更新报告后再继续；不在本阶段自行生成。
- 流程/框架图优先用 `\includegraphics` 插入 `mm-graphics` 生成的矢量 PDF；600 DPI PNG 只作兼容与核查备份。插入后按实际版心复核最终字号与线宽。
- 模型对比、灵敏度、鲁棒性和检验只在适用时写入，可内嵌于对应论证位置，不强制独立小节；动态、空间演化或迭代题写入关键状态结果。
- **表格数字核对**：每张结果表写完后，与 `results/` 对应文件逐项核对（易错列：LOOCV-RMSE、标准化系数、$p$ 值、百分位区间、logdet/方差等），发现不符立即修正。
- **章节归属检查**：图表插入后确认其位于对应问题章节内（不得跨章节错位），提交前通读目录结构核对一遍。
- **关键汇总表位置**：数据审计表、符号表和核心结果汇总表紧跟首次引出文字，并排在同节大型图片之前。默认 `[htbp]`；编译后若因浮动竞争脱离引出段、落到无关图片之后或形成孤立浮动页，只将该关键表改为 `[H]`，不得把全部表格机械锁位。
- **问题分析与数据预处理分离**：问题分析章可以概括数据来源、可用性、质量风险、必要处理方向及其理由，但不写具体缺失率、异常值数量、处理参数、特征构造结果或描述统计结果。多问共享同一数据时，在模型章最前设置条件性的公共数据处理二级标题；各问数据独立时分别写入对应问题；部分共享时采用“公共处理 + 问题专属处理”。
- **推导链自检**：每问模型建立必须形成闭环推导链——变量定义 → 基础公式（给出机理/统计/数据形态来源）→ 本题化改造 → 目标与约束；纯经验公式必须说明来源，后一条公式须解决前一条公式尚未解决的困难；写完模型节后逐条自检"这条公式从哪来、为什么需要它"。
- **求解展示方式**：成熟求解器简洁但完整地写明模型性质、算法/求解器、软件版本、关键参数、容差或终止条件、求解状态和输出；常规算法用连续段落或普通编号说明输入、核心步骤和输出；智能优化或复杂自研算法进一步说明编码、初始化、目标/适应度、更新规则、参数来源、随机种子、独立运行和收敛证据。只有具有实质分支、循环、状态更新或终止机制的复杂自研算法才使用流程图；不得给每问机械设置相同的"求解流程"小节。
- **反模式**：四问小节标题完全一致（如每问都出现"建模思路"）即模板化；承接段不设标题，小节标题随问拟定。
- **问题重述与分析的自然篇幅**：问题背景和逐问重述按题目数量、对象复杂度及输入输出边界自然展开，不设置最低占页率；`1.1 问题背景`不得只写可替换到任意题目的短套话。问题分析只有在缺少任务边界、数学类型、主要困难、数据条件、方法依据、跨问依赖、验证方式或交付形式时才补写，不得为填页重复题意。具体执行本文"问题重述写作"与"问题分析写作"。

### Step 4：生成论文（LaTeX）

**LaTeX 路径（默认）**：
- **前置检查**：本机必须已安装 TeX 发行版（MiKTeX/TeX Live），并使用其自带的 `xelatex` 引擎（当前环境 xelatex 不在 PATH，需从 MiKTeX 安装目录调用 `xelatex.exe`）。若未安装，先装；无法安装时暂停并告知用户，不得以未编译的 `.tex` 充当最终交付。
- 生成 `paper/论文.tex`（ctexart / xelatex），结构同 Step 2 规划，公式用 `equation` 环境自动编号、正文 `\eqref` 交叉引用；凡同一个公式表达中原本会用逗号、分号等并列书写多个等式，均用 `equation` 内嵌 `aligned` 与左花括号逐行排版，每行一个等式，整体只保留一个式号；需要逐条引用或分别推导的公式才拆分编号；三线表用 `booktabs`；插图用 `graphicx` 并 `\graphicspath{{figures/}}`。
- **内部多轮要求**：完成全部正文并最后写摘要后，至少双遍编译；随后依次运行页面长度、字体/表格/结构、引用、布局、摘要和语言审计。任一脚本失败都不得结束本次调用。正文页数不足或章节明显偏离预算时，生成/更新 `paper/content-gap-report.md`，按缺失的推导、参数来源、约束解释、算法细节、结果机理、检验、误差传播、最终回答和有数据依据的图表逐项补充，再次双遍编译和复检。
- 一级标题按中文序号手工或通过可靠的 LaTeX 编号配置显示（"一、""二、""三、"…），非顺序标题使用无编号命令（如 `\section*{参考文献}`、`\section*{附录}`、`\section*{AI 工具使用声明}`）；编译后逐页核对标题显示，禁止出现"1、问题重述"或"九、参考文献"这类混用。
- **LaTeX 固定排版要求**：
  - `\documentclass[12pt,a4paper]{ctexart}` + `\usepackage[margin=2.54cm]{geometry}`；导言区必须显式写入 `\setCJKmainfont{SimSun}`、`\setCJKsansfont{SimHei}`，并在正文开始时使用 `\songti\zihao{-4}`，确保小四号宋体正文而不是依赖默认字体。
  - 摘要独占一页（`\newpage`）、页码从摘要页起（`\pagenumbering`/`\thispagestyle` 控制，页脚中部从 1 起）；摘要后的正文各章节连续自然排版，不因章节标题另起一页；附录可在前文结束后另起页；
  - 摘要页主标题必须使用 `{\centering\heiti\zihao{3}\bfseries ...\par}`，摘要标题使用 `{\centering\heiti\zihao{3}\bfseries 摘\quad 要\par}`，摘要正文使用 `\songti\zihao{-4}`；关键词行使用 `\noindent{\heiti\zihao{-4}关键词：}{\songti\zihao{-4}关键词内容}`，两标题间距默认 `0.4em`。
  - 通过 `\ctexset` 固定标题字体：`section` 使用居中的 `\heiti\zihao{-3}`，`subsection` 使用左对齐的 `\heiti\zihao{4}`，`subsubsection` 使用左对齐的 `\heiti\zihao{-4}`；有编号和无编号标题均适用。AI 工具使用声明、参考文献和附录总标题均使用无编号一级标题，保持小三号黑体居中。
  - 附录前正文使用小四号宋体；图题、表题使用小四号宋体，可用 `\DeclareCaptionFont{cjkcaption}{\songti\zihao{-4}}` 与 `\captionsetup{font=cjkcaption}` 强制；所有 `tabular`、`tabularx`、`longtable` 表内文字使用 `\songti\zihao{5}`。附录总标题小三号黑体居中，A/B 二级标题四号黑体左对齐，三级标题小四号黑体，说明正文小四号宋体，源码 `listings` 基本字体为 `\ttfamily\zihao{5}`。
  - 正文单倍行距、**两字符首行缩进**，相邻正文段落额外间隔约 `0.25\baselineskip`；**禁止用 `\noindent` 让新段落不缩进（`\noindent` 仅限关键词行），`\paragraph{}` 小标题后的正文仍须缩进（见公共要求 #18）**。
  - 不设页眉：必须显式 `\pagestyle{plain}`（页码在页脚中部）或 `\pagestyle{empty}`（仅用于演示草稿）；
  - 无目录；正文 ≤30 页；附录用 `\clearpage` 单独另起一页，总篇幅控制在 9～11 页，固定包含 A、支撑材料文件列表和 B、主要的源程序；附录只展示主要源码，其余完整可运行源码在支撑材料中提供；全文匿名；
  - 单页图表默认使用 `[htbp]`；一级标题边界使用 `placeins`，并在每个 `\subsection` 前执行 `\FloatBarrier`，禁止图表跨入下一小节。顺序保持"文字引出 → 图表 → 解读"。确需跨物理页面的长表改用 `longtable`，按本文"跨页续表排版"设置续表，不得嵌套在 `table` 中。
- **排版间距与留白控制**：图表与正文之间不得留下大段空白。先判断空白来自文字篇幅失衡、浮动约束、图表锚点还是图件尺寸，不预设"优先缩图"；默认 `[htbp]`，一级和二级标题边界均使用 `\FloatBarrier` 防止跨节漂移。图片缩放必须保持标签清晰、比例协调，不得把图缩到难以阅读。
- **相邻证据组留白审计**：表格与其直接对应的图（或图与对应表）若在源码中连续出现、共同支撑同一结论，编译后必须作为一个局部证据组检查。若独立浮动导致表后或图前出现明显空白，且当前页剩余空间足以容纳两者，应优先把该组关键表/图局部改为 `[H]` 或合并为同一排版块；不得只凭"仍在同一小节"判定通过。逐页核查相邻表图之间的空白比例。
- **前部改写回归检查**：改动问题背景、问题重述、问题分析或其他位于浮动体之前的文字后，必须双遍编译，并从改动页连续检查到首张后续关键表。至少核对图文顺序、孤立图页、大块无效留白、关键表页码与首次引出位置；不得只检查改动段本身。
- **局部修复顺序**：先审计相邻文字——缺少问题要害、证据、选择理由或交付边界时补充实质内容；存在重复题意、可合并句子或应移至其他章节的细节时删减压缩。若改变图片大小不适用、会损害可读性或不能解决空白，允许通过有依据的增写或减写平衡分页。文字已完整紧凑时，再调整图表锚点/叙事顺序、浮动参数、关联图组合和可读范围内的局部尺寸。禁止为排版编造内容、重复注水、删除必要论证，或改变全局字号、行距和页边距。
- **表格字号与对齐（含字体泄漏）**：表内文字统一五号宋体（`\songti\zihao{5}`，10.5pt）；表头、文字和数字全部水平居中，长文本使用 `>{\centering\arraybackslash}p{}` 或等价定宽列自动换行；使用紧凑列距与行距，禁止为消除溢出擅自缩小字号。**硬性**：`longtable` 或章节级表格结束后必须立即恢复 `\songti\zihao{-4}`，不能只写 `\normalsize` 而遗留错误字体族；浮动表也应把宋体五号限定在局部分组内。终稿须实测正文为小四号宋体，表内为五号宋体，不得发生字号或字体族泄漏。
- **表格浮动与跨页**：单页表格默认 `[htbp]` 并受一级、二级标题边界的 `\FloatBarrier` 约束；只有必须锁定在解释段后的关键表才使用 `[H]`。确实无法单页容纳的表格允许用 `longtable` 跨页，按本文"跨页续表排版"设置：首页正常表题；续页"续表 N　原表题"；续页重复完整表头与单位；非末页标"续下页"；仅末页使用 `\bottomrule`。续页沿用原编号且不重复进入表目录，整张长表必须在同一小节内结束。
- **表格位置复核**：逐表比对"首次正文引用页 → 表题页 → 下一小节标题页"；关键汇总表不得晚于同节的大型图片，不得单独漂到下一页下半部或浮动专页。发现异常先调整源文件叙事顺序，再按需对单张关键表使用 `[H]`。
- **图片位置复核**：逐图比对"首次正文引用页 → 图题页 → 下一小节标题页"，确认图片位于对应问题和小节，且顺序为"文字引出 → 图片 → 实质解读"。关键图片不得脱离引出段、形成孤立图页或漂到下一小节；异常先调整叙事顺序和锚点，再在可读范围内调整浮动参数与局部尺寸。
- 编译验证：`xelatex -interaction=nonstopmode -halt-on-error paper/论文.tex` 产出 `paper/论文.pdf`；编译必须通过（无未定义引用、无缺图），若中文缺字检查 ctex/字体配置。
  - **语言门禁**：编译前运行 `python <mm-paper-writing目录>/scripts/audit_submission_language.py paper`，扫描 `paper/` 下的 TeX 正文源文件。出现禁用表达时，按本文"语言自然化与去 AI 味"第 8 节改写并重跑；只有官方规定的 AI 工具使用声明可用 `language-audit: allow-start` 与 `language-audit: allow-end` TeX 注释包围后豁免。不得用豁免标记包围其他正文。
  - **字体/表格/表题/模型章结构门禁（硬性）**：编译后运行 `python <mm-paper-writing目录>/scripts/audit_paper_tables.py paper/论文.tex`，**PASS 以脚本 exit 0 为准**。该脚本强制：① SimSun/SimHei 字体系统、正文/标题/图表题/表格/源码的固定字号与字体族；② 表题/图题标签为 "表1 标题 / 图1 标题"；③ 表格列全部居中；④ 符号说明只允许一个规范 `longtable`；⑤ 表内文字五号宋体（`\songti\zihao{5}`）；⑥ 三线表；⑦ `\end{document}` 恰一次；⑧符号表只收录跨章节核心量；⑨模型章允许条件性公共数据处理且问题小节按题面顺序；⑩公式多等式左花括号。任何 FAIL 必须修正后重跑，禁止只写"已核对"或手写 PASS。
- **人工冷读门禁**：语言脚本通过后，逐节按"本节要解决的具体问题是什么 → 证据来自哪里 → 为什么得到这个判断 → 该判断如何服务题目"冷读。若删去一段后论证、边界或证据没有损失，删除该段；若读者需跳回上游报告才能理解变量、公式或结论，补足正文中的必要连接。此门禁不能由关键词脚本替代。
- **题面追踪门禁**：提交前逐条核对题面要求追踪表。每个 `P-##` 子问题必须至少对应一个明确的模型、结果和结论落点；每个正文核心段落必须能指出其服务的 `P-##` 或 `REQ-###`。发现"写得正确但没有回答题目"的内容时删除或改写；发现题面要求没有模型、证据或结论承接时，回补对应内容后再交付。

- **版面机检（硬性）**：编译产出 PDF 后运行 `python <mm-orchestrator目录>/scripts/check_layout.py paper/论文.pdf`，**PASS 以脚本 exit 0 为准**（检测页内大段空白/凑篇幅留白、孤立图/表页即图表与正文不相邻）；FAIL 需调整排版、浮动锚点或文字篇幅，直到 PASS。
