# 建模与求解章节写法（操作规范）

> **本文件是"模型的建立与求解"章节写作的唯一操作规范**（兼含 28 篇语料统计与六篇优秀论文拆解作为论证依据），冲突时以本文件为准。

> **来源**：基于 28 篇国赛优秀论文语料（2020–2025）统计的共性规律，以及六篇优秀论文"模型构建与求解"部分的深度拆解（商超蔬菜定价补货、古代玻璃成分分析、企业原材料订购运输、NIPT 检测决策、生产检测拆解决策、同心鼓）。
> **定位（重要）**：本文是**论证思路与写作原则库，不是可套用的模板**。写"某问建模与求解"前**必须完整读本文**；写作时按题型、题面、数据形态现场组织，环节可缺、可并、可换顺序，只要**论证逻辑闭环**即可。判题人看的是"思路对不对、论证顺不顺"，不是"小节齐不齐"。

## 1. 每问内部流水线（28/28 篇一致）

```
问题分析/求解思路（1–3 句，说清要建什么模型、为什么）
  ↓
模型建立（变量/假设/目标函数/约束，公式编号）
  ↓
模型求解（算法 + 工具 + 关键参数）
  ↓
结果（表格汇总 + 图 + 1 段结果分析）
```

- 缺一环即扣分点：**最常被忽略的是「求解思路」与「结果分析」**——只给公式不给求解过程、只给表不做分析。
- **求解环节的篇幅**：成熟求解器只需简述模型性质、工具、关键参数与结果；复杂自研算法可用连续段落、普通编号或流程图交代实质分支、循环、状态更新和终止机制。
- 结果必须落成**表格**（语料中每问末尾都有结果表），纯文字列数字不算数。
- **"问题分析/求解思路"的位置与篇幅**：这里的 1–3 句是**承接性短句**（承接章节层面"问题分析"章，用"由问题分析可知……"带过），**不是独立小节、不设标题、不复述**问题分析章已讲的问题本质与选型理由。若问题分析章已充分论证"为什么选该模型"，每问内部这一环可缩减到 1 句或直接省略，从"模型建立"开始。同一句话在两个位置出现即冗余。

## 2. 通用铁律（六篇共识，换题不变）

1. **模型链思想**：前一个模型的输出 → 后一个模型的输入/依据。写论文要显式写出衔接，不靠读者自己看；否则就是"模型堆砌"。
2. **公式前必有理由**：不直接放公式，先回答"为什么需要它"（五种引公式方式见 §4）。理由的长短随题而定，机理题多推、优化题点到即可。
3. **分模块建模**：复杂目标/成本/收益先按经济或物理含义拆成子模块，逐个建立，最后求和合并。
4. **模型与算法分开**：模型回答"什么方案最好"，算法回答"怎样找到"；先判断模型性质，再选算法。
5. **篇幅分配：建模推导与结果分析占大头，求解简要**。求解小节通常只写"模型性质 → 求解器/算法 → 关键参数与结果"，把笔墨留给"模型怎么建"和"结果怎么解读"。
6. **求解写法分两类**：成熟求解器简要说明；复杂自研算法根据内容使用连续段落、普通编号或算法流程图，只呈现有实质意义的初始化、分支、更新与终止机制，不贴真实代码。
7. **求解 ≠ 结束**：求解后必须"检验 → 解释"。检验手段随模型类型而选，不强行统一。
8. **结果翻译回题目语言**：最优值/参数/类别 → 谁、何时、做什么的实际决策。
9. **主观参数 → 扰动 → 稳健性**：凡模型含人为设定参数（权重、阈值、先验），扰动后观察结论是否改变。

## 3. 模型构建的叙事逻辑（讲故事原则）★

模型构建**不是数学对象的清单罗列**（"变量定义→目标函数→约束①~⑥"），而是一条**有前因后果的情节链**：让读者顺着"为什么会出现这个数学对象"一路走下去，像读故事一样抵达"模型成形"。这是"公式前必有理由"在整章尺度上的升级。

**故事线骨架（按题组织，非固定章节）**：

```text
开场      → 这个场景要解决什么问题（背景 + 最终目标，1–3 句）
规矩      → 现实规则逐条摆出（物理规律/经营约束），即约束的由来
主角      → 方案到底决定什么 → 决策变量（因为要决定 X，所以定义 z）
铺垫      → 决定之后怎么算收益/效果 → 参数从哪来（题目/数据/前序模型）
冲突      → 难点或特殊处理（卖不掉怎么办、参数不确定怎么办、相关怎么办）→ 引入分段/随机/相关等"本题化改造"
成形      → 目标 + 约束汇总，模型完整（"综合上述……建立如下模型"）
```

**写作要领**：

1. 每个数学对象的出现都有"前因"：先讲困境再给公式，公式是叙事的落点而不是起点。
2. 用因果连接词串逻辑：因为……所以……；为了……需要……；然而……；由此……。
3. 约束按故事顺序讲，不按数学类型罗列：按决策的自然顺序逐条引出，而不是把约束堆在一起编号。
4. 冲突（特殊处理）是叙事的核心：要写出"为什么会遇到这个矛盾、两种处理分别意味着什么"。
5. 收尾要"成形"：所有元素汇聚成完整模型时，明确说"由此得到如下 0-1 整数规划/随机规划模型"。
6. 判断标准：删掉任一环节后，读者是否还能顺着"为什么这样建模"走下去；不能，说明叙事断裂、退回了清单。
7. 创新点/关键设计要给足篇幅：按"现实困境 → 为什么这样设计 → 不这样做会怎样 → 这样做带来什么"讲透，宁可长不可略；篇幅紧张时砍常规环节，不砍创新点。

> **⚠️ 叙事是内在逻辑，不是表面文风**：
> - 禁止用故事化/口语化小节标题（如"主角""规矩""冲突"）——学术论文标题必须克制规范。
> - 叙事性只体现在段落内部的因果递进与小节的先后顺序上（先摆现实规则、再引出其数学化，先讲难点、再给处理）。
> - 小节标题一律学术式，如：符号与参数确定 / 目标函数的构造 / 约束条件的建立 / 模型汇总 / 模型求解 / 求解结果与分析。
> - 一句话判定：**标题像论文、段落像讲故事**。标题负责目录感，段落负责因果感。

## 4. 五种"引公式"方式（按题选，不必都用）

| 方式 | 逻辑 | 适用 |
|---|---|---|
| 从数据结构/问题特征引 | 普通方法违反什么假设 → 替代模型 → 数学形式 | 统计/优化题 |
| 从机理/业务引具体项 | 每加一项（二次项、交互项）都给统计/机理/数据依据 | 回归/机理建模 |
| 从模型适用性引 | 数据特点 → 模型特点 → 选型理由 | 所有题 |
| 从业务指标反推数学定义 | 自然语言目标 → 可计算量（如"最佳时点"→"至少 α 比例达标的最早孕周"） | 把模糊要求变可算 |
| 从优化目标引目标与约束 | 现实要求逐条 → 目标函数 → 约束 → 合并 | 优化题 |

## 5. 公式六层（写作时按需定义，不是只放一个大公式）

数据处理 / 变量定义 / 主模型 / 目标损失 / 约束 / 检验评价——需要哪些数学对象就依次定义哪些。原则：**公式必须承担至少一种作用，否则不写**。哪几层出现、各占多少篇幅，完全随题。

## 6. 模型选型：题目类型 → 模型（语料高频组合）

| 题目类型 | 高频模型/方法（语料中出现） |
|---|---|
| 机理/几何类（A/B 物理工程题） | 坐标系与坐标变换、反射定律、几何推导（正弦定理/向量叉乘/线面角）、光学效率连乘、微元法 |
| 优化类 | 单目标优化（目标=某指标最大化/最小化）、多目标（主要目标法/NSGA-II）、整数/0-1 规划、动态规划、背包模型 |
| 预测类 | 时间序列（ARIMA/VAR/温特斯乘性）、回归（双对数/最小二乘）、LSTM、Prophet、灰色 GM(1,1)、贝叶斯（MCMC） |
| 评价类 | AHP、TOPSIS、灰色关联、熵权、VIKOR、聚类（K-means++ / CURE） |
| 数据类（C 题） | 描述统计、相关性（Pearson/Spearman）、异常值（IQR/3σ）、关联规则（FP-Growth）、分类（随机森林） |
| 求解算法 | 贪心、模拟退火、遗传/粒子群/飞蛾火焰、变步长/三分/二分搜索、蒙特卡洛、遍历/穷举、最小二乘拟合、蚁群、差分进化 |

- **同一问内模型不宜堆砌**：每道子问基本 1–2 个模型体系；一篇论文总模型数 3–6 个合理。
- 常见获奖套路：**逐问递进**（28/28 篇逐问展开，多数显式递进）——问题一建基础模型，后续问题在上一问模型上扩展（二维→三维、单目标→多目标、简单地形→真实地形），并显式说明「在问题一模型的基础上」。
- 机制题（2023 A 类）常见「机理建模 + 数值离散化（栅格/光线追迹）+ 搜索算法」组合：机理保证严谨，离散化保证可算，搜索保证寻优。

## 7. 分题型：不同的常见论证路径（示例，非唯一）

- **优化题**（商超/原材料/生产/C 题同构）：拆问题 → 定义决策变量 → 构造指标/参数（正向化/归一化）→ 目标函数 → 逐条约束 → 汇总模型 → 按模型性质选算法（精确求解器优先）→ 求解 → 结果解释。
- **数据/统计/分类题**（玻璃/NIPT 同构）：识别数据结构（成分/时序/缺失/高维）→ 数据有效性筛选 → 适配模型的数据变换（说明"为什么"）→ 模型适用条件检查 → 按问题类型选模型 → 训练/测试分离与评价 → 异构交叉验证 → 敏感性分析。
- **物理机理题**（同心鼓同构）：过程分阶段 → 受力/几何分析 → 基本定律 → 状态方程+初始条件 → 小参数近似线性化 → 求解 → 模型出问题→修假设 → 策略输出 → 多目标约束检查。
- **概率/序贯决策题**（生产决策同构）：现实随机机制 → 随机变量/分布（分布必须来自随机过程）→ 期望成本/收益（分模块）→ 优化目标 → 枚举或动态规划 → 参数不确定性（先验→后验→期望化）→ 灵敏度。

**判断标准**：路径是否顺应题目的递进逻辑（确定性→不确定性→相关性 / 描述→分类→验证 / 理想→误差→修复→控制），而不是"有没有按某个模板写"。

## 8. 模型修复范式（发现模型出问题时）

```
模型结论不符合实际/无解 → 检查关键假设（不是急着换模型）
→ 放宽/修正假设 → 建立改进模型（最小幅度修改，只动受影响部分）
```

典型：同心鼓"小拉力无实解→瞬时碰撞假设过强→引入碰撞时间 $t_0$"；生产决策"确定 $p$→升级为 Beta 后验"。

## 9. 参数不确定性范式（确定→分布→期望化）

```
确定性模型（参数为常数） → 将参数视为随机变量（分布来自题面区间/共轭先验）
→ 情景/后验抽样 → 对目标函数求期望 → 重新优化 → 与确定性结果对比 → 主观参数灵敏度
```

写论文时显式写"在问题一模型基础上，将确定参数升级为随机变量"，体现模型继承。是否用、怎么展开，随题面是否含不确定性而定。

## 10. 模型建立的呈现规范

- 目标函数、约束条件按「1) 决策变量 2) 目标函数 3) 约束条件」顺序组织（2023 A175 等采用），评审能快速定位。
- 公式**全文连续编号**（式 1、式 2…），正文引用「由式(3)可得」。只要同一个公式表达中包含多个用逗号、分号等连接的等式，就使用左花括号逐行排版、每行一个等式并整体共享一个式号；这不要求各行属于同一模型。若某行需要单独引用或分别推导，则拆为独立公式编号；公式组中的每一行仍须在行文中解释其现实含义与来源。
- 每个模型先说**适用条件/假设**，再说数学表达。
- 若有多个候选模型，可显式对比后选一（2023 B311 用 CAD 作图对比后弃一取一）——这种「模型比较」写法加分。

## 11. 求解的呈现规范

- 写清**算法名称 + 工具 + 关键参数**：如「模拟退火（初温 100、衰减 0.95、迭代 30000 次）」「LSTM（Adam、400 epochs）」。
- 工具在语料中出现：MATLAB、Python、SPSS（SPSSPRO）、EVIEWS、Lingo、Origin、R、OpenBUGS、Excel、geatpy/cvxpy（Python 库）。写清哪个工具解决哪一步。
- 复杂自研算法可在正文编号与算法流程图之间选择信息增益更高的表达。
- 涉及随机算法时给出收敛性/稳定性说明（如 MCMC 的收敛性、模拟退火的误差对比、遗传算法进化曲线收敛性——2024 C234 用进化曲线论证收敛）。
- 自研算法只在存在实质拓扑时使用流程图，否则用连续段落或普通编号，不贴真实代码。

## 12. 结果呈现规范

- 数值结果**保留 2–3 位小数**，带单位。
- 结果表设计：按问汇总；多区域/多情景时用汇总表（如 2023 B226 表 5 多区域汇总表）。
- 每张结果表后跟 1–3 句「结果分析」：说明数字的含义、与约束的符合度、异常原因，不要只贴表。
- 每张图必须有对应文字：图前一句引出"为什么要看这张图"，图后 1–3 句"从图中可以看出什么"；全文不允许孤图（正文未引用、或引用后无解读的图）。
- **结果四要素**：目标函数值 + 最优决策变量 + 图表 + 实际解释。
- 图表服务结论：参数关系图用于"参数解释 + 策略选择"，不只画计算结果。
- 策略输出操作化：数学结果翻译成"第几秒/哪块地/哪个决策单元做什么"。
- 结果分析四步：数学结果 → 统计/物理意义 → 现实意义 → 决策建议。

## 13. 每问内部：常见组织方式（参考，不是必须的小节清单）

```
建模思路/选型理由（可选：问题分析章已论证时直接承接一句或省略，不复述）
变量/符号定义（已知参数 / 预测参数 / 决策变量 分三类）
基础模型 + 本题化改造（"考虑到本题还存在……，因此引入……项"）
目标函数（先自然语言，再 min/max）
约束条件（逐条"现实要求→数学翻译→公式"，最后汇总）
参数确定（题目给定 / 数据计算 / 统计估计 / 前序模型输出）
模型求解（简要：模型性质→求解器/算法→关键参数与结果；自研算法才交代流程）
求解结果（表+图+关键数值）
结果分析（数学含义→实际含义→对题目的直接回答 + 验证）
```

- **⚠️ "建模思路"与"问题分析"章的分工（常见问题）**：问题分析章负责"问题本质、数据特点、为什么选该模型"的完整论证；每问内部若再设"建模思路"，只写**该问独有的选型论证**（普通方法哪里不够→为何选此模型），用承接句带过，**不得复述**问题分析已讲内容。问题分析充分时可直接省略该环节。

## 14. 思路链（思考/检查顺序，不是写作目录）

```
问题特征/数据特征 → 模型选择（理由） → 变量定义 → 基础公式 → 本题化改造
→ 目标函数 → 约束条件 → 参数确定 → 求解（怎么算、何时停） → 输出结果
→ 结果解释（翻译回题目） → 模型验证/灵敏度 → 评价
```

**核心判断标准**：每条公式是否回答一个明确问题，且后一条公式是否解决前一条公式尚未解决的困难。

## 15. 易错点

- ❌ 只建模不求解（公式堆砌，无数值）。
- ❌ 求解过程黑箱（「用软件求解得…」——要写算法与参数）。
- ❌ 结果表无分析段。
- ❌ 模型间无衔接，每问从零开始（逐问递进才有层次感）。
- ❌ 参数表出现「/」或空缺（2023 A175 设计参数表多处「/」是反例）。
- ❌ 模型类型表述摇摆（2023 A175 自陈「此处应该是多目标优化模型」）。
- ❌ 公式前无理由，直接罗列数学对象（叙事断裂、退回清单）。

## 16. 边界（最重要：不要当模板套）

- **没有通用模板**：六篇论文没有两篇结构相同。本文提供的是"论证思路库"，写题时按题型、题面、数据形态**现场组织**。
- **预测环节不可硬套**：题目给出参数区间/趋势时用情景抽样即可，不虚构"历史→时间序列预测"。
- **精确求解器优先**：LP/MILP 能精确求解的问题，不要为"像优秀论文"降级成 GA/SA。
- **预处理篇幅看数据形态**：结构化参数表短写；流水/时序/成分数据才详写。
- **模型组合看题目递进**：优化题是"确定性→不确定性→相关性"，数据题是"描述→分类→验证"，机理题是"理想→误差→修复→控制"——链条不同，论证逻辑相同。
- **小节粒度随篇幅**：篇幅紧则环节合并、不单独成节；篇幅宽则适当展开。小节数量不是得分点，论证完整才是。
