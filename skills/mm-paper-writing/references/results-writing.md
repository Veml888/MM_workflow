# 结果描述规范

> 背景：评委反馈"结果描述不行"。典型病根：只报数 + 一句"方向合理"、大表无读表指南、鲁棒性一句话带过、反直觉结果不系统化、结果与机理/策略脱钩。

## 1. 结果描述三段式（每问每个关键结果必须）

**数值 → 机理 → 决策含义**：

1. 数值：报结果本身（带单位、精度 2~3 位小数、口径说明：成功率/全部均值/成功均值）；
2. 机理：解释**为什么是这个数**——对应模型哪条机制、哪段策略（如"挖矿 7 天使资金台阶式上升"）；
3. 决策含义：翻译回题目/决策者语言（"如果我是玩家/运营方，最优做法是……"）。

禁止只写"数值 + 方向合理"。至少三段中的"机理"与"决策含义"缺一不可。

## 2. 灵敏度结果必须解释"为什么敏感/不敏感"

每个参数扫描给出三件事：

- 敏感性排序（谁主导、谁次要）；
- **机理归因**：为什么这个参数敏感/不敏感（与策略结构挂钩：挖矿天数、购买量、补给次数、资源消耗构成）；
- 方向解释：为什么是正向/负向（如"水价上涨→挖矿段补水成本上升→收益下降"）；
- 临界/边界观察：是否存在策略切换点（参数到某个值后最优策略形态改变），有则指出。

反例（禁止）："变化 ±19%，方向合理"——没有归因、没有结构挂钩。

## 3. 大表必须给"读表指南"

对超过 6 行的结果表，表后解读必须指明：

- 先看哪一行/哪一列（主导参数或关键对比列）；
- 行与行之间的差异模式（如"除初始资金外，其余参数扰动均 ≤7%"）；
- 表内数字与前面策略特征的联系。

禁止整表只有一句"见表 X"。

## 4. 鲁棒性分析必须展开

不只报"变化区间 + 通过标准"，还要：

- 解释波动为什么小（模型结构：冗余购买、约束主导、最优解平坦区）；
- 指出最坏情形（区间上限对应什么扰动）；
- 通过标准的选取依据（为什么 ≤5%/≤1% 合理）；
- 若存在不稳健处，如实讨论并说明原因（示弱也是加分项）。

## 5. 反直觉结果系统化

全文至少一处（通常放在结果对比或模型检验章）汇总"反直觉结果清单"：每条 = 反直觉现象 + 机制解释 + 验证证据（对比/灵敏度/回放）。例如"第四关不挖矿""第六关保守者收益最高""均衡分路帕累托有效"。

## 6. 结果与机理、策略、图表的联动

- 灵敏度数字必须回链策略结构（挖矿天数、购买量、补给次数）；
- 每个图后 2~4 句解读（看图指南：看哪条曲线、哪个拐点、对应哪段策略）；
- 结果章节引用前面公式/表格时说明"为什么这个机制导致这个结果"。

## 7. 验收自检

- [ ] 每问每个关键结果有三段式（数值→机理→决策含义）；
- [ ] 灵敏度每参数有排序 + 归因 + 方向解释；
- [ ] 大表有读表指南；
- [ ] 鲁棒性有波动解释 + 最坏情形 + 标准依据；
- [ ] 全文有反直觉结果清单；
- [ ] 每张图有 2~4 句解读；
- [ ] 全文无"方向合理"式空话结尾。
