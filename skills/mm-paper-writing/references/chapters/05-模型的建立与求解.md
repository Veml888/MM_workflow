# 一、总纲：骨架与公式粒度

> 本章是"论证思路与写作原则库，不是可套用的模板"。判题人看的是"思路对不对、论证顺不顺"，不是"小节齐不齐"。**但框架是硬性的：每个子问题独立成章，章内固定"模型建立 / 模型求解"二分层，公式分解到"一量一式"。** 这是整个模型章不可违背的骨架，先读本节，再进"模型建立"或"模型求解"板块。

## 模型章骨架（硬性，必须遵守）

**外层：每问独立成章。**
- **N = 题面子问题数（任意值，常见 2~4）**，每个子问题单独设一级标题；N 不同骨架不变，只是章数随 N 变，序号连续（前四章"问题重述/问题分析/模型假设/符号说明"固定为一~四，问题章从"五"起，后续章节序号随 N 顺延）。
- **问题章标题命名（硬性格式）**：`（该问核心模型/方法名）的构建与求解——问题X`，破折号后置问题号。核心模型名取该问**最具代表性、能概括建模思路**的模型或方法（如"期望递归模型""多级递推模型""精确检验模型"），不得只写"问题一的模型建立与求解"这类无对象死板标题，也不得把次要算法堆进标题。
- **模型评价与推广永远是单独一个一级章节**（序号随 N 顺延），不并入任何一问、不因问数变化而消失。
- 章首（问题一前）可用一段"引言/主线"总述各问的递进关系，点明"前问输出→后问输入"。
- 多问共享同一原始数据时，可在问题一章之前设一个条件性的公共数据处理一级小节；部分共享用"公共处理 + 问题专属处理"，数据彼此独立则分别写入对应问题。

**内层：章内固定"模型建立 / 模型求解"二分层。**
- `模型建立`（二级标题）：只讲"为什么这么建模、公式怎么来"。按模型成分拆成若干三级小节，一个模型成分（一个子模型、一个关键参数）一个三编号小节。
- `模型求解`（二级标题）：只讲"怎么算 + 算什么"。三级小节按"求解算法 → 结果（表/图）→ 解读 / 灵敏度"组织。
- 每个三级小节内部遵循"**一段 = 一个动机 + 一个公式 + 一句作用**"：先给"为什么需要它"，再放公式，最后一句"这个式子的作用 / 怎么检验它"。一事一段，不把一个长段挤进多个模型。
- 不再使用"建模思路—模型建立—模型求解—结果分析—模型检验"这套模板五段；小节数量以本题实际建模成分为准，不要求凑数。

**每问必须闭合的论证链**：题目目标 → 数据与已知条件 → 模型选择依据 → 变量、参数与单位 → 核心数学关系 → 目标与约束（或状态方程）→ 求解算法 → 结果 → 对题目的直接回答 → 证据与适用边界。闭环是硬要求，小节数量和标题名称不是硬要求。

## 公式粒度：一量一式（硬性）

凡一个物理量、一个参数、一个约束，若能被独立推导或独立检验，就**单独编号一个公式**，不要塞进 `cases`/`aligned` 共享式号。**"公式多 = 分解细 = 每个公式都承载一个'从哪来、怎么用'的量"，不是刻意堆砌。**
- 例：两个**相互独立、都能被独立检验的量**不必合并成一个 `cases`；一个目标量（如"期望"）若由几个可分别解释的参量构成，各参量各成一式。
- 每个式子前给引入理由，后给现实含义与作用，保证"一读即懂这个量是什么、怎么来"。
- 真正需要并列、且必须同时满足的一组判定约束（如情形1/情形2 的功效约束），才用左花括号 `\left\{`/`cases` 共享一个式号（各行左对齐、齐左）。
- 需要分别引用或分别推导的公式才拆分式号；同属一个逻辑、必须并列呈现的少量约束才合并。

# 二、模型的建立

> 写模型章的第一半。核心是把模型**当众推出来**、**按需配图**、**不剧透**。本板块的规则覆盖"模型建立"二级层下的每个三级小节。

## 现场推导：模型建立是"推导故事"而非"公式清单"（硬性）

模型建立节须体现**数学建模的过程**：每个公式是当众推导出的因果链节点，而非"摆出来再解释"。判据：**能否看到"为什么需要它→从哪出发→推到什么"的完整链条**，而非"给定公式+事后解释"。

- **公式不许凭空出现**：每条公式前先交代它解决什么、从哪个已知条件出发。禁止"由 XX 可知"带过关键一步，要**当众算出来**（几何分布期望给等比求和依据、概率乘法链写推导、递归求和先列几何级数再求和）。
- **因果链叙事**：用"因为 A，所以设这个量；由条件 B 可推得 C"串联，文字与公式交织，数学是叙事的载体。每步"因为…所以…"，不是孤立公式堆叠。
- **遇难点先推演再给结论**：对易成"想当然"的关键点（如单基准点设约束致退化、忽略回收会低估），现场推演出"为何不能这样"，再引出改进，而非直接断言。
- **自检/退化/一致性验证收尾**：每个核心模型给出后，验证其退化情形（参数/规模取特值时模型回到更简单或已知形式），证明无凭空构造。
- **按需配示意图/流程图辅助理解**：按下方"公式/符号的图形化辅助"节判断——有直观含义才配，纯代数不配；推导链长时可配流程图。
- **不剧透（沿用规则）**：模型建立章只陈述"公式怎么来、模型长什么样"，结论在下文求解节；现场推导展示的是"推的过程"，不是"结果有多好"。
- **"为什么选这个模型"归问题分析章**：模型建立节只管**用数学把模型推出来**；关于"用线性回归还是 Poisson、用固定效应还是随机效应"这类**模型选择的理由**，一律放在问题分析章（那里本就有"为什么选此模型"的职责），不在模型建立节展开——模型建立是数学推导，不是决策评审。

**建模完整性的粒度**（并入本节）：关键变量与参数说明类型、下标、单位、取值范围和来源；每个公式按"引入理由→数学表达→现实含义→作用"呈现；每条约束说明对应的资源、容量、预算、时间、守恒、逻辑或边界条件。优化模型求解前集中汇总决策变量、目标函数、全部约束和变量范围，不得分散多页后直接调用算法——与"当众推导"一体两面。

## 公式/符号的图形化辅助（示意图的用武之地，硬性）

模型建立节不只是"摆公式"，更要让读者**一眼看懂这个公式/符号在讲什么**。凡一个公式、一个符号、一个约束**具有可直观呈现的空间、结构、几何、关系或分布含义**，就应在首次定义处**配一张小示意图**辅助理解。示意图为"帮助理解公式/符号"服务，不是数据图、不是装饰。

- **什么值得配图**：①某公式刻画了**几何/空间关系**（夹角、投影、方位、距离）；②某符号代表**结构/装配/层级**（部件→组件→整体）；③某参数是**分布/区间/边界**（接受域、可行域、置信区间、概率密度）；④某约束描述**可行/不可行区域**或**状态转移**；⑤某成分本身是**状态机、网络、时序**；⑥**符号的物理/几何定义**（向量、法向量、夹角、坐标系、物理场景），让符号从"字母"变为"看得见的对象"。
- **什么不用配图**：**纯代数运算/递归求和**（几个概率相乘、期望写成递推闭式，看公式即懂，画图反添负担）；无量纲性质、一句话能说清的一般变量；无信息增益的孤图。
- **总判断标准（一句话）**：这张图能否帮读者理解公式/符号的**具体实际意义**？能——就配；只是把符号摆出来连成线、没增加直观对象——不配。
- **何时配**：先问"这个公式单独读，读者懂它在算什么吗？"能——不配；只有"公式易懂但某符号的对象长相/位置/范围难以想象"——才为那个**符号**配图。
- **先识别、先画、再写，或写作中返回补画（图件时序·双路径，硬性）**：示意图/流程图服务于"帮读者理解公式/符号"，因此必须在**动笔写该处正文之前**已存在。允许两条路径：
  - **路径 A（默认·先画后写）**：写该问模型建立前，先按 `workflow-and-gates` Step 2.5 识别该问哪些公式/符号/约束值得配图，登记到 `paper/figure-requirements.md`，回写负责的图件 skill（`mm-graphics` 画非数据图、`mm-figures` 画数据图），画好后再写正文；写作时只用 `\ref` 引用（见 3b 条）。
  - **路径 B（写作中返回补画·允许）**：写作进行到某处，发现某个公式/符号需要配图辅助理解、且尚未登记/未画，**允许停止该处撰写，返回对应图件 skill 补画**（登记→画→产出），画好后再回到正文继续写该处并用 `\ref` 引用。
  - **硬性判据（两条路径共用）**：在动笔写**这段引用图的文字**之前，该图必须已完成（`figures/` 有产出、`figure-requirements.md` 状态为 `drawn`）。严禁整段/整章写完后再补图当"事后装饰"；严禁用正文文字替代本该配图的位置。写作中哪怕临时发现需要图，也必须走路径 B 先补画、再写文字。
- **放哪**：**紧贴该公式/符号定义处**，图注写明"图 X 用以说明式 (Y) 中……的含义"。图是**补充**——公式给定量关系，图给直观对象，不取代公式与文字解释。
- **怎么画**：非本阶段职责，`mm-graphics` 按 `references/line-art-syntax.md` 相应类执行（线稿、白底、无填充、黑白灰、标签≥8pt 等画法与禁忌见该 skill）；写作阶段只负责"判断值得配图 + 预留位置"。

> 例（值得配）：设定某角度 $\delta$ 为两几何元素夹角，配几何关系线稿；设定某统计量 $\hat p$ 超过阈值则拒绝，配接受域/拒绝域示意——读者立刻明白 $\delta$ 是哪个角、判定规则对应哪个区域。
>
> 例（不该配）：几个量相乘得联合概率、期望写成递推闭式，看公式即懂，画"部件→整体"连线框图多此一举——这类不配。

## 不剧透（各问内部，硬性）

每问结论（最优方案、数值结果、是否稳定/翻转、灵敏度方向）只在该问的**求解小节**出现；该问章首"难点+分层"导语与模型建立节只陈述"要解决什么问题、为什么这么建模"，**不得提前写出结果或模型优势**。
- **模型选择对比**（为什么选此模型而非其它）收敛到"因此我们采用……"来引出建模，**不说"因此它必定最好/能保证最优/闭式精确"**——模型优劣要等求解与验证结果出来后才有依据；讲"不选的方案有缺陷"（如忽略递归会低估收益）是合理的取舍理由，不算剧透，但不以此断言所选模型必然最优。
- **引表/图句**：先交代"下表/图用于说明……"再让读者看结论；**不得先写结论再补"见表 X"**（如"情形 2 翻转，见表 4"应改成"表 4 给出各情形在区间下的最优决策，用于判断是否翻转"）。
- **模型建立节**：只讲"因变量/参数/目标如何引入"，不下"该模型保证了……"的结论式断言，模型效力留给求解与验证小节。

# 三、模型的求解

> 写模型章的第二半。核心是把"怎么算 + 算什么 + 结果怎么解读"写完整。本板块规则覆盖"模型求解"二级层下的每个三级小节。

## 模型与算法分开（通用铁律）

- 模型回答"什么方案最好"，算法回答"怎样找到"。二者不混写。
- **求解前**：先说明模型性质、决策空间规模，再定算法（如"决策变量仅 4 个、组合 16，全枚举即可全局最优，无需智能优化"）。
- **求解后**：解释结果并提供与模型类型匹配的证据（见下文"结果呈现与分析"）。

## 求解写法分级

- **成熟求解器**：简洁但完整地说明模型性质、算法或求解器、软件及版本、关键参数、容差/终止条件、求解状态与输出。
- **常规算法**：用连续段落或普通编号写清输入、核心步骤和输出。
- **智能优化或复杂自研算法**：必须说明编码、初始化、目标/适应度、更新规则、参数来源、最大迭代、终止条件、随机种子、独立运行与收敛证据，**不贴真实代码替代解释**。

## 求解 ≠ 结束

- 求解后必须解释结果并给出与模型类型匹配的证据。
- **使用前**的量纲、极限、退化、守恒和可行性检查放在**模型建立位置**；**使用后**的误差、交叉验证、对比和稳定性证据紧跟对应结果。多个同类模型确需统一比较时才设置共享检验小节。
- **选择性敏感度**：只扰动重要、不确定或可能改变结论的参数，说明选择原因、基准值、现实范围、步长和关注指标；不得把所有参数机械统一上下浮动固定比例。含人为设定权重、阈值或先验时，必须检查结论是否翻转并报告稳定区间。

## 结果呈现与分析

**结果一致性与口径（硬性，写后逐处核对）**
- **数值一致**：同一物理量、同一模型、同一解在**摘要 / 正文 / 表格 / 灵敏度基准 / 鲁棒性基线**中出现时，数值必须一致。若确需在另一处用不同口径，须**显式说明差异**，不得无声换值。
- **口径显式化**：凡结果有两种以上算法口径，必须在结果呈现处**显式写死口径**，并保证结果文件列含义与正文口径一致。
- **基准对比量化**：凡声称"相比方案 A 提升 X 倍/Δ"或"优于基准"，必须给出对比基准的**具体数值与出处**，最好落一张对比表。

结果不能只报数 + 一句"方向合理"。**结果描述三段式（每问每个关键结果必须）**：`数值 → 机理 → 决策含义`——数值（带单位、精度 2~3 位小数、口径说明）；机理（为什么是这个数，对应哪条机制/策略）；决策含义（翻译回题目/决策者语言）。至少"机理"与"决策含义"缺一不可。
- **灵敏度结果必须解释"为什么敏感/不敏感"**：每个参数扫描给出敏感性排序、机理归因、方向解释、临界/边界观察。
- **大表必须给读表指南**：超过 6 行的结果表，表后解读指明先看哪一行/哪一列、行与行之间差异模式。
- **鲁棒性分析必须展开**：解释波动为什么小、指出最坏情形、通过标准选取依据。
- **结果与机理/策略/图表联动**：灵敏度数字回链策略结构；每个图后 2~4 句解读。

## 呈现规范

- **呈现规范**：目标函数、约束条件按「1) 决策变量 2) 目标函数 3) 约束条件」顺序组织；公式全文连续编号、正文引用"由式(3)可得"。**同一公式表达中若确实需要并列多个等式/约束（如两种情形的判定、链式 `a=b=c`、`\qquad` 并列的约束组），用左花括号逐行排版、每行一个等式并共享一个式号；但能独立成式、独立检验的物理量一律各成一式，不合并。**
- **求解呈现**：写清算法名称+工具+关键参数（如"模拟退火（初温 100、衰减 0.95、迭代 30000 次）"）；工具写清哪个解决哪步；复杂自研算法在正文编号与算法流程图之间选信息增益更高的表达；涉及随机算法时给出收敛性/稳定性说明。

# 四、公共要求（建模与求解通用）

> 本节规则在"模型建立"与"模型求解"两个板块中始终适用。

## 文字密度：三不写（硬性）

篇幅靠**公式、表、图、小节标题**撑，文字只负责"动机 + 作用"的串联——获奖论文的文字密度约为每页 400～500 字，文字多恰恰是公式/图表不足的遮羞布。
1. **中间推导量不写文字叙述**：凡能用编号公式表达的量（传递关系、中间参数、判定条件），一律用公式，不用文字描述"谁乘谁、怎么算"。
2. **表内数值不在正文复述**：数值结果一律落表/图，正文只写 2～3 句解读（数值→机理→决策含义），不得把表中数字逐个念一遍。
3. **建议/启示类内容不写**：各问正文不得出现"对生产管理的启示""对实际生产的指导""对企业的应用建议"类段落——此类内容全文**只写一处**，统一收口在"模型评价与推广"章（见该章"建议收口"条款）。这类段落与评价章重复，是初稿文字超密的最大来源。
   - 注意：三不写第 1 条"推导量不写文字"与现场推导的"当众算"互补——**凡能写成编号公式的量就落成公式（不写文字描述）**，但那条公式的**来源/动机要当众推导**。前者管"不把数学用文字糊弄"，后者管"数学本身要推得出来"。
3b. **解释类图正文只保留引用、无任何介绍性文字**：流程图、示意图、机理图等**解释性图**（非数据结果图）本身自明，正文**不应出现任何介绍、引出或描述该图的句子**（禁止"图 X 展示了…""图 X 给出了…"这类独立介绍句）；图在正文里**只以 `\ref` 引用形式出现**，且必须嵌在讲结论/机理的真实句子里作锚点（如"该过程收敛，如图 X 所示"），让读者自行看图。**本条仅适用解释性图，数据结果图不适用**——数据图（折线/柱状/散点/热力/灵敏度/误差等）必须按"结果呈现三段式"解读，不得省去；判断标准：图内画的是"数值结果"还是"逻辑/几何/结构"。与 02 章"不逐节点复述图中文字"同理，此处统一为全文规则。
写作自检：任一正文段落，若删去后论证链、数值答案、机理归因均无损失，删。
## 写作内在逻辑（通用铁律）

1. **模型链思想**：前一个模型输出 → 后一个模型输入/依据，显式写出传递量、单位、时间/空间尺度和必要转换，并让它真实进入后问的变量、参数、目标、约束、初值或数据输入；只写"基于问题一"而后问仍独立重算，不算模型联动。
2. **公式前必有理由**：先回答"为什么需要它"，再放公式（五种引公式方式：从数据结构/问题特征引、从机理/业务引具体项、从模型适用性引、从业务指标反推数学定义、从优化目标引目标与约束）。与"现场推导"呼应：有理由是前提，现场推导把理由变成可追踪的推导链。
3. **模型与算法分开**：见"模型的求解"板块。
4. **求解写法分级**：见"模型的求解"板块。
5. **求解 ≠ 结束**：见"模型的求解"板块。
6. **选择性敏感度**：见"模型的求解"板块。
7. **不剧透**：见"模型的建立"板块。

## 叙事与故事线（内在逻辑，不是文风）

模型构建不是数学对象清单罗列，而是有前因后果的情节链。按题组织：`开场`（解决什么问题）→ `规矩`（现实规则逐条摆出）→ `主角`（决定什么→决策变量）→ `铺垫`（参数从哪来）→ `冲突`（难点/特殊处理→本题化改造）→ `成形`（目标+约束汇总）。写作要领：每个数学对象出现都有"前因"；用因果连接词串逻辑；约束按故事顺序讲、不按数学类型罗列；收尾要"成形"（"由此得到如下模型"）。**标题像论文、段落像讲故事**（三级小节标题命名见下节）。
> 与"每小节一段一事"并行不悖：故事线是全文的内在因果，`一段=动机+公式+作用`是每小节的微观呈现。两者结合既保证逻辑贯通，又保证每一段清爽、一事一段。

### 三级小节标题：学术式命名（硬性）

模型建立/求解下的每个三级小节标题，须用**名词性学术名**（点明建模成分），**禁止口语化、设问式、叙事式**。内容可讲故事，标题必须像论文。

- **合规**：`问题界定与数据口径`、`计数模型的选取与对数链接`、`站点随机效应的引入`、`决策变量与约束条件`、`目标函数的构造`、`参数估计与检验`、`退化与一致性验证`、`模型汇总`。
- **违规**：`先看问题：需求数据长什么样`、`为什么偏偏是 Poisson`、`参数怎么估计`、`退化验证：模型不是生造的`。

> 判别：标题若是**问句**、含**"怎么/为什么/先看/到底"**等口语词、或以**结论式惊叹**收尾，即违规；改为"对象或成分 + 做法"的名词短语。标题可改，正文推导不受影响。

## 题型化组织参考（只示范逻辑，不是模板）

- **公式六层**：数据处理 / 变量定义 / 主模型 / 目标损失 / 约束 / 检验评价——需要哪些定义哪些；公式必须承担至少一种作用否则不写。
- **分题型论证路径（示例，非唯一）**：优化题（拆问题→定义决策变量→构造指标/参数→目标函数→逐条约束→汇总模型→按性质选算法→求解→结果解释）；数据/统计/分类题（识别数据结构→数据有效性筛选→适配变换→模型适用条件检查→按类型选模型→训练/测试分离与评价→异构交叉验证→敏感性）；物理机理题（过程分阶段→受力/几何分析→基本定律→状态方程+初始条件→小参数近似线性化→求解→发现模型出问题→修假设→策略输出）；概率/序贯决策题（现实随机机制→随机变量/分布→期望成本收益→优化目标→枚举或 DP→参数不确定性→灵敏度）。判断标准：路径是否顺应题目的递进逻辑，而不是"有没有按某个模板写"。
- **模型修复范式**：`模型结论不符合实际/无解 → 检查关键假设（不是急着换模型）→ 放宽/修正假设 → 建立改进模型（最小幅度修改，只动受影响部分）`。
- **参数不确定性范式**：`确定性模型（参数为常数） → 参数视为随机变量（分布来自题面区间/共轭先验） → 情景/后验抽样 → 对目标求期望 → 重新优化 → 与确定性结果对比 → 主观参数灵敏度`。写论文时显式写"在问题一模型基础上，将确定参数升级为随机变量"。

## 易错点（自查清单）

### 通用易错点
只建模不求解（公式堆砌无数值）；求解过程黑箱（"用软件求解得…"要写算法与参数）；结果（图/表）无解读段；模型间无衔接、每问从零开始；参数表出现"/"或空缺；模型类型表述摇摆；公式前无理由直接罗列（叙事断裂、退回清单）；**把本可独立成式的量硬塞进 `cases` 共享式号（违背"一量一式"）**；**约束下标不完整**（如"每机至多3弹"应写 $\sum_k\sum_m a_{jk,m}\le3\ \forall j$）；**约束中数值常数来源不明**（须说明是物理/时间窗/防退化/减子域）；**扫描子域≠约束域时不说明**；**同一结果多处口径不一致**（摘要/正文/表/灵敏度基准/鲁棒性基线须一致或标注差异）。

### 现场推导专项自查（每问模型建立节逐项核对）
- [ ] 每条公式是否**当众推导**而非"给了再解释"？关键一步（期望、概率链、递归求和、极限）是否写出推导依据，而非"由 XX 可知"带过？
- [ ] 是否先"为什么需要它 → 从哪出发 → 推到什么"，再给公式？（因果链，非清单）
- [ ] 是否**现场推演**了难点（如退化/低估/单点约束失效），证明"为何不能简单做"，而非直接断言？
- [ ] 核心模型后是否有**退化/一致性验证**（变量/参数取特值，模型回到更简单或已知形式）？
- [ ] 是否**按需配了自明图**（有直观含义才配，纯代数不配）？图是否只 `\ref` 引用、正文未介绍？
- [ ] 是否**不剧透**（模型建立节只讲推导，结论留给求解节）？
- [ ] **模型建立节是否只做数学推导**（未出现"候选/不选/采用"、"为什么选这个模型"等决策评审式内容）？模型选择的理由是否已放到问题分析章？

# 五、骨架一览（硬性，必须遵守）

框架固定，内容按本题实际建模成分定：
```
1  （该问核心模型名）的构建与求解——问题一
   1.1  模型建立
     1.1.1  模型成分A  （动机 → 公式 → 作用，现场推导）
     1.1.2  模型成分B
     1.1.3  模型成分C
   1.2  模型求解
     1.2.1  求解算法
     1.2.2  求解结果（表/图）
     1.2.3  解读 / 灵敏度
2  （该问核心模型名）的构建与求解——问题二
   （同 1 结构，核心模型名按该问最具代表性的模型/方法定）
```
示例（核心模型名的取法）：取该问**最具代表性、能概括建模思路**的模型名，如"递推期望模型""多级递推模型""精确检验模型"，标题统一为"〈该模型名〉的构建与求解——问题X"。忌用无对象的死板名（"问题一的模型建立与求解"），也忌堆砌次要算法名。
子模型小节的数量与命名按本题实际建模成分决定，不要求凑数；每问章首一段"本节难点 + 分层说明"。**注意："不凑数"指小节内部成分数量按题定，不是骨架可放松——前述五点骨架硬性不变。**
