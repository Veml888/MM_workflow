# 摘要写法（整页、加粗、突出方法与结论）

> **本文件是摘要写作的唯一操作规范**；`corpus/摘要写作-playbook.md` 仅提供 28 篇获奖论文的统计证据与反例，执行规则以本文件为准，两处冲突时以本文件为准。

摘要决定评委初印象。目标：**写满一整页（不超过一页），重点突出每个问题的解决思路、方法与结论**。这里的“写满”必须由首页面元素坐标验证，不再用“单页 + 字数合规”代替。量化规则来自 28 篇获奖论文语料（见 `corpus/摘要写作-playbook.md`）。

## 内容结构（总起段 + 逐问分块）

摘要重点放在"**每个问题的解决思路 + 使用方法 + 结论**"，不要大段背景铺垫：

```
[总起段] 背景/问题引入 + 全文总体方法（1–2 句，≤3 句）
[针对问题一] 关键洞察/建模理由（1 句）→ 方法 → 模型 → 求解 → 结果（带数字）→ 一般性策略（1 句）
[针对问题二] 同上
[针对问题三/四] 同上
[结尾句] 检验/评价/改进（可选）
```

- **第一段克制**：总起段 1–2 句，出现"本文建立/提出了…"，不堆模型列表。
- 每个问题块固定按 **方法→模型→求解→结果** 顺序，不倒叙。
- 每个问题块**至少 1 个带单位、保留 2–3 位小数的数字**（获奖论文 20/28 每问都带数值；只写方法、写"见表"或不带单位都是明显失分点，反例见语料 playbook 第 3/6 节）。
- **关键洞察/建模理由（必写）**：每个问题块用一句说明"为什么能这样做"——证明、化简、记账变形、结构性质等（如"可证明除沙暴外只在矿山停留""购买可先使用后记账，资金不进状态""对手方案固定后最佳回应仍是单人 DP"），不得只给模型名+数字。
- **一般性策略（题目要求时必写）**：题目要求"给出一般情况下玩家的最优策略"时，每个问题块末尾必须把可迁移的决策规则显式写成一句"一般性策略为：……"，不能只报各问数值。
- **数值口径**：结果口径与常见口径不可直接比较时（如"成功优先、失败记 0" vs 确定性期望、"含半价回收" vs 不含），摘要必须用括号注明口径，避免数字被误读。
- **求解与验证的抓手**：求解环节写清算法/实现/验证动作（如"稠密数组递推""二维后缀最大""蒙特卡洛 5000 局""回放一致性检验"），体现可执行性；但不要堆参数细节（如迭代次数、网格步长）。

## 字数与段落

- 字数 **550–1100 个汉字**为允许区间，优先写到 **750–950 个汉字**；英文术语、公式和数字不计入汉字数，但必须计入版面占用。
- 段落：**必须分段，禁止整篇一个大长段**。推荐结构为“总起段 + 每问各一段 + 检验/评价结尾段”，全篇 3~5 段（总起 1 段、每问 1 段、结尾 1 段），不要逐问内部再碎拆，也不要 5 段以上碎段。若按“逐问成段”分段后总段数超过 5，可将检验/评价并入结尾段或适当合并总起段。
- 关键词 **3–7 个**（主流 4–6），内容为模型名/算法名/题目关键词，不写"数学建模""论文"这类空词；分隔符（顿号/逗号/分号）全文选一种并保持一致。

## 排版要求（整页、不过页）

- **固定标题层级**：无官方模板或用户覆盖时，论文主标题与摘要标题均固定为三号黑体 `\zihao{3}\bfseries`，间距默认 `0.4em`。禁止放大标题制造视觉重量。
- **写满一整页**：摘要严格不超过一页；关键词行底边必须落在可打印版心纵向 **78%--90%** 区间。低于 78% 判定留白过大，高于 90% 判定过满风险。
- **内容优先补足**：占用率不足时，优先补充选模转折、失败对照、误差/区间、稳定性证据和适用边界；不得重复结论、堆背景或添加空泛创新点。
- **禁止排版注水**：不得使用 `\vfill`、带 `fill` 的弹性空白、`\enlargethispage`、缩小页边距、异常放大标题或无信息手工换行来通过占用率。
- **首行缩进**：摘要正文各段首行缩进两字符（ctex 默认 `\parindent=2em`），不得用 `\noindent` 取消缩进；关键词行同样缩进。
- **段前段后间距（非必须，仅兜底）**：段前/段后间距默认与正文一致（通常 0pt），**当内容足够写满页面时不要额外加段间距**；只有内容在合理字数区间内仍明显不足一页时，才允许小幅增加，基准**约 6pt（相当于 Word 的 6 磅）**，上限不超过 8pt，**禁止 12pt 及以上**的间距。页面仍显空荡时应优先**充实内容**（增加实质信息），而不是继续放大间距；禁止缩小页边距至 2.5cm 以下，禁止内容超过一页。
- **页边距**：官方要求上下左右**各至少 2.5 厘米**，**不得小于 2.5cm**。写不满/留白多时优先**充实内容**，其次按上一条调整段前段后间距，不突破官方页边距下限。
- **加粗**：关键方法名（**特别是本文独有或与众不同的方法**，如"二维后缀最大购买变换""期望外包最大""最佳回应动态规划""风险类型冲突规避"等）、关键结论、关键数值**加粗**，让评委一眼抓到方法与创新点。
- **页码**：摘要专用页页码从 1 开始，页脚中部（见 `official-cumcm-format-2026.md`）。

## 反模式（真实失分点）

- 大段"随着……的发展"背景铺垫。
- 先写结果再写方法（倒叙）；只写模型名不写求解方式。
- 结尾用无数字的纯定性句收尾（"本文模型合理有效"可要，但不能只有它）。
- 摘要与正文结论**矛盾**（评审大忌）；数字与正文不一致。
- 摘要里堆公式推导/参数细节（"30000 次迭代"写进摘要，偏技术化）。
- 逐问分块缺"求解"环节（只写模型名就直接给结果）。
- 只报模型名和数字、缺关键洞察；题目要求一般性策略时却只给各问数值。
- 数值口径不清（如"成功优先、失败记 0"与确定性期望混用），导致数字被误读。

## 交付前自检

- [ ] 主标题与摘要标题均为三号（或已记录官方模板/用户覆盖）？
- [ ] 汉字数 550–1100，优先 750–950？
- [ ] `audit_abstract_page.py` 输出 `status=pass`，关键词行版心占用率 0.78–0.90？
- [ ] 未使用弹性空白、缩边距、放大标题或空泛句子填页？
- [ ] 总起段 ≤ 3 句？
- [ ] 每个问题块都有「方法→模型→求解→结果」？
- [ ] 每个问题块有"为什么能这样做"的关键洞察（证明/化简/记账变形等）？
- [ ] 题目要求一般性策略时，每个问题块末尾有可迁移的"一般性策略为：……"？
- [ ] 数值口径已注明（成功优先/失败记 0、含回收等）？
- [ ] 求解与验证有具体抓手（算法/实现/验证动作）？
- [ ] 每个问题块至少 1 个带单位、2–3 位小数的数字？
- [ ] 已按要求分段（总起段 + 逐问分段 + 结尾段），全文不是一个大长段？
- [ ] 关键方法与结论已加粗（特别是与众不同的方法名）？
- [ ] 摘要结论与正文一致、数字三处一致？
- [ ] 关键词 3–7 个且无空词？
- [ ] 写满一页且未溢出（页边距 ≥2.5cm）？
