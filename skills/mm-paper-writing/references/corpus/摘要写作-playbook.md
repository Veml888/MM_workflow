# 摘要写作 playbook

> **定位**：本文件是摘要写作的**语料证据库**（28 篇统计 + 反例），不是操作规范；执行规则以 `references/chapters/00-摘要.md`为准，两处冲突时以操作规范为准。

> 基于 28 篇国赛优秀论文语料(2020–2025)统计。规则后标注支持篇数;语料清单见 `research/_paper_roster.md`。

## 1. 结构:总起段 + 逐问分块(28/28 篇采用,跨 6 年最强共性)

优秀论文摘要几乎**全部**采用同一骨架:

```
[总起段] 背景/问题引入 + 全文总体方法(1–2 句)
[针对问题一] 关键洞察/建模理由(1 句) → 方法 → 模型 → 求解 → 结果(带数字) → 一般性策略(1 句)
[针对问题二] 同上
[针对问题三/四] 同上
[结尾句] 检验/评价/改进(可选,约半数论文有)
```

- 总起段要点:用 1–2 句说清「问题背景 + 本文思路」,不要超过 3 句。约 1/4 论文省略背景直接进方法,仍可接受,但带背景的完整度更高。
- 每个问题分块内部固定按 **方法→模型→求解→结果** 顺序推进,不要倒叙。
- 每块**应给**具体数值结果(约 20/28 篇每问都带数字,其余至少部分问题带;见第 3 节与反例)。
- 优秀摘要通常还包含**关键洞察**(如第二篇先证明"除沙暴外只在矿山停留"、第一篇把地图压缩到关键节点)与**一般性策略**(如"先尽快到村庄补给,再按剩余时间决定挖矿或终点"),只报模型名+数字是明显差距。
- 数值**口径**不同时(如确定性期望 vs 成功优先/失败记 0)需在摘要注明,否则数字会被误读(示例:同一第四关,不同口径下 10065 与 5628.89 不可直接比较)。
- 求解与验证交代具体抓手(算法/实现/验证动作),但不要堆参数细节。

## 2. 长度与段落

- 语料统计中 550～1100 字较常见，但本工作流固定采用 **800～1000 个汉字**；超过一页即为风险。
- 段落:**必须分段,禁止整篇一个大长段**；本工作流采用“一个两句引言段 + 每问各一段 + 一个收尾段”，段落数随子问题数量变化，不用 3～5 段上限压缩多问内容，也不在单个问题内部碎拆。
- 填满页面:段前/段后间距**不是必须项**——内容足够时保持常规间距(通常 0pt);仅内容不足一页时才小幅增加,基准约 6pt(Word 6 磅)、**上限不超过 8pt、禁止 12pt 及以上**;留白较多时应优先充实内容,不得缩页边距、不得超一页。
- 第一段就出现「本文建立/提出了…」,不要在总起段里堆模型列表。

## 3. 数字密度:每个问题块至少 1 个关键数值(主流做法,20/28 全做到)

获奖论文摘要的共同点:每个问题块给出**结果数字 + 单位**,而不是「结果良好」这种空话。跨年统计:2023 年 13/13、2024/2025 年 5/6 每问带数值;**反例(少数派,不推荐)**:2024 A163 五问全部只写方法不写数值、2022 A022 问题 1/3 只写「见表」、2022 C155 仅一问给数值——评委无法从摘要一眼看到结果,是明显的失分点。

| 论文 | 摘要中的数字示例 |
|---|---|
| 2023 A127 | 36.9945 MW、0.6051、0.5888 kW/m² |
| 2023 B477 | 34 条测线、覆盖率 99.956%、总长 434662 |
| 2023 C050 | 最大收益 5105.60 元、29 种单品、1282.2631 元 |
| 2023 E176 | 监测方案、临界值、误差 0.1011/0.3205 |

- 数字保留 **2–3 位小数**并带单位(元、MW、m、%…)。
- 若某问结果只有定性结论,补一句「…满足题目约束」式量化描述,而不是空白。

## 4. moves 顺序检查清单

用以下序列对照草稿(√ 越多越好,顺序不可乱):

1. 背景/问题引入(可省略)
2. 全文方法或整体思路
3. 问题一:关键洞察 → 方法 → 模型 → 求解 → 结果(数字) → 一般性策略
4. 问题二:同上
5. 问题三/四:同上
6. 检验/评价/改进(可省略)

**反模式**:
- ❌ 先写结果再写方法(倒叙)。
- ❌ 只写模型名不写求解方式(「建立了XX模型」后面直接是结果,缺求解环节)。
- ❌ 只报模型名和数字、缺关键洞察;题目要求一般性策略时只给各问数值。
- ❌ 数值口径不清(成功优先/失败记 0 与确定性期望混用),导致数字被误读。
- ❌ 结尾无数字的纯定性结论句收尾(「本文模型合理有效」——这句可以要,但不能只有这句)。

## 5. 关键词

- 数量:**3–7 个**,主流 4–6 个。
- 内容:模型名/算法名/题目关键词,不要写「数学建模」「论文」这类空词。
- 分隔符不统一(顿号/逗号/空格/分号都有),选一种全文一致即可。
- 示例:「定日镜平均输出热功率优化模型;变步长搜索算法;分区域同心圆规划策略」

## 6. 摘要常见错误(语料中实际出现)

- 摘要与正文结论矛盾(2023 E176:摘要称「调水调沙成效不佳」,正文称「成效显著」)——**评审大忌**。
- 关键数字转写/抄写不一致(2023 B477 表 3 多处面积数字不一致;2022 A022 摘要 37193.8119 与正文 37193.812 不一致)。
- 摘要里出现公式推导细节或参数堆砌(2023 C126 把「30000 次迭代、燃烧 3000 次」写进摘要,偏技术化,是少数派做法,不推荐)。
- 逐问只写方法不写数值(2024 A163)——评审无法快速看到结果。
- 关键词粘连无分隔或错用「关键字」(2021 A115、2022 C155)。

## 7. 交付前自检

- [ ] 字数在 800～1000 区间?
- [ ] 引言段恰为两句且未写成技术目录?
- [ ] 每个问题独立一段并包含任务、模型/算法、可核验答案和适用证据?
- [ ] 每个问题块至少 1 个带单位、保留 2–3 位小数的数字?
- [ ] 摘要结论与正文一致?
- [ ] 关键词 3–7 个且无空词?
