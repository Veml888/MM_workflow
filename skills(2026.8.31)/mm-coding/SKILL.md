# 数学建模：编程实现与求解

本 skill 是数模流程第 3 阶段。目标：把 `docs/02-modeling-report.md` 的模型、求解思路、伪代码、对比与灵敏度方案，落成**可运行、可复现**的代码，算出真实数值结果。

## 一、定位与产出

**输入**：`docs/02-modeling-report.md`（必须）、`data/`。
**产出**：`code/`、`results/`、`docs/03-results-report.md`（必须）、`results/复现清单.json`（必须），并更新 `project-manifest.json` 的 `implemented_models`、结果、验证执行记录与产物记录。

跨阶段不变量遵循 `../mm-orchestrator/references/cumcm-shared-policy.md`；代码实现、运行、证据实验、结果文件和复现清单细则以本 SKILL 为准。交接字段遵循 `../mm-orchestrator/references/project-manifest-contract.md`。

## 二、工作流（主线：怎么一步步做）

> 主流程就是这六步。§三～§七 是支撑这几步的规范与结构，不是主线；执行时按 Step 顺序走，某一步要什么规范就到对应小节去查。

### Step 1：按建模报告建代码骨架

- 每个子问题一个 `code/problemN.py`，公共函数放 `code/utils.py`。
- 先写骨架与函数签名，再填实现；每个函数对应建模报告"待编程要点"里的一项。
- 数据读取统一走 `utils.py`，避免散落硬编码路径。

### Step 2：实现并运行

- 严格按 §四"代码规范"：固定随机种子、写清量纲、输入输出路径参数化。
- 运行代码，确认每个子问题都能跑出真实数值结果，无异常。
- 结果落盘到 `results/`：能写 `.csv`/`.xlsx` 的按题面要求格式输出。

### Step 3：实现适用的证据实验

- 按建模报告中标记为适用的方案，跑出模型对比、灵敏度、鲁棒性或其他检验结果，落盘到 `results/`；不适用项不生成占位结果（详见 §五"实验与仿真"）。
- 对比必须"同数据、同指标"，否则结论不可信。
- 预测/分类/审核题按 §六"训练/测试隔离"输出：交叉验证均值±波动、容量指标 Recall@B/Precision@B/Lift@B、风险因素 Bootstrap 区间与方向一致率、聚合敏感性、测试集一次性外部评价。

### Step 4：实现仿真与多帧输出

- 对仿真/迭代类子问题，把演化过程按时间步/迭代次数采样成多帧，输出 2D 视角所需的数据（如位置坐标随时间）；仅当 `mm-figures` 确定需要 3D 视角时才额外输出 3D 坐标数据，落盘到 `results/`，命名清晰（如 `results/q4_frames_t00.csv`、`q4_frames_t10.csv`）。

### Step 5：生成复现清单

按 §七"复现清单结构"写 `results/复现清单.json`，记录执行命令、工作目录、随机种子、输入与代码 SHA-256、依赖锁文件、操作系统、求解器版本、收敛状态、数值容差、运行耗时和输入输出清单。**写入后必须运行 `python <mm-orchestrator目录>/scripts/check_reproducibility.py results/复现清单.json --root .`；PASS 以脚本返回值为准（exit 0，且它重算的 SHA-256 与真实文件一致），禁止只写"已复现"而不跑脚本**。脚本 FAIL 时修正清单或真实哈希，直到 exit 0。

### Step 6：写结果报告

写 `docs/03-results-report.md`，包含：

- 每个子问题：用了什么模型/算法、核心代码位置、关键数值结果（表）、结论一句话。
- 为论文求解段登记实际软件与版本、算法输入输出、初始化、关键参数及来源、随机种子、最大迭代/容差/终止条件、独立运行次数和收敛状态；不适用项写 N/A，不得凭写作需要补造运行细节。
- 适用的模型对比、灵敏度、鲁棒性或其他检验结果；不适用项写明 N/A 理由。
- 适用题目的仿真关键状态说明。
- 结果与建模报告预期是否一致；不一致处说明原因。
- 独立复核结果（仅预测/分类/风险排序/审核题）：复算项、误差、结论。
- 供图表阶段的**候选结果清单**（供 `mm-figures` 综合决策，作为素材而非正式 `figure-requirements.md` 来源）：哪些结果**可能**需要画图、适合什么图种（含 3D 图、多帧图），指向 `results/` 具体文件。

## 三、硬性要求（不可违背，单点定义）

> 本节的"硬性"是底线；下游（结果报告、论文、验收）都以此为凭。凡"禁止编造数据、禁止静默换模型、禁止把候选当定稿"等原则只在**本节**定义，其余位置不再重复，需要时引用本节。

1. **数据真实**：所有输入参数来自题面/附件，**不得编造**；题面没给又必需的数据，用建模报告"待确认项"里约定的来源或假设，并在结果报告中标注。**禁止编造数据、拼凑数字、为了让结果好看而改参数**；凡使用假设值的参数，在代码注释与结果报告中标注"假设值 + 来源/理由"。对答案真实性负责（下游、论文、验收均以此为凭）。
2. **证据实验按需实现**：只实现建模报告标记为适用的模型对比、灵敏度、鲁棒性或统计检验；凡结果报告声称更优、稳定或可靠，必须有对应计算结果。
3. **真实仿真按题触发**：只有涉及时间演化、空间演化或迭代过程的子问题才做真实仿真；每个适用子问题至少输出初始、关键中间与终止状态，不要求必须有两个子问题。
4. **结果可复现**：按 §七"复现清单结构"记录随机种子、输入与代码哈希、执行命令、环境、求解器、容差、收敛状态和输入输出关系。
5. **训练/测试隔离与独立复核**：仅在预测、分类、风险排序或审核决策题触发 §六；其他题型标记 N/A。
6. **复杂算法实现记录**：对非平凡算法记录实际状态/决策规模、关键参数、初始化、更新次数或收敛轨迹、终止条件、运行耗时/资源和失败或退化情形；结果报告不得只写算法名称和最终数值。记录应能与建模报告的复杂度分析和论文解释对应。
7. **目标函数实现核对**：代码必须逐项对应建模报告中的目标函数、方向、归一化、权重/惩罚和约束；记录实际优化值、各目标分项、约束违反量（如有）及可行性状态。不得静默更换代理目标、权重、惩罚系数或把不可行解当作最优解。

## 四、代码规范（复现性优先）

数模代码的核心评价不是"写得多高级"，而是**评委/队友能否复现你的数**。

### 必须遵守

1. **固定随机种子**：任何涉及随机（智能优化、随机森林、采样、train/test 划分）的模块，在文件顶部显式设置 `np.random.seed(...)`、`random.seed(...)`，并在 `复现清单.json` 中记录种子值。**禁止**把种子设成与时间相关（`time.time()`），会导致不可复现。
2. **输入/输出路径参数化**：不硬编码绝对路径；用相对 `PROJECT_ROOT` 的路径，通过常量或参数传入。
3. **量纲与单位注释**：每个关键数值变量的单位在注释里写清，避免张冠李戴。
4. **可运行**：每个 `problemN.py` 单独可运行；`utils.py` 不含顶层副作用代码（用 `if __name__ == "__main__":` 保护）。
5. **依赖可查**：用到的第三方库在文件头注释列出；尽量限定在 numpy/scipy/pandas/matplotlib/sklearn 等主流库。

### 命名与结构

- 函数名动宾结构，变量名有意义（`cost_matrix` 优于 `c`）。
- 子问题脚本按"读数据 → 建模计算 → 写结果"三段式组织。
- 结果写入 `results/`，文件名含子问题号与含义（如 `results/q1_最优方案.xlsx`）。

### 结果落盘约定

- 数值结果优先存 CSV（utf-8-sig，方便 Excel 打开中文），题面要求 `.xlsx` 时用 pandas 写 xlsx。
- 表头用中文列名（与论文一致），关键中间量也保留，便于论文引用。

### 反模式（避免）

- 在循环里重复读盘/重复加载模型。
- 全程 `print` 关键结果却不落盘。
- 把随机种子设成与时间相关（`time.time()`）。
- 一个文件混着三四个子问题、上千行逻辑。

## 五、实验与仿真（按题触发，非每题必做）

> 本节承接 §三硬性要求的第 2、3 条，是"证据实验与仿真"的落地规范。只对**建模报告标记为适用**的题做，不适用项写 N/A 理由、不生成占位结果。

### 模型对比实验规范

- 对比必须"同数据、同指标"，否则结论不可信。
- 备选模型与所选模型在同一份输入上分别运行，输出同一指标的对比表（如 RMSE、成本、耗时、准确率）。
- 对比结果落盘到 `results/`，命名含"对比"字样（如 `results/q1_模型对比.csv`）。

### 仿真与多帧输出规范

- 仿真/迭代/时间演化类问题，把演化过程按代表性时间步/迭代次数采样成多帧。
- 每帧分别落盘 2D 与 3D 视角所需数据（如 `results/q4_frames_t00.csv`、`q4_frames3d_t10.csv`）。
- 帧采样 3~6 个（初始、中间转折、收敛/终态），供 `mm-figures` 做多帧可视化。

### 优化/机理题的落盘契约（重点，可追溯取数）

对连续优化、机理、几何等**非预测/分类/审核**题（尤其是 CUMCM 主流题型），编程阶段必须把"下游 mm-figures 要画的图"所需的求解数据，按**可追溯、口径一致**的结构落盘，而不是只落盘最终解：

- 每个候选解/局部最优：记录**稳定 ID + 全部决策变量 + 目标值 + 口径说明**（如"灵敏度基准取候选2，目标 4.60 s，全局最优 4.70 s"），供 mm-figures 画目标函数地形、等高线、候选对比；
- 每个参数扰动项：记录**参数名 + 基准值 + 扰动范围 + 输出指标 + 变化方向**（供灵敏度曲线）；
- 每次优化运行：记录**初值、迭代次数、收敛状态、最终目标值**（供收敛曲线）；
- 多弹/多机/多目标分配：每个单元的目标值**单独记录**，并写清"求和"还是"并集"口径、以及"逐单元加总"与"并集后求和"的差别——**防止下游取数时把 34.60（并集）误当 49.4（逐单元和）**。
- 以上数据建议统一放 `results/` 的汇总文件或分表，表头用中文、含单位。

> 这条契约是杜绝"论文/图中同一数值多处口径不一致（如 4.60 vs 4.70、34.60 vs 49.4）"的关键——编程阶段就把口径钉死，下游 mm-figures、mm-paper-writing 照章取数。

## 六、训练/测试隔离与独立复核（仅预测/分类/风险排序/审核题触发；其他题型 N/A 直接跳过）

> **触发条件**：只有题目包含预测、分类、风险排序或审核决策时才进入本节，并实际执行这里的隔离与复核；**优化/机理/几何类题目本节整体 N/A——不是"可以不读"，而是"确认题型后明确跳过"**，在 `docs/03-results-report.md` 相应位置写 N/A 理由。是否进入本节，以 mm-problem-analysis 的题型判定为准；不要被本节的强范式带偏而忽略真正的优化实现。

### 隔离纪律

- 训练集负责字段选择、标准化、变量筛选、超参数、技术阈值和决策参数。
- 测试集只在规则全部冻结后用于一次性外部评价。
- 禁止用测试集调参或反向修改模型；测试集字段闭合率、哨兵异常和 PSI 只作部署诊断。
- 身份编码、机构编码不得进入评分器。
- 泄漏审计：日期重复、总计字段、ID 交集、重复行、目标变量出现在特征中。

### 独立复核

- 除主分析程序外，写独立复核脚本，复算公式与指标：AUC、分类指标、字段闭合、容量收益、成本曲线、标签隔离。
- 与主程序结果对比，误差超阈值（如 1e-6）即定位并修正。
- 复核结果写入 `docs/03-results-report.md`。

### 必出结果

- 交叉验证均值与波动（mean ± sd），不只最优一次。
- 容量指标 Recall@B / Precision@B / Lift@B（B = 50/100/150/200）。
- 风险因素的 Bootstrap 区间与方向一致率。
- 聚合方式的敏感性比较（AUC 与 Top-B 名单）。
- 测试集一次性外部评价结果。

## 八、边界

- 不画论文级图表（交给 `mm-figures`），但可画简单调试图。
- 不改模型公式；若发现模型不可行，回写建模阶段或在本阶段报告"模型需修正"并说明，不静默换模型。实际实现必须引用 `selected_models`，不得把未确认的候选模型直接写入代码。
